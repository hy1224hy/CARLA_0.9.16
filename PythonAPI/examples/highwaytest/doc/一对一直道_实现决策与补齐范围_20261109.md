本文记录今日与用户讨论后冻结的决策与补齐范围，作为完善 `highwaytest/straight/` 代码与脚本的依据。基础契约见[一对一直道_观测动作与三级奖励V1](一对一直道_观测动作与三级奖励V1_20261109.md)，总体研究设计见[分级对抗奖励与策略池](分级对抗奖励与策略池_设计细化_20261109.md)与[两日实施方案](研究点一_互学习对抗驾驶_两日实施方案_20261109.md)。本文不覆盖研究奖励系数本身；候选数值仍以开发集预实验校准为准。

## 1. 冻结的决策（用户确认）

### 1.1 实验矩阵：30 run，复用不重训

| 研究块 | 配置 | seed | 新 run | 复用 |
|---|---|---:|---:|---|
| 主对比 | L1/L2/L3 × independent/mutual | 42/43/44 | 18（`configs/straight_v1/` 已生成） | — |
| β 敏感性 | 仅 L2 mutual，β=0.005/0.08 | 42/43/44 | 6 | β=0 复用 L2_independent，β=0.02 复用 L2_mutual |
| 奖励消融 | 仅 L2 mutual，no_risk / no_event | 42/43/44 | 6 | full 复用 L2_mutual |

- 每级都保留 independent 双副本对照（M0），互学习收益可按级报告；机制结论仍主要在 L2-A（《分级》§12）。
- 复用配置不重训：batch 只跑新配置目录；报告端从主对比目录取被复用 run 的数据，并在图表/表注中说明复用（《两日》§9 要求）。
- λ（攻击权重）敏感性本轮不做（按《分级》§12 口径）。
- 输出目录布局（对齐《两日》§14 建议）：`runs/straight_v1/train/{main,beta,reward}/<run>`；`pool` 与 `matrix` 只覆盖 main 18 run（敏感性/消融 run 不是策略池候选，防止 β=0.08 或 no_event 的模型被选为 L2 代表）；`report` 合并全部 30 run（被复用 run 从 train/main 取数并在表注说明）。

### 1.2 奖励消融口径：按文档改

- `StraightConfig` 新增 `risk_weight`（h_t 风险项系数，默认 1.0，非负）。
- L2 密集项改为 `effect_weight*d + 2*risk_weight*h`；L3 的 `0.5*h` 改为 `0.5*risk_weight*h`。L1 无 h 项。
- 消融 = **no_risk**（risk_weight=0，去几何引导）+ **no_event**（event_weight=0，去掉 F 事件奖金与 E1/E2 成功奖金；碰撞惩罚 -20 保留）。
- `no_effect`（effect_weight=0）不再作为本轮研究消融；effect_weight 字段保留，供后续 λ 研究使用。

| 描述符 | 来源 | 状态 |

- 接触方位为几何代理分类（碰撞瞬间 |Δy| 与车宽的比），不宣称真实接触力；实现阈值由开发者定并在代码注释与图注中说明。
- 新增 `stop_qualified`（vV<2m/s 持续≥2s 且 C1>8m/s 曾发生）供归类与 L2 逼停子类型判据使用。

### 2.2 等级一致性矩阵

- 行为归类器（按回合、按策略）：`invalid / none / mild / strong / collision` 五列，优先级 invalid → collision → strong → mild → none：
  - invalid：出界、参考失效等无效事件；
  - collision：指定目标碰撞（含 L1/L2 的碰撞越级）；
  - strong：非碰撞强行为 = L2 类合格（cut_in 且反应确认）或 stop_qualified；
  - mild：blocking_time≥1.5s 且无以上；
  - none：无明显效果。
- 新 CLI 子命令 `matrix --runs <main训练根> --output <file>`：只覆盖主对比 18 run 的 selected.pt，在 selection 案例上评估并归类。
- 聚合口径：行 = 训练意图 × 方法（L1/L2/L3 × independent/mutual，6 行），列 = 5 个行为类；格子 = 该行全部 run 的 episode 中落入该类的比例（行归一化）；另输出按 seed 拆分的原始计数 CSV 与合并方法后的 3 行汇总。无 selected.pt 的 run 列入 missing。

### 2.3 稳定性回撤

- 不新增训练期评估（重评冻结 best checkpoint 在确定性 selection 案例上数值恒同，回撤恒为 0，无信息量）。直接利用 validation.jsonl 已有的 A/B 每轮报告：
  - **逐轮优胜系列**（每轮按选模 rank 取 A/B 中更优者的指标）→ 图 1 学习曲线；
  - **最终选中团队的逐轮系列**（同一策略谱系在固定 selection 案例上的演化）→ 回撤计算：后半程检查点 max−min、相邻负变化均值（《两日》§10.3）。
- 报告端对每个 run 输出选中谱系的回撤指标；A/B 两谱系原始序列存入长表 CSV。
- runner 无需改动（validation.jsonl 已有两团队每轮报告，优胜与选中谱系均可由报告端导出）。

### 2.5 配置与脚本

- **主对比配置重生成**：现有 `configs/straight_v1/*.json` 是 `eval_cases=16` 且无 `risk_weight`，与 report 的契约比较（含 eval_cases）及 β/消融新配置不一致。原地重生成 18 份（加 risk_weight、eval_cases=32）；尚无任何训练结果引用旧文件，不构成覆盖结果。
- `write_study_plan`：`--study beta` 只生成 β=0.005/0.08 各 3 seed（method=mutual），输出新目录 `configs/straight_beta_v2/`；`--study reward` 只生成 no_risk/no_event 各 3 seed，输出 `configs/straight_reward_v2/`。旧 straight_beta_v1/straight_reward_v1 目录保留不动（未经训练的未提交生成物，仅作历史）。
- 训练期 selection 评估案例数 `eval_cases` 默认 16→32（对齐《两日》§10.1 selection=32）；`check` 命令增加契约校验（eval_cases、risk_weight 一致），旧口径配置直接拒绝。
- `evaluate --cases` 默认：test=100、selection=32（按 split 定默认）。
- batch 输出根：main → `runs/straight_v1/train/main`，beta → `train/beta`，reward → `train/reward`；`report/pool/matrix` 的目录范围按 §1.1 布局。

- summary.json 与 checkpoint 记录累计墙钟（resume 时延续）。

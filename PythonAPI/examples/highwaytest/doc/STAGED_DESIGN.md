# 分阶段驾驶与对抗训练实施方案（2026-11-08）

用户已确认保持正常通行能力的对抗驾驶，要求可运行实现。沿用现有v3物理/评价/奖励协议，不修改目标或放松安全约束；新实验独立为staged_v1，旧runs不变。

## 设计

- 配置增加可选逐动作探索和课程设置，默认不序列化，保持旧配置/网络加载兼容。
- 共享普通IDM演示初始化：只使用训练seed命名空间，数据与预算记录。使用现有25维局部输入拟合物理归一化动作，不把集中状态或参考轨迹泄露给actor。普通无通信预训练将消息输入权重置零，确保新通信组从同一行为起点开始。
- 普通G0继续PPO训练；导出的共同攻击初始化来自合格selected模型，额外用gate检查，不采用不合格或退化latest模型；完整普通训练成本和示范成本均计入来源记录。所有攻击组使用同一文件hash。
- 对抗配置保留nominal attack_weight=1用于评价，训练实际权重按0.1/0.3/1课程推进。两队连续满足gate通行/安全条件且达到最小阶段步数才晋级；退化连续出现则降级。所有组规则相同，但实现轨迹可能不同，逐条记录，报告不能声称实际奖励历史完全相同。
- 完整攻击阶段之前selected只能作诊断候选。保存课程状态，严格resume恢复；训练末期不满足门槛时保留eligible=false。
- staged CLI生成seed42配置、演示、普通训练、初始化导出和带共同初始化的有界并发攻击矩阵，复用现有锁/runner/日志，支持重启恢复，拒绝来源变化。

## 实施与验证计划

1. 先写测试：探索兼容/逐维边界、阶段晋降与状态恢复、坏教师不晋级、公共初始化的资格/版本/seed检查。
2. 最小实现config、Team、curriculum模块；runner接入状态、日志和初始来源校验，保证旧路径不变。
3. 实现IDM示范拟合与资格检查、staged实验入口和运行管理。真实小规模验证驾驶策略，而非仅断言接口通过。
4. 运行原34项及新测试，短训续训比较完整状态；实际bootstrap验证、一个短攻击run、评价/GIF/TensorBoard闭环。
5. 提供新服务器zip、依赖与源码hash、中文顺序指令；不启动长期正式训练，不保证算法优于基线。

不扩大网络、不加入强制低速罚、不取消教师门槛、不使用最终test调参。BC/探索变化均属于新的实验训练程序，应独立归档和报告。

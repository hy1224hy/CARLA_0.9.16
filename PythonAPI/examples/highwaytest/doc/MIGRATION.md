# 迁移记录与实验边界

日期：2026-11-07。实现位置仅在 `PythonAPI/examples/highwaytest`，依赖安装于仓库原有 `venv`。未启动、终止或连接原 CARLA 训练进程。

## 原项目逻辑对应关系

|原项目|本项目|处理方式|
|---|---|---|
|`environment/mut_mappo_env.py`|`environment/highway.py`|替换物理后端；四辆物理车、两蓝角色保留|
|冻结红车 actor|固定 IDM 红车|遵循轻量迁移计划；不是旧红策略的性能复现|
|`training/mut_mappo_learning.py`|`training/ppo.py`、`training/runner.py`|独立 MAPPO/GAE 实现，A/B 各自采样和优化|
|`training/mutual_distillation.py`|`training/ppo.py`|保留同角色、同输入的 student-to-teacher 高斯 KL|
|`GateState`|`training/mutual.py`|保留配对场景族证据、冻结教师、安全与质量门槛；轻量 quality 替换 CARLA 指标|
|通信设计草案|`models/team.py`|新增真正参与执行和梯度传播的单轮消息编码/接收|
|完整团队边界 checkpoint|`training/checkpoint.py`、`runner.py`|记录模型、optimizer、教师、门控、各自 RNG、预算与最佳选模状态|
|独立选模/最终评估|`evaluation/runner.py`|train/gate/selection/test 不同 seed 命名空间|
|实验注册/报告|`config.py`、`__main__.py`、`evaluation/report.py`|配置哈希、源码快照、15份矩阵配置、跨 seed 汇总|

这是研究逻辑迁移，不是数值逐项复现。新环境的观测、动作、奖励、步频、对手和任务长度都发生变化。旧 CARLA checkpoint 会被协议检查拒绝，禁止用它们冒充 Highway-env 的恢复训练。

## 正式实验顺序

1. 用 `configs/driving_g0.json` 检验普通 MAPPO 的正常驾驶学习与评估表现。脚本控制器能完成任务，仅说明存在可行驾驶行为，不能代替“MAPPO 可学习”的证据。
2. 预实验决定预算、共同奖励、成功/安全指标、门控阈值后冻结配置。对抗强度默认0.3是候选值，不是从正式测试选出的最优值。
3. 相同预算运行 G0/G1/G2 分离普通互学习与质量门控收益。检查门控覆盖、真实 KL 和成功/违规表现。
4. 增加 G3/G4，完成互学习×通信 2×2 比较；G5 可补有通信条件下的普通互学习对照。
5. 三个独立训练 seed 分别选模后做相同最终测试。消息置零、过期和丢包属于固定模型干预，不能代替无通信训练组。

当前平行/追近场景首先用于打通车辆任务和算法比较，不保证局部信息互补足够强、也不保证通信组会胜出。若无通信已近满分，或消息内容重复，应在正式结果冻结前增加有实际信息缺口的场景、统一调整所有组，而不能只提高通信组的信息权限。不能把无显著增益隐瞒为“有效性已验证”。

## 检查口径

- 单元检查：固定 seed 重现、感知范围屏蔽、无通信角色输入隔离、消息梯度、旧/新 log_prob 一致性、时间截断 bootstrap、配对门控、冻结教师、制动不倒车、总预算与精确恢复。
- 集成短测：六组各64个合计训练决策步，覆盖训练、选模、checkpoint、四种消息评估模式及预览输出。
- 独立可行性探针：四辆 IDM，以普通驾驶方式运行两类任务各4个案例。该探针替换蓝车为 IDM，检验的是场景可行性，不是连续策略控制器或学习性能。
- 当前不启动15组10万步正式实验；先交付可检查、可恢复的迁移实现。短测报告不得进入论文主性能表。

首轮集成探针曾暴露两个工程问题：临时 IDM 查询把同位置真实蓝车当作前车；原生 Vehicle 在持续制动后允许负车速。已将探针改成实际 IDM 蓝车，并在两条物理道路统一限制速度 [0,30]m/s；补充了不倒车检查。早期 `runs/smoke_20261107_103401` 已被后续修正版验证取代，保留用于追溯。

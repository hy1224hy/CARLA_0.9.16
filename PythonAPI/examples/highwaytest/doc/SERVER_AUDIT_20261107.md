# 服务器运行前审查（2026-11-07）

结论：修复下述问题后，可在服务器开展有日志、有对照的初步实验。尚未证明当前任务上 MAPPO 能稳定收敛，也没有互学习或通信收益结论；先做正常驾驶探针，再决定是否投入正式三seed矩阵。当前版本为配置/模型协议v2。

## 发现并修复

|问题|影响|修复|
|---|---|---|
|完全没有TensorBoard事件记录|不能按用户预期监控服务器实验|新增SummaryWriter；训练/回合/验证/门控分层标签，统一A+B预算横轴|
|训练回合没有累计return|每步奖励容易被误读成完整回合结果|记录团队均值、每角色return、终止/超时及场景族|
|恢复时直接解析所有JSONL行|崩溃留下半行会导致无法恢复|从checkpoint边界保留已提交行，容忍最后一行写入中断；内部损坏仍明确报错|
|TensorBoard恢复没有去重语义|曲线可能记录未提交尾段或重复预算|只在checkpoint提交后输出；恢复时purge并从权威JSONL重放，测试验证预算点不重复|
|critic只含当前四车状态，没有各车目标进度|随机起点对应的终止目标不能从critic输入完整恢复|每车增加目标进度，state由24改28；协议升级，拒绝旧checkpoint混用|
|汇总只比较任务，未比较预算与超参|不同训练预算/预训练方案可能被误当算法对照|增加完整比较contract、源码、同seed预训练哈希与唯一group/seed检查|
|没有服务器批次入口与并发保护|容易覆盖目录、重复启动、遗漏失败组|新增check/batch、批次清单、进程日志、OS文件锁、恢复/跳过已完成组|
|依赖只有宽版本范围|换服务器后可能不自知地改变运行环境|新增测试版本requirements-server、manifest版本快照，恢复/重启批次检查依赖漂移|
|源码哈希直接读取字节|Windows/Linux仅换行差异也会阻碍恢复|规范化源码换行后计算哈希；仍不保证跨平台位级一致|
|配置边界检查不完整|0Hz、过短episode、负seed、布尔线程数等可能延迟报错|补齐类型/范围/seed空间检查|

额外诊断包括稳定的非负近似KL、clip比例、梯度范数、critic解释方差、动作饱和、策略标准差、消息置零均值效应、链路覆盖及采样/更新吞吐。消息效应非零只说明策略使用消息，不能单独证明信息有益。

## 配置与成本判断

1. `driving_pilot.json`：正常驾驶G0、seed42、20,000训练决策步，先确认学习趋势。
2. `server_pilot/`：G0–G4各seed42、每组20,000步，均从头训练，对抗奖励0.3；可作探索性同预算对照，不能作多seed稳定性结论。
3. `adversarial/`：G0–G4各3seed，每组100,000步；保留作后续冻结实验，不建议当前直接全开。
4. 默认每轮A/B各512步。门控与选模每次共64个episode，在最长100决策步的情况下最多额外6,400验证步；20,000步pilot约5次验证，最坏额外32,000步/组。实际会因早停/到达而减少。训练预算公平不等于总耗时相同，应同时记录验证步和批次真实elapsed。
5. 当前单环境、CPU实现。`--jobs 2`是起点，不承诺GPU加速或固定吞吐。训练机资源、并行度和依赖版本写入运行记录。
6. 未保证场景必须通信才能完成；两车道平行/追近可能被独立局部策略解决。若无通信组已接近满分，应在正式方案冻结前统一增强信息不对称与协同要求，而非只给通信组更多真实状态。

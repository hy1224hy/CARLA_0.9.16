# 一红两蓝瓶颈实现方案（2026-11-09）

用户已选择此前提出的第二种方案，授权实现；不再重复设计审批。旧v3结果与发布包保留。新协议bottleneck_paired_attack_v4，目录和checkpoint身份独立。

## 设计

- 真实RoadNetwork两车道上游、平滑收窄段、单车道下游。红0，蓝1/2；角色显式传递，不伪造第四辆车。
- 两场景族：蓝B位于蓝A前34–44m或后60–70m；红车在A后18–24m。后位间隔避免正常参考车辆同时挤入车道收窄末端。红车正常IDM含固定案例风格，三条件参数一致。前位族包含蓝A可见红车、蓝B不可见的互补信息；提供相同蓝B观测、不同隐藏红车速度的结构检查。
- 25维局部观测：自身7、红车及另一蓝车各6、道路几何6；集中state25。actor/消息主干保持，critic适配三车。动作保持加速度±5m/s²、转角±0.25rad。
- 资格：25s固定时窗、两蓝到达瓶颈下游公共终点、原安全规则、相对固定IDM C1进度保持率>=85%、累计停车<=3s。候选参数经脚本校准冻结。C0/C1/C2参照同初始状态、红车风格、道路与时窗，U仍为合格额外红车损失/180m，失败计0。
- 保留场景族级门控：A/B初始状态指纹校验，KL在同一学生观测/通信掩码上，教师独立重算消息。没有声称实现逐状态反事实门控。
- 沿用BC->普通PPO->共享合格初始化->攻击课程、8组匹配预算、TensorBoard/preview/续训/评价。新BC演示使用瓶颈IDM控制。
- 修复G3严格一致性检查的批量浮点假阳性：批量超过阈值时回查与采样相同形状的逐行前向；真正旧策略不一致仍失败，记录两种误差。不直接放宽全局阈值。

## 实施与验证计划

1. 失败测试覆盖三车/真实拓扑/输入掩码与信息互补、角色安全统计、通行保持率、三条件风格配对、门控指纹及概率检查回退。
2. 新bottleneck子包负责契约、场景、环境、评价、演示、CLI/校准；共享模型、PPO、runner保持统一算法实现，旧路径默认不变。
3. 普通IDM负对照、双蓝/单蓝低速移动脚本对照；报告是否真正需要双车，不强迫联合效果优于单车。不用学习胜出作为单元测试。
4. 原47项+新增测试；真实校准、BC资格、短PPO与对抗恢复/评价/GIF闭环。仅工程验证，不运行长期主实验。初始间隔方案先固定，再在train/gate/selection/test各16个后位案例上做正常IDM可行性检查；这些test案例不是完全未查看的案例，没有用于学习策略或攻击收益调参，严格完全未触碰的主表应另设冻结留出案例。
5. 新服务器zip、独立seed42后台脚本和中文说明。旧checkpoint不直接续入；CARLA仍需对应三车场景/控制适配，不能把接口设计当真实CARLA性能。

# Highway代码与当前实验计划一致性审查

审查日期：2026-11-09。审查对象：`PythonAPI/examples/highwaytest/`，对照当前一对一直道、22维观测、三级奖励、同配置双训练副本互学习方案。本次完成代码审查及TensorBoard精简，没有实现新的三级训练环境。

## 结论

当前代码是既有v2/v3/v4多车研究实现，尚不具备当前计划的完整训练和评价链路。不能直接运行旧G0/G1/G4矩阵并将结果标为一对一三级奖励实验。

| 项目 | 代码证据与差异 | 影响 |
|---|---|---|
| 车辆与模型 | `models/team.py`固定两个actor；`common/contract.py`要求四车；v4有三车专用契约 | 未实现一可学习车+一规则目标车 |
| 观测 | v3为25维局部观测、29维集中状态；v4也有专用25维契约 | 尚无22维一对一接口，旧权重不可直接视为新模型 |
| 动作 | `common/contract.py:physical_action`使用有符号加速度±5、转角±0.25 | 与候选连续动作方案一致 |
| 奖励 | `common/objective.py`优化驾驶进度和截断为非负的参考延迟势函数 | 没有L1轻度范围、L2切入事件或L3正碰撞目标 |
| 失败处理 | 碰撞会惩罚并清除攻击势值 | 与L3目标相反 |
| 评价/选模 | `training/runner.py`按低bad_rate、驾驶资格和旧quality选模 | 即使只改奖励，也会淘汰新的L3成功策略 |
| 目标规则 | 已有IDM/MOBIL组件；配置中`red_lane_change`默认False，具体协议可覆盖 | 新主矩阵需要显式统一开启换道，不能依赖默认值 |
| 基础初始化 | 已有规则示范BC与驾驶PPO；旧维度、角色及驾驶资格绑定旧协议 | 能复用方法，仍需新单车接口适配 |

## 互学习机制

已有正确基础：

- runner维护两套同构Team，各自参数、optimizer、采样环境和随机流；不表示同一物理场景中车辆直接相互模仿。
- `training/ppo.py`在学生同一批观测/links上计算学生与教师分布，教师前向位于no_grad中；教师参数不被学生损失更新。
- 使用tanh前高斯的`KL(student || frozen_peer)`；PPO各自使用本副本on-policy样本。
- `training/mutual.py:snapshots`提供冻结副本，runner按refresh_rounds刷新。

需要明确的差异：

- 当前互学习对象是一整套双actor团队。新任务要改为每副本单actor，不能只改组名。
- G1=plain且关闭通信，最接近用户指定的基础互学习；G0是无互学习的双副本对照。G2/G4为选择性门控，G3/G4还涉及通信，不应自动作为当前主方法。
- warmup按round计数，之后直接使用固定beta；没有文档候选的按总训练步线性ramp。新正式实验须冻结明确日程。
- 教师是周期快照而非每个小批次实时更新的对方；需在算法描述中如实说明。
- 已报告的mutual_kl乘过样本门控，并非selective配置的未加权原始KL。G1激活后权重全1。

本次没有暗中改变旧奖励、门控、通信或训练日程；这些改变需要新协议及匹配的环境、评价和选模测试。

## 本次TensorBoard优化

实现位置：`training/telemetry.py`。改为白名单，不再递归记录所有数字。

| 分组 | 保留内容 |
|---|---|
| train/A、train/B | policy/value loss、entropy、PPO approx_kl/clip_fraction、explained_variance、gradient_norm、ratio_error、动作饱和率、加速度/转向std、learning_rate、采样更新吞吐 |
| 互学习（train下） | mutual_kl、gate_fraction、effective_beta、mutual_loss |
| rollout/A、rollout/B | return、success、collision、offroad、episode_steps、red_delay_m；新事件字段只有真实存在时才展示 |
| validation/selection/A、B | success/bad/collision/offroad、quality、qualified_attack_utility、参考无效数量、red_delay_m；新任务事件率只有真实存在时才展示 |
| curriculum | 实际attack_weight、curriculum_stage，仅当验证记录包含时 |
| budget | 累计validation_steps；横轴已经是A+B合计训练步 |
| 文本 | 完整配置及横轴说明 |

删除默认面板中的逐场景副本、逐物理角色回报/进度/停车重复曲线、通信效果/链路曲线、全部gate评估与逐场景开门曲线、无选择地展开数字的行为。完整JSONL仍保留这些原始记录，后续分析可以使用。

新增runner记录：effective_beta是本轮确实启用互学习且至少有样本开门时的beta系数，否则0；mutual_loss=配置beta×已经乘样本权重的mutual_kl。gate_fraction另外展示覆盖，不能把effective_beta误认为beta×覆盖率。

历史JSONL缺少新增字段时不补造0。重放历史记录也使用白名单；未删除旧event文件或改写原始日志。对已有run不绕过源码身份检查强行续训；本次Python源码变更会影响checkpoint中严格的source_sha256校验，应使用现有显式迁移流程审查后处理。

## 1. 适用范围

`evaluate_multi_adversarial.py` 设计时针对 [train_multi_adversarial_mappo_v2.py](../training/train_multi_adversarial_mappo_v2.py) 的 ckpt 格式。
新增的两个训练脚本：

- [train_multi_adversarial_kl_risk.py](../training/train_multi_adversarial_kl_risk.py)
- [train_adversarial_fixed_scenario.py](../training/train_adversarial_fixed_scenario.py)

ckpt 格式同样保存 `cooperative_ids / adversarial_ids / adversarial_actors` 三件套 → **原 eval 脚本能加载新 ckpt**，但训练几何/指标对齐不到位，effectiveness 数字会失真。

## 2. 检查结果

### ✅ 正确的部分

| 项 | 位置 | 备注 |
|---|---|---|
| ckpt 加载兼容 v2/kl_risk/fixed_scenario | L85-107 | 三类训练脚本均保存 `cooperative_ids/adversarial_ids/adversarial_actors` |
| baseline vs attacked 对照 | L160-166 | baseline 时 BLUE 用合作策略，attacked 时用对抗 actor |
| completion_time 度量 | L181-185 | 最后到达的合作 agent 步数 × timestep，仅成功 ep 记录 |
| deterministic eval | L158/165 | `get_deterministic_action`，eval 标准做法 |
| collision_sticky 跨步累积 | L170-172 | 正确反映 episode 内是否曾碰撞 |
| effectiveness 定义 | L228 | = baseline_coop_success − attacked_coop_success，可解释 |

### ⚠️ 问题清单

#### 🔴 P0-1 — 评估蓝车摆位与训练几何不一致（关键）

训练侧（kl_risk / fixed_scenario）必经此步：

```python
# train_*: 把蓝车摆在红车之间
scenario_config["agents"] = make_adversarial_positions(
    scenario_config, cooperative_ids, adversarial_ids,
    margin_ratio=adv_margin_ratio,
)
# → red[160] - blue[180] - blue[200] - red[220]
```

`evaluate_multi_adversarial.py._eval_scenario`（L193-198）**直接 `env.set_scenario(config)`**，不做摆位：

```python
config = env.load_scenario_by_name(scenario_name, scenario_dir)
if config:
    env.set_scenario(config)   # 文件里只有 agent0/agent1，蓝车走 env 默认 waypoint
```

**后果**：基础场景文件只声明 agent0/agent1（2-agent 设定），评估时 BLUE（agent2/3）走 env 默认 `_find_straight_road` 的 waypoint 分配 → 与训练几何完全不同。训练 TB 上的 `coop_success_rate` 趋势与 eval 不可比。

#### 🔴 P0-2 — goal_zone 静默继承（与训练侧同病）

`apply_scenario_config` 缺 goal_zone 时不重置 `self.goal_zone`。eval 跨场景循环时，前一场景的 goal 会污染后一场景。

#### 🟡 P1-3 — baseline 用合作策略 = "BLUE 未训练初始状态"（命名/文档问题）

[L124](../evaluation/evaluate_multi_adversarial.py#L124)：

```python
self.normal_policy = self.cooperative_actors[self.cooperative_ids[0]]
```

所有 BLUE 在 baseline 模式下都用合作 agent 0 的策略。
**这其实是对的**——训练侧 BLUE init 时就是用合作 agent 0 的预训练权重，所以 `normal_policy` ≈ "BLUE 未训练状态"。
但名字与含义存在歧义：用户可能误以为 baseline = "没有 BLUE"。建议文档明确：**baseline = BLUE 处于合作策略起点状态，attacked = BLUE 训练后**。

#### 🟡 P1-4 — 缺解释性指标

只输出 `success / collision / completion_time`，**没有**：

- BLUE 在威胁窗口内的步数占比（攻击意图覆盖度）
- RED 被威胁时的速度 vs 未被威胁时的速度（因果减速效果）
- 平均威胁分（攻击强度）
- BLUE 自碰率（验证 KL 锚定是否生效）

`effectiveness` 数字只能告诉你"BLUE 有没有效果"，**不能告诉你"为什么"**。

fixed_scenario 训练侧已经有这些指标（写在 TB 里），eval 没补齐 → 不可对照。

#### 🟡 P1-5 — deterministic + 同 seed → 噪声主要来自 CARLA 物理

[L201-209](../evaluation/evaluate_multi_adversarial.py#L201-L209)：同场景多 episode，policy 全 deterministic，环境也无随机化。N=5 时统计 power 较弱，主要测物理浮动。可加 stochastic 模式或起点 jitter。

#### 🟢 P2-6 — 默认 `--test-scenario-dir = data/training_scenarios`

in-distribution eval。泛化要求 holdout 目录，文档需明确。

## 3. 修复方案

| 编号 | 改动 | 优先级 | 改动量 |
|---|---|---|---|
| **M1** | 评估前调用 `make_adversarial_positions` + 可选 `--coop-start-config` 覆盖红车起点 | 🔴 必修 | ~40 行 |
| **M2** | `_run_episode` 累积 `is_any_red_under_threat` / `avg_red_speed` / `sum(compute_blue_threat_scores)`；`ModeStats` 加新字段；JSON/打印同步 | 🔴 必修 | ~80 行 |
| **M3** | env 侧 fail-loud（缺 goal_zone 时显式重置 + warn），与训练侧 P0-2 修复一并解决 | 🟢 已计划 | 已在 `对抗训练_初始化分析与修复计划.md` |
| **M4** | 加 `--policy {deterministic, stochastic}`，stochastic 时 BLUE 用 `sample_action`，提高统计 power | 🟢 可选 | ~10 行 |
| **M5** | summary 输出区分基线 BLUE 自碰率（应≈0）与对抗 BLUE 自碰率（应<15%）|🟢 可选 | ~5 行 |

### M1 摆位对齐草图

```python
from training.train_multi_adversarial_mappo_v2 import (
    make_adversarial_positions, _scenario_agents, _load_config_file
)

def _eval_scenario(self, env, scenario_name, scenario_dir):
    config = env.load_scenario_by_name(scenario_name, scenario_dir)
    if config:
        config = dict(config)
        # 可选红车起点覆盖
        if self.args.coop_start_config and ...:
            coop_cfg = _load_config_file(self.args.coop_start_config, scenario_dir)
            ...
        # 关键：与训练一致摆位蓝车
        if self.args.match_training_layout:
            config["agents"] = make_adversarial_positions(
                config, self.cooperative_ids, self.adversarial_ids,
                margin_ratio=self.args.adv_margin_ratio,
            )
        env.set_scenario(config)
```

## 4. 验收清单

新脚本 sanity（30 episode × 3 场景，约 10 分钟）：

- [ ] `baseline.coop_success_rate` ≈ 95%+（合作策略下 RED 应正常到点）
- [ ] `baseline.blue_collision_rate` ≈ 0%（合作策略不会自毁）
- [ ] `attacked.coop_success_rate` 低于 baseline ≥ 10%（对抗起作用）
- [ ] `attacked.blue_threat_window_pct` 显著高于 baseline（BLUE 主动施压）
- [ ] `attacked.red_relative_slowdown` > 0%（RED 被减速）
- [ ] `attacked.blue_collision_rate` < 15%（KL 锚定有效，不自毁）
- [ ] 全部指标在 per-scenario JSON 中输出
- [ ] 缺 goal_zone 场景被显式 warn（依赖 M3）

# Town05 正式实验迁移与 16 场景设计

> 状态：2026-08-12 已实现；离线几何、真实 CARLA 16 场景加载和 gamma 对齐单更新训练均通过。逐场重验曾暴露 CARLA 偶发丢失异步初速度请求，现已用同步状态提交、核验、有限重试和失败关闭修复；等待该初始化修复提交后在精确 commit 上最终重验。本文是 Town05 新实验背景的设计与执行真值；Town02 结果保留为历史证据，不与 Town05 checkpoint 续训或横向混算。

## 1. 迁移边界

- 正式地图：`Town05`，CARLA `0.9.16`，同步步长 `0.1 s`。
- 基础策略入口：`training.train_no_rllib_mappo_robust_v2`；默认场景池：`data/training_scenarios_town05_v1`。
- 训练场景：Road 44 南北向和 Road 3 东西向，共四个方向、四类任务、16 个场景。
- 留出评估：Road 43 南北向和 Road 6 东西向，8 个场景；训练过程不得采样。
- Town05 改变了地图几何、任务分布、合法变道语义和目标区，必须从随机初始化 fresh 训练；Town02 权重、优化器、RNG 与里程碑裁决不得 resume 到 Town05。
- 不沿用旧 pygame 可视化程序。日常查看采用初始化时联动 CARLA spectator 的即插即用方案；正式训练关闭额外渲染，避免改变吞吐。

## 2. 奖励与目标区语义

“车道居中”严格按每辆车当帧所属的 CARLA `Driving` lane waypoint 中心线计算：

1. 两车处于相邻车道且各自在本车道中心时，二者横向偏离均为 0。
2. 不使用双车道路幅中线，也不使用共享终点中心计算居中奖励。
3. 合法变道完成后，基准自然切换为新车道中心，不锁定出生车道。
4. D1–D3 使用 `goal_mode=preserve_start_lane`，导航目标也保持各自出生车道，避免共享宽目标产生向分隔线的隐性吸引。
5. D4 刻意使用一个半宽 `1.6 m` 的共享目标车道，从而使指定车辆必须完成并道。
6. Town05 中只含 `Broken` 标线的 lane-invasion 回调视为合法变道，不罚分也不计 unsafe invasion；`Solid`、`Curb`、未知/空回调仍是违规，人行横道仍按碰撞处理。Town02 历史语义不变。

## 3. 四类任务针对的问题

| 难度 | 家族 | 主要诊断问题 | 初始速度 |
|---|---|---|---|
| D1 | `parallel_stationary` | 最基础的并排冷启动、身份/左右车道对称性、从静止协同起步 | `0 / 0 m/s` |
| D2 | `parallel_rolling` | 同速并排行驶时的车道保持、无必要抢道和策略对称性 | `3 / 3 m/s` |
| D3 | `stagger_rear_closing` | 跨车道前后错位、后车追近时的速度协调与安全间距 | 后车 `5`、前车 `3 m/s` |
| D4 | `required_merge` | 必须跨越虚线进入另一车道时的让行、时序决策和非碰撞并道 | `3 / 3 m/s` |

四方向与 Agent 身份镜像，避免策略把“Agent 0/1”或某一个世界坐标方向误学成固定角色。

## 6. 2026-08-12 验证证据

- 离线几何：16/16 训练场景、8/8 留出场景通过；四难度、四家族、四方向和角色镜像均平衡。
- 真实 CARLA：2000 端口 Town05 逐场加载 16/16 通过；出生位置误差 `0–0.01 m`，滚动速度 `2.96/3.00 m/s`、追近速度 `4.89/5.00 m/s`。
- 旧最小训练：`T05_MIGRATION_SMOKE_20260812_121336` 完成 1 个 PPO update、4 个分层 episode、每车 480 transitions（总计 960），`approx_kl=0.00131/0.00166`，reward audit 残差 `1.78e-15`，无碰撞、无 skipped update，约 `41.43 transitions/s`。该 reward audit 只证明“已发奖励等于分量和”，不能发现奖励计算采用了错误 gamma。
- 旧 C0 入口：`P0_BASE_C0_smoke_u000001_20260812_121700` 协议验证 PASS；C0 环境正确使用 0.997，而其输入 checkpoint 的训练环境实际使用 0.99，因此这对产物只保留为工具链诊断，不进入正式训练、比较或选模。
- 2026-08-12 gamma 审计：训练合同、PPO/GAE 与 C0 均声明 0.997，但 `robust_v2` 创建训练环境时遗漏 `reward_gamma`，环境退回默认 0.99。现已改为同源显式注入、创建后 fail-fast，并在 checkpoint runtime 记录环境实际值；Town05 C0 拒绝缺失/错误实际 gamma 的 checkpoint，一键 smoke 自动核对 gamma、strict metrics 与清理；修复已提交为 `2d18f68`。
- 第一次提交后完整逐场重验只通过 14/16：场景 09 的 agent0 与场景 11 的 agent1 均出现 `position_error=0.50 m, speed=0/5 m/s`。同一 JSON 隔离重复时可正常达到约 `4.89/5.00 m/s`，方向、坐标和训练命令不变，且故障发生在 episode/PPO 之前；因此根因是 CARLA 服务端异步 `set_transform`/`set_target_velocity` 偶发未提交初速度，而不是 Critic、梯度、探索速度或训练时长。
- 初始化修复：每次尝试先对全车清零线/角速度，再把预偏移 transform 与目标速度分同步 tick 提交，最后按 `0.25 m / 0.25 m/s` 容差核验所有车辆；整组最多重试 5 次，仍不一致则 fail-fast，错误状态绝不进入 rollout。丢失第一次非零速度请求的单元回归已加入，全量 184/184 通过；修复工作树上的真实逐场复验恢复为 16/16。
- 提交前训练诊断 `T05_parallel_smoke_s42_20260812_160851`：1 update、4 episodes、每车 477 transitions（总计 954），1 collision/3 timeout；strict validator 验证 4 条 episode、197 个必需标签和 583 个 TensorBoard scalar 标签，checkpoint 验证 `training=environment gamma=0.997`，退出后恢复 async/None 且 vehicle/sensor 为 0/0。该 Run 包含未提交初始化修复，只用于证明修复方向，不作为正式性能或最终 clean-commit 证据。
- 验收命令勘误：首次专项测试从项目目录误用 `.\venv`，选中了无 NumPy 的内层空环境；规范路径 `..\..\..\venv` 下 62/62 通过。首次留出集 validator 使用了不存在的 `--allow-heldout-roads`，正确参数为 `--validation-pool`。二者均为调用命令错误，不是算法、场景或 CARLA 故障。提交前 training/GO-HOLD preflight 因 critical source 尚未提交而拒绝，属于预期 fail-closed 行为。
- 当前真实门槛：提交初始化状态修复后，必须在该精确 commit 上重新完成 16/16 初始状态核验及 1-update CARLA smoke，验证 `environment_reward_gamma=training_config.gamma=0.997`、strict metrics 和清理；提交前诊断不替代此门槛。
- CARLA 日志中的 `Town05.bin Nav cache` warning 不影响本次车辆生成、同步 tick、训练或评估；当前场景无行人导航需求，但后续引入行人前需单独解决。

## 7. 正式命令与下一门槛

```powershell
# 工作目录：PythonAPI/examples/mappo_training
..\..\..\venv\Scripts\python.exe -m utils.validate_town05_parallel_scenarios

..\..\..\venv\Scripts\python.exe -m training.train_no_rllib_mappo_robust_v2 `
  --host 127.0.0.1 --port 2000 `
  --experiment-contract configs/base_mappo/p0_base_town05_v1.json `
  --run-id P0_BASE_MAPPO_Town05_s42_<timestamp> `
  --updates 5 --cpu --follow-spectator `
  --save-dir logs/P0_BASE_MAPPO_Town05_s42_<timestamp>
```

唯一下一步是：提交 CARLA 初始状态同步核验修复，在 clean commit 上重跑真实 16/16 初始化和 1-update smoke。只有该 smoke、checkpoint 实际 gamma、strict metrics 和 CARLA 清理全部通过，才允许 fresh 运行 seed 42 到 update 5；随后立即停止并执行 strict validator、两次 C0 gate 和 Town05 GO/HOLD。不得恢复 Town02 u5，不得先启动多 seed 或 Phase 1。

其中 `--follow-spectator` 是即插即用俯视模式：每次 reset 后按全部出生车辆及其逐车/共享目标区自动计算中心和高度，只移动 CARLA spectator；不调用现有 pygame visualizer。正式无人值守训练可直接删掉该开关。

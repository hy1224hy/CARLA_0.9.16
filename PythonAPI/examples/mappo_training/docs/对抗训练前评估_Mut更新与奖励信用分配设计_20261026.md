# 对抗训练前评估、Mut更新与奖励/信用分配

2026-10-26。当前源码核对与建议设计。本文中的新奖励、团队成本及四组合贡献评估尚未实现；本轮没有运行CARLA，没有修改资格合同或训练算法。

## 1. 应先回答的驾驶能力问题

已有策略需要两层资格：在原任务上正常驾驶，以及在将要使用的四车初态中面对普通交通仍正常驾驶。基础驾驶资格不能由训练return或单次共同到达代替；对抗研究也不能只用无蓝C0替代普通蓝交通C1。

### 指标结构

| 维度 | 必需指标 | 当前状态与解释 |
|---|---|---|
| 任务完成 | 各车/团队到达率、超时率、路线完成度、失败原因、成功条件到达时间 | 原资格器已检查到达与到达时间；失败与成功条件时间应分报，不要求两车同步到达 |
| 安全 | 任意物理接触、蓝红/红红接触、越界、逆行/非法换道、事件对象与冲量 | 基础资格已有碰撞/越界/道路事件；接触事件按物理对象和帧去重，不能将两辆车传感器重复报告算两次 |
| 起步与效率 | 静止无阻挡起步延迟、巡航速度带占比、无阻挡低速比例/最长时段、上限外速度比例/峰值 | 已实现；真实阻挡从效率处罚中排除，安全/超速评估不豁免 |
| 横向与控制 | 参考车道偏差P95/峰值、实际转向变化率、控制回读覆盖率、踏板冲突 | 前几项已实现；合法换道任务需要单独的参考走廊及豁免，不能照搬自由行驶保持车道条件 |
| 纵向交互 | bbox净车距、道路切向闭合速度、TTC、THW、危险曝光时长、前车离开后的恢复 | BaseDrivingEnv已有修正的净距/TTC诊断，资格器尚未完整汇总；需要少量同道跟车与普通切入/释放探针 |
| 平顺性 | 纵向/横向加速度、jerk、实际控制变化的P95/尾部 | 当前资格仅覆盖部分控制平滑，物理加速度/jerk需补统计，先标定再冻结阈值 |
| 对称与稳定性 | 四方向、静止/滚动、前后/左右角色分层，各车最弱层、重复性、编号对差值 | 已有分层及配对规则；镜像和仿真seed不是独立训练seed，不能扩大独立样本数 |
| 证据有效性 | checkpoint/场景/协议SHA、真实初速、冻结actor、连续帧、缺失回读、清理与环境异常 | 已有大部分审计；缺失值不当作0风险，环境故障不当作驾驶失败 |

纵向安全量必须有清楚单位：

`net_gap = road_tangent_center_distance - ego_projected_half_extent - front_projected_half_extent`

`closing_speed = (v_ego-v_front) dot road_tangent`

`TTC = net_gap/closing_speed`，仅在前车存在、净距有效且正在闭合时定义；不闭合用不适用，不能记成0秒。THW仅在正向车速足够时定义。复用BaseDrivingEnv的bbox投影口径，不直接用旧父类把中心距命名为front_gap的字段。

### 现有合同可作为起点

`configs/evaluation/base_driving_vnext_v1.json`目前规定：

| 指标 | 当前合同值 |
|---|---|
| 静止无阻挡起步 | 达到0.5m/s前累计无阻挡时间≤2s |
| 任务巡航带 | 2～4.1667m/s，合格巡航采样占比≥80% |
| 无阻挡低速 | <0.2m/s占比≤5%，最长连续≤1s |
| 超过任务优选速度带 | 时间占比≤5%；峰值≤8.3333m/s |
| 参考横向偏差 | P95≤0.6m、峰值≤1.2m |
| 实际转向变化率 | P95≤1.5/s |
| 实际控制证据 | 回读覆盖≥95% |
| 评价条件 | 默认seed63001/63002，逐车、逐任务/方向/起步/角色分层，最低案例数与分层覆盖 |

这些是当前低速直道工程合同，不是道路法规或已验证的通用驾驶标准。峰值上限比巡航带宽松，不能据此将接近30km/h视为本任务正常巡航。需要在相同任务下标定并冻结，不能为放行某个checkpoint反复修改。

当前合同另要求零安全或超时事件，并检查团队到达率≥95%。实际是更严格的叠加条件；若今后允许少量任务超时，应把安全与任务完成分开定义，而不是只改95%文字口径。

### 评价任务与输出

1. 复用原基础训练的并排回归和32个独立验证配置，保持静止/滚动均覆盖；两seed的完整验证为64个episode。对抗训练只选滚动，不意味着基础资格取消静止能力评估。
2. 对拟用的8→24个对抗初态，先做C0无蓝、C1普通冻结蓝交通，检查红方自身与普通交互；C2学习蓝留作攻击效果评估。
3. 补少量纵向闭合、前车减速/释放、合法普通切入探针。它们是能力诊断，不构建新的192例训练网格；不要求旧策略必须永不减速。
4. 输出每车分层表、失败案例索引和曲线，按安全与能力资格过滤，再按效率等选择。训练return不参与资格排名，纯成功条件均值不掩盖失败案例。

### 现有证据

本地 `diagnostics/base_driving_vnext_20261020/long_s42_u600_v1/screen_u000600/validation/qualification.json`记录64个有效验证episode，共同到达率0.6875（44/64），资格为false，失败项含安全/超时、共同到达率和逐车分层。`u000600_summary.json`的选模结果为NO_QUALIFIED_CANDIDATE。

这说明框架已在使用，但不表示已有合格红方；也不能将u600结论套给u370或其他checkpoint。u370需按其真实协议单独评估；弱基线可用于工程流程检查，不能冒称合格正常红方或把其自然失败计为攻击收益。

## 2. Mut-MAPPO需要两套学习器，不要求并发训练

物理世界是红0/1加蓝2/3。A/B是两套蓝团队，不是红蓝双方。每套包含两个Actor、一个带车辆ID的集中Critic、自己的优化器、ValueNorm和随机状态。

当前 `training/train_mut_mappo.py` 的每轮执行：

```text
A用自己的Actor采集4个完整episode
A用自己的buffer更新Critic和蓝2/3 Actor，辅助项读取冻结B教师
B用自己的Actor重新采集4个完整episode
B用自己的buffer更新Critic和蓝2/3 Actor，辅助项读取冻结A教师
若到刷新边界：冻结更新后的A/B快照，串行gate评估，再同时替换双方教师与门控
保存完整A+B边界；下轮交换先后顺序
```

因此每轮两套团队各更新一次，不需要两个CARLA服务、两个GPU或两个同时推进世界的训练进程。B不会因为A刚在本轮更新，就立刻以该最新A作为教师；使用的是上次刷新形成的冻结快照，更新图不跨教师反传。

当前轮默认共8个episode，训练预算按A+B合计world ticks计算。A/B案例顺序对应，但动作随机流及episode seeds独立；各自轨迹只能进入自己的PPO。KL在学生自己的观测上重新计算同角色教师分布，不交换PPO轨迹、不平均网络参数。

红方全程冻结。B0也训练A/B两套，只关闭互学习；单团队MAPPO是另一个拓扑。A/B不是两个独立实验重复。

实现位置：训练循环382～448附近，`refresh_peers()`307附近；学习器的`set_peer()`309附近、`update()`332附近。蓝Actor仍按各自PPO优势更新；教师无梯度，Critic只拟合真实回报。

## 3. 建议固定的奖励版本

研究目标限定为“蓝方安全和任务资格内，相对普通交通降低红方通行效率”。奖励各算法组共用；第一轮不把奖励或信用分配也作为新的算法因素。

### 主攻击信号：C1参考进度落后面积

先用合格C1为每个训练物理模板记录红方各车的正常路线完成度曲线`p_ref,r(t)`。参考绑定红方hash、案例、目标、时限、普通蓝策略及初速，只使用对应训练/门控划分，最终test参考不进入训练。

令p为0～1的归一化路线进度，H为统一测量时域秒数，R为两辆红车。候选主项为：

`a_t = I(blue_eligible) * dt/(H*|R|) * sum_r[p_ref,r(t)-p_r(t)]`。

采用有符号差：红方比普通交通参考更快时为负；不因只保留随机差异的正半边而制造奖励。累计攻击项介于−1与1，主正收益上界清楚。实际推进采用冻结的路线投影/完成度口径；若需要改变既有欧氏距离完成度语义，应新版本化并检查蓝车是否可通过横移刷进度。

这是配对基线的效率代理，不是逐动作因果证明。普通C1自身不稳定时，先校准参考，不能用一条偶然很快的轨迹要求所有C2都达到。多次普通参考之间的差异应进入噪声与置信区间。

不再以“最近2秒降速2m/s”作为主分；不再按贴近3m程度递增攻击分；+5事件与+15超时转为诊断/次级评估。由此避免窗口忘记持续低速，也避免猛烈制动和普通超时关联支配目标。

### 团队效用与起步系数

建议先用共同团队效用：

`G_t = 10*a_t + d_team,t - c_risk,t - c_event,t`，有效蓝Actor接收同一个G。

- `d_team`是小权重团队蓝方路线推进势差，按两蓝平均，例如`mean_b(gamma*p_b(t+1)-p_b(t))`。正向总预算不超过约1，不另给蓝方大额到达奖金。
- `c_event`针对新物理事件：蓝方接触/越界/道路违规50，任务驻停违规20；同一接触不因两侧传感器重复扣费，也不把持续标志每帧当新事件。
- `c_risk`保留实际净距/TTC、连续超速和实际控制变化成本，统一时间量纲、记录各项贡献，权重经一次共同先导后冻结。超速项不因达到某速度而停止增长。
- 任蓝违规关闭本回合后续正攻击信用，事件成本作用于整个蓝团队。这里的资格/成本是任务约束，不能称法律责任划分。

10、1、50、20是依据归一化预算给出的首轮候选，尚未验证。其目的在于让主攻击正预算与安全成本可以比较，而非承诺硬安全保证。首轮固定这组成本规则，不再用4episode的0/25/50%离散违规率来宣称控制到5%。若研究严格约束优化，应另设计dual更新/约束估计及对照，不能继承CPO的理论保证。

### 生命周期是共同奖励能否正确回传的前提

当前蓝车到达后会移除、停止收集，其后团队攻击/超时奖金无法回传到该车先前的动作。因此换成团队效用时，必须明确统一测量窗口，分离动作有效mask与团队回报结算边界。

不允许给失活车伪造动作。可以在episode末对真实有效动作计算覆盖团队任务边界的return，或显式处理退场后的团队收益尾项；不能只改`rewards[2]=rewards[3]`就宣称完成团队信用设计。

成功到达后进度记1，不把已完成车辆的零速度当停滞。环境故障/外部截断不补造成50秒失败；真实红方事故单列结局，不凭结束后假想停车补发干扰分。统一时域的完成吸收状态可以按任务事实结算，但不能伪造物理观测或bootstrap。

## 4. 信用分配：训练与贡献解释分别处理

### 主训练先保持共同目标

对当前以Mut门控为研究变量的版本，推荐共享团队G，不再按“谁离红车最近”切分攻击分。每个Actor的策略梯度仍由自己的动作log_prob和优势产生；共享团队奖励不要求同一动作。带ID的集中V有助于拟合不同角色，但不等于它已算出因果贡献或解决搭便车。

这是一种明确的团队回报方案。若同时引入新的差分信用网络，就难以区分收益来自Mut选择还是信用估计。后续若要COMA式动作反事实，当前V(s,i)不够，需要联合动作价值Q(s,a2,a3)及连续动作反事实估计，不能将两个V直接相减。

### 用四种冻结控制组合检验贡献

保持同一四车初态、目标、红方和配对seed，不删车；0表示该蓝使用普通冻结策略，1表示使用学习后的攻击Actor：

| 组合 | 蓝2 | 蓝3 |
|---|---|---|
| 00 | 普通 | 普通 |
| 10 | 攻击 | 普通 |
| 01 | 普通 | 攻击 |
| 11 | 攻击 | 攻击 |

各组合按同一冻结的安全/效率效用U评价，不能使用各团队自己不同的训练lambda或Critic数值排名。

两蓝的配对Shapley型分解为：

`phi2 = 0.5*((U10-U00)+(U11-U01))`

`phi3 = 0.5*((U01-U00)+(U11-U10))`

因此`phi2+phi3=U11-U00`。联合交互项为：

`I = U11-U10-U01+U00`。

I>0说明在该基线与评价定义下存在超加性收益；U11优于单蓝只说明联合增量，不能自动说明超加性。phi可以为负，不应裁成0或重新归一化成正比例，否则破坏分解意义。

普通蓝替换会改变其他车辆后续观测；这是完整策略干预的案例级贡献，不是同一物理状态下的精确动作反事实。CARLA需要匹配初始化及扰动证据，并按完整物理模板/配对与外层训练seed报告不确定性。先用于冻结评估，不将这些参考轨迹混入PPO训练。

若每个训练episode都跑四组合，仿真成本显著增加且近似物理恢复问题更复杂，因此不作为第一版在线信用分配。未来确认搭便车问题后再独立引入差分回报或反事实critic，并给所有Mut组使用同一版本。

## 5. 当前已有与需要实现的界线

| 项目 | 当前状态 |
|---|---|
| 基础逐车自由行驶资格、分层和冻结评估 | 已实现，有未合格报告 |
| 跟车/切入能力、TTC/THW与物理平顺性完整资格 | 需要补齐 |
| A/B串行采集与更新、冻结教师、各自buffer | 已实现 |
| 当前奖励：事件+距离威胁+关联超时、个体驾驶/成本 | 已实现 |
| 本页的C1参考进度效用、团队安全成本、回报尾项处理 | 候选，需要实现与共同先导 |
| 四组合与Shapley型贡献评估 | 候选，需要实现；当前不是COMA |

建议执行顺序：先补齐驾驶资格与C0/C1依据，再冻结共同奖励和测量窗口，最后比较B0/B1/B2；四组合用于解释协同。场景仍按8→24的基础配对思路，不追加全组合网格。

文献边界：[COMA](https://arxiv.org/abs/1705.08926)提出动作反事实baseline；[CPO](https://arxiv.org/abs/1705.10528)讨论显式约束策略优化；[Shapley原文](https://www.rand.org/pubs/papers/P295.html)是边际贡献分解的经典依据。本页不是这些算法的实现或理论复现。

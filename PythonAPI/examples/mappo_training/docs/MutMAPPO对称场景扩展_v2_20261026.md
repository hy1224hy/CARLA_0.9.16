# Mut-MAPPO 对称场景扩展 v2

2026-10-26。范围是丰富同向四车对抗初态，生成更多对称案例。本轮没有启动CARLA或训练。

## 当前实现与扩展结果

训练入口从case manifest读取固定案例，调用 `MutMAPPOEnv.reset_case()`：先载入两辆红车的基础场景，再用 `red_overrides` 设置速度，沿红车所在车道的waypoint弧长在前方放置两辆蓝车。蓝方在episode内自由输出连续控制，blocking/cut_in是初态类型，不是预先写好的攻击轨迹。

旧训练集只有4例：blocking/cut_in × north/south。红车速度固定3m/s，蓝车前向距离固定15/22m，初速度固定2.2/2.35m/s；换seed不会改变几何参数。旧gate/selection/test仅在同一对走廊上做少量间距、速度变化。

新增 `data/mut_mappo/symmetric_v2/cases.json`，兼容现有 `mut_mappo_cases_v1` 读取协议：

| 轴 | 取值 | 数量 |
|---|---|---:|
| 交互族 | blocking / cut_in | 2 |
| 道路方向 | north / south / east / west，Road 44与3 | 4 |
| 红方角色 | 红0在物理左车道 / 右车道 | 2 |
| 蓝方纵向角色 | 蓝2在近端 / 远端，蓝3取另一端 | 2 |
| 完整组合 | 每个参数组保留全部组合 | 32 |

| 划分 | 参数组 | 案例数 | 每个交互族 |
|---|---:|---:|---:|
| train | 3 | 96 | 48 |
| gate | 1 | 32 | 16 |
| selection | 1 | 32 | 16 |
| test | 1 | 32 | 16 |
| 合计 | 6 | 192 | 96 |

共生成8个基础红车模板。红方左右互换会交换真实出生姿态；蓝方近远互换会一起交换距离和速度，保留对称的运动学条件。不同方向使用地图中真实存在的同向双车道，不对世界坐标做任意旋转。

CARLA物理左方向为 `(sin(yaw), -cos(yaw))`。生成器按坐标判断左右，再写入正确的角色标记，不照搬历史源文件名中的left标签。

## 初始距离与速度

距离是蓝车中心相对其出生车道红车中心的前向弧长，不是保险杠净距；速度单位m/s，是出生初速度，不是持续控制目标。

| 划分/参数组 | 两辆红车速度 | 近端/远端距离m | 近端/远端蓝车速度 |
|---|---:|---|---|
| train t0 | 3.0 | 10 / 16 | 2.4 / 2.55 |
| train t1 | 3.3 | 12 / 19 | 2.5 / 2.65 |
| train t2 | 3.6 | 14 / 22 | 2.7 / 2.85 |
| gate g0 | 3.1 | 11 / 17.5 | 2.45 / 2.6 |
| selection s0 | 3.4 | 13 / 20.5 | 2.6 / 2.75 |
| test e0 | 3.7 | 15 / 23 | 2.8 / 2.95 |

这些数值是初期候选范围。红车略快于蓝车，允许产生接近和交互；初始距离仍留有空间。生成器检查按初速度匀速运动时，3秒出生保护期内中心间距不低于5m，但这不是对实际策略动作的安全保证。真实reset仍检查出生接触、偏移和车道证据。

blocking中蓝2/3分别以红0/1所在车道为出生锚点；cut_in中交换锚点，并保留现有相邻车道与虚线/换道许可检查。当前奖励和策略没有强制某个蓝车只攻击某个红车，也不强制cut_in案例一定换道。左右、前后变体丰富的是初态与角色分配；两种family不是已验证的不同攻击行为。

各方向路线长度仍沿用各自基础场景，约39.5～45m，因此是局部交互参数与角色均衡，不是四条路线在世界坐标中的严格几何同构。暂不加入路口、逆行、天气变化或必须并线的新任务。

## 采样与数据划分

现有训练循环按清单顺序每次采集4个episode。新清单的每个连续4例包含：四方向各1例、两类交互各2例、红0左右各2例、蓝2近远各2例。A/B采集相同案例序列，保留各自采样随机流。

每团队需要24次更新，且训练tick预算没有提前用尽，才能遍历96个训练案例一次。遍历不代表收敛。原本2轮流程检查只会覆盖8个训练案例；改用新清单不会自动延长预算。参数组按t0、t1、t2顺序循环，不包含基于表现动态升级的课程。

同一参数组的全部32个对称变体必须留在同一划分，防止只把同一个参数组的镜像放到测试中。物理去重依据四个固定角色的实际初态，忽略名称、seed、family和元数据。镜像变体存在相关性，192个案例不是192个独立实验种子。

四个划分仍共用这四条走廊，属于同走廊参数留出，不能据此宣称跨地图泛化。gate每族从8例增加到16例，原有违规率/质量差门槛不变；一次A+B教师刷新需要64个验证episode，需单独记录验证成本。

## 文件与使用

- 生成器：`utils/build_mut_mappo_symmetric_cases_v2.py`。
- 清单与覆盖统计：`data/mut_mappo/symmetric_v2/cases.json`、`coverage.json`。
- 地图检查证据：`data/mut_mappo/symmetric_v2/offline_map_validation.json`，绑定清单、8个基础模板及OpenDRIVE的SHA256。
- 独立候选配置：`configs/mut_mappo/symmetric_v2_candidate.json`。

在 `PythonAPI/examples/mappo_training` 目录下，用本仓库venv执行：

```powershell
# 核对生成结果与地图拓扑；不创建CARLA Client，不推进仿真
python -m utils.build_mut_mappo_symmetric_cases_v2 --check --validate-map

# 核对候选配置接口、checkpoint与清单身份
python -m training.train_mut_mappo --config configs/mut_mappo/symmetric_v2_candidate.json --validate-only
```

新增候选配置继承 `local_candidate_v1.json`，只改场景清单；其红方仍是该配置里的R8C1候选，不会自动切换为u370。`method=off`、2轮及其他预算也保留，不能直接当成长训练或完整场景遍历。既有默认入口仍指向旧清单。

使用另一份已有红方/服务器配置时，在对应运行目录生成新的独立配置：

```powershell
python -m utils.build_mut_mappo_symmetric_cases_v2 --base-config <已有配置.json> --config-output <新候选配置.json>
```

这会保留源配置的红方checkpoint、奖励、方法与预算，只改为新清单并标为candidate。不要拿新清单恢复旧run；清单身份发生变化，应建立新的run目录。

已有实验规划工具可据新候选配置生成B0/B1/B2先导队列；它只写计划，不启动训练：

```powershell
python -m utils.plan_mut_mappo_experiments --config configs/mut_mappo/symmetric_v2_candidate.json --phase pilot --suite core --output logs/mut_mappo/queues/symmetric_v2_pilot
```

真实训练前仍要串行验证四车实际出生、传感器与C0/C1/C2配对结果，再依据吞吐和覆盖决定预算。v2清单的正式冻结依赖这些运行证据。

## 本次验证

192例均通过本地Town05 OpenDRIVE检查，调用生产环境的 `_resolve_case()`，覆盖Driving车道、切入换道许可与标线、初始中心间距、物理初态去重、同车道前向目标可达性。未创建CARLA Client，没有真实车辆出生或world.tick。

24项离线检查通过，包括新增的对称配对、完整组合、四例采样均衡、物理去重、划分隔离、现有配置兼容，以及原奖励、生命周期、几何证据与实验注册表回归。

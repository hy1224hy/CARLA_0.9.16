# u356→u456新奖励微调结果与下一步（2026-09-28）

## 结论

本轮确实改善了训练中的任务完成率、越界和超时，但没有持续解决双车效率不平衡，也未控制高速行为。继续相同配置堆轮数不应作为首选；保留u456和原u356，在小范围行为复测后调整效率与超速约束，再做短微调筛选。

本报告未修改训练、环境或奖励源码，未连接CARLA或执行评估。原实验100updates完成、最终断点哈希已核实，监控carla-20已删除。

## 奖励与学习机制

1. 当前route_pace_v1参考速度2.5m/s（9km/h），按自身累计畅通时间计算计划进度。落后越多扣分越大，每步最多-0.05；没有队友进度项，不直接奖励同步到达。它能增加拖延的代价，但不保证两车形成相近的驾驶效率。
2. 超速15km/h起罚、30km/h即达到每步-0.005上限，之后50km/h与30km/h扣分相同。与pace最高成本相差10倍，只是局部量级对比，不代表完整回报相差10倍。末20轮agent0超速风险非零步占比按update均值75.16%，两车峰值49.12/40.50km/h，约束不足有直接证据。旧策略也已有45–49km/h峰值，不能说全由这次新增。
3. 累计落后会形成历史欠账：即使当前速度已经恢复，欠账未清除前仍可扣分；成本饱和时不同程度落后不再区分。赶进度缩短惩罚暴露时间可能鼓励加速，但该解释需轨迹核实。
4. pace畅通累计时钟和初始路线长度未显式进入当前观测，含前车豁免的历史不一定能从瞬时观测恢复。对无记忆MLP而言奖励状态不充分可见；这是已知设计缺口，不等于已证明它是本轮不平衡的主因。
5. 两车独立Actor、不同初始状态/车道可能固化差异，但这次不能将问题归因于MAPPO不适用或无参数共享。数值未出现nonfinite、跳过更新或ratio/奖励残差异常；critic EV有波动，单凭EV也不能认定训练实现出错。

## 建议路线（实现前供用户审核）

1. **先做一次小规模定位。** 保持u356/u456权重不变，使用现有evaluation.evaluate_reward_fork同协议比较，优先短静止04、南长静止10、东长静止11和北长05。默认12场景×2种子×2权重共48例的现有入口也可直接使用；若要只跑上述4场景，需要先补场景筛选参数。看起步延迟、畅通时低速时长、首车到达时另一车进度、超速、碰撞类型，不仅看到达差。暂不启动评估。
2. **奖励优先处理超速与效率目标的一致性。** 建议把畅通直行9–15km/h作为初始候选区间而非已验证最优范围；区间内不加额外速度奖励，区间下对沿路线方向的低速/停滞扣费，上界以上增加连续且随速度继续增长的超速成本，避免30km/h后成本不再增加。前车阻挡、合理起步加速和终点减速需要豁免或调整目标。保留终止碰撞/越界成本，不先放大所有惩罚。
3. **简化历史欠账项。** 优先考虑用可由当前观测计算的路线方向速度缺口替换累计pace；这样便于在保持现有观测维度时做微调对比。它仍须考虑可见障碍和终点制动，不能只惩罚标量低速，否则会催促危险跟车或偏航。若保留历史pace，则应显式提供缺口/时钟等状态，并另设观测协议版本；不能直接当原20D checkpoint无变化续训。不要同时再加队友进度差惩罚，以免鼓励快车等慢车、掩盖真实效率。
4. **再短微调筛选，最后重训。** 新版本另建run，保留当前数据；从同一可恢复状态做20–50updates观察，优先u356以便延续已有比较。若短窗口能同时改善慢车与安全，再从头训练确认。20–50为建议预算，不是效果保证；正式结论需要旧奖励同预算对照，而工程筛选阶段可先不扩展多组实验。不要现在继续同配置跑到600，也不要直接认定此新奖励已可正式重训。
5. **正式基础策略再扩展场景。** 当前覆盖充分，但只是12个固定场景，不能排除过拟合。加入合法范围的起点纵向偏移、初始速度/相对间距变化与agent车道角色交换，并留出独立参数组合做验证。方向和车辆角色使用平衡采样，避免把几何非法的点作为随机化。先稳定当前任务，再扩展对抗训练。

最小下一步是一次行为对比，随后修订速度成本和效率项；不建议此时重做网络、增加复杂课程或堆叠更多奖励项。

# R2固定奖励长预算诊断计划（2026-11-04）

状态：PLAN_PENDING_METRIC_IMPLEMENTATION。本文为本次核验后提出的具体计划，未创建或启动新CARLA训练。已有R2仍完成于v4的43轮/24k软上限，不修改其配置、源码快照、模型或评估。

目的：验证固定R2奖励与当前MAPPO/PPO配置，在增加交互预算后能否同时改善蓝方驾驶与对红方的危险交互；区分持续学习、减少交互、提速脱离及表现平台。单seed曲线不能证明PPO一般有效、R2优于其他奖励或B2优越。

## 1. 先完成测量准备

复用现有OBB TTC、事件、物理接触、驾驶诊断和配对报告模块，实现docs/危险交互指标口径审查与建议_20261103.md所述新增分项：

- 接触前持续预测冲突出现率（0<TTC≤1.5秒，连续至少0.3秒，同一红蓝车辆对）。
- 实际接触、无接触且已观察到解除、观察截断、几何与物理接触不一致分别计数。
- 蓝方事件资格G，以及速度、合法行驶区域/合法换道参考走廊、实际操纵质量；完整驾驶D的规则必须先明确，不能直接套用保持起始车道阈值判定合法切入。
- 全有效回合分母下的D与无接触险情联合率，配合原始危险、TET、红方急减速、任务完成和C1配对变化。旧q_event、碰撞分项继续保留。

先对R0/R1/R2已完成冻结轨迹离线重算，复核R2 A两例几何重叠但无物理接触记录、以及事件末端censoring。该步骤不消耗CARLA ticks。指标实现和可解释性核验完成后冻结分析协议及SHA；不为让R2过关调整原阈值。

## 3. 冻结评估与成本

训练器已经保存每个完整边界的不可变round文件。登记初始round0，以及实际train计数首次达到24k、48k、72k的完整A+B边界与SHA；记录每个节点实际ticks，不能把软上限后的边界标成精确预算。

训练完成后串行评估这些快照，避免评估进程与训练争用世界。初始模型用于衡量学习相对Actor初始化带来的变化。每节点使用相同24个gate案例、固定配对seed、C0/C1/C2、A/B分别报告，即144回合；四节点共576个冻结评估回合。该清单已用于开发，不作为heldout；selection/test保持未用于本轮选参。

预登记成本：72000主训练ticks及完整边界超额；内部gate在约10k/30k/50k/70k共4次、每次48回合（实际刷新边界可能后移）；冻结评估576回合；必要参考重建、启动/cleanup及废弃采样另列。已有参考只有身份及完整证据校验通过才复用，否则新建并计费。

历史R2训练监督器约2026-11-01 18:19:36至18:48:02（北京时间），约28.4分钟，包含一次内部gate验证。按相近吞吐，72k训练约1.5小时量级；四节点冻结评估再约一小时量级。预计真实执行约2–3小时，回合长度、渲染和服务状况可能显著影响耗时；不把此估时当固定承诺。离线指标开发与参考重建不包含在该估时内。

## 4. 结果判断与分支

先核验数值完整性、奖励分项残差、实际Actor更新、Critic/ValueNorm及UUID/worker退出证据。PPO链路此前离线已通过，但驾驶目标还需真实轨迹验证。

- 若相对round0，蓝方驾驶改善且无接触预测险情/联合目标和C1配对指标有一致改善，则支持这套R2+当前PPO在该弱红工程任务上可学习，继续准备同预算B1/B2；一个seed不作正式算法结论。
- 若坏率下降、预测冲突和红方响应也下降，结合轨迹检查是否在减少交互或更快脱离。不能以单一总危险率作结论，也不能只看奖励升高。
- 若24k至72k冻结表现平台且离目标明显，结合KL、梯度、探索与奖励分项，再做固定预算下单变量的学习率或数据复用对照，或新版本奖励修订。不一边训练一边换奖励，不自动超过本次预算。
- 若B0支持继续比较，B0/B1/B2必须固定同奖励、场景、初始化、学习率时钟和实际预算。R2与R0的奖励优劣另需同长预算对照，不能用R2 72k对R0 24k宣布奖励获胜。

## 5. 运行与异常处理

实际启动前核对服务、Town05、当前controller及锁所有权；已有活跃worker则跟进，不重复tick/reset。启动时登记完整源码/配置/checkpoint SHA、实际worker和预算。长跑使用20分钟纯文件监控，健康推进保持安静，异常/重要结论/完成时通知；整体任务完成后删除对应监控。

发生NaN/Inf、奖励/状态异常、进程原生退出、GPU显存错误或失联时保留日志、未提交样本成本与退出证据，在完整边界停止并诊断；不自动重启CARLA或无上限重试。几何/接触证据争议与事件观察截断不能伪作已确认无接触险情。

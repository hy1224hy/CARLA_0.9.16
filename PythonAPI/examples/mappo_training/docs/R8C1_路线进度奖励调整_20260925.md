# R8-C1 路线进度奖励调整（2026-09-25）

状态：用户授权的奖励调整已实现并完成离线检查，尚未连接 CARLA、启动训练或验证策略效果。新干预名称 `v6 + route_pace_v1`，旧 `v6 + frozen_v6` 默认行为保留。

## 当前奖励的问题

当前实际运行的是 v6：保留 v5 的折扣路线势能、到达奖励、安全/道路违规/超时成本，再增加 `free_flow_pace_deficit`。不是旧版说明中的每米 +20 奖励。

旧 pace 公式为 `-0.01 * clip((剩余路程比例 - 剩余时间比例 - 0.05)/0.95, 0, 1)`，以整个超时时限作为进度标准，短场景 20 秒、长场景 50 秒。等待数秒的成本很小；前 2 秒及最后 10% 路段还豁免。

另外发现实际覆盖缺口：01–04 同时有 `free_flow` 和 `non_interactive` 标签；05–08 只有前者，09–12 没有这对标签。因此旧 pace 实际只对前四个短场景生效。环境读取标签时没有自动补齐。本次保留场景文件，通过新奖励的明确 family 白名单补齐覆盖。

这些是代码层面确认的问题，但不能据此认定它们是两车先后通行的唯一原因。

## 本次实现

每辆车按自己的初始目标距离 L 和当前路线完成度计费，不使用队友是否到达、两车进度差或排名。

- 参考进度速度：2.5 m/s（9 km/h，低于现有超速成本起点 15 km/h）。这是初始实验参数，尚未经实车仿真调优。
- 起步宽限：2 秒；允许进度落后 2 米。
- 期望前进距离：`min(L, 2.5 * t_free)`。`t_free` 是宽限之后、没有前方阻挡的累计合格时间。
- 超出容忍带的落后距离：`lag = max(0, 期望距离 - L*完成度 - 2)`。
- 成本：`-0.5 * timestep * min(1, lag/5)`，0.1 秒步长下每步最多 -0.05。达到参考进度没有额外成本，也没有速度正奖励。
- 保留前方阻挡和复杂交互豁免；阻挡期间暂停进度时钟，解除后不会把那段等待记成新增进度债务。
- 终止步、已到达/已销毁车辆不再计费；每次 reset 清空进度时钟。
- 取消末段 10% 自动豁免，继续允许 2 米误差，并以已有终点判定结束。
- 除原双标签场景外，明确允许 `free_flow`、`parallel_stationary` family；当前 12 个场景均覆盖，未放开 required_merge 等复杂任务。
- 进度势能、成功奖励、碰撞/越界/道路违规、超时、车道和控制平滑等奖励保持原公式。

例：起步后第 4 秒仍停在原地，前 2 秒宽限后参考进度为 5 米，超出容忍带 3 米，当前步扣 0.03；旧短场景约扣 0.00158，旧长场景因标签不满足不扣。持续完全落后的 50 秒回合中，新增成本的粗上界为 25，实际还受宽限、阻挡、终止等影响；碰撞终止原惩罚为 50。这个上界只是量级检查，不是安全保证。

## 接入与续训标识

数学实现位于 `environment/route_pace_reward.py`；环境 v6 分支显式选择 profile；训练入口接受 `--reward-version v6 --pace-profile route_pace_v1`。不是修改旧奖励默认值。

新 profile 写入 checkpoint 的 `training_config`、`protocol_versions.pace_reward`、运行元数据和 `metrics_schema.json`。续训未显式指定 profile 时自动恢复；显式改成另一 profile 会拒绝。新 profile 不能绑定旧冻结实验契约。`pace_deficit_raw` 在新 profile 中单位为米，日志 schema 已注明；旧版此字段是比例，不能直接合并比较。

旧契约、旧 v6 数学文件、场景和 u356 checkpoint 没有改写。修改前的三个共享源文件备份在 `diagnostics/reward_route_pace_v1/original_sources/`（env、trainer、recorder）。共享源码变动会触发旧训练代码指纹检查，因此不能直接用旧 `resume_r8c1_u600.ps1` 启动新奖励，也不能声称原实验仍可在当前源码下无条件原样续训。备份用于还原原执行版本/建立隔离对照，不应覆盖现有工作目录。

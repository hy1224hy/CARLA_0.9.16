# R2 奖励预算校准：论文正文与实验设计

> 适用范围：Town02 两辆基础红车、二维 signed-longitudinal 动作协议、基础 MAPPO 当前训练入口与 C0 v3。
> 因果边界：R2 只修改基础策略奖励的结构、尺度、指标和契约；Actor/Critic 结构、观测、场景、PPO 超参数及 CARLA 动力学均保持不变。
> 实验状态：本节完成的是无 CARLA 数学、代码和协议验收，不声称策略成功率已经提高；真实行为验证位于 R5。
> 执行勘误（2026-08-12）：奖励公式与离线预算测试按 `gamma=0.997` 正确建立，但当时的正式训练入口创建环境时遗漏 `reward_gamma`，实际 PBRS 使用环境默认 `0.99`，而 PPO/GAE 和 C0 使用 `0.997`。Town02 R3 u5 与修复前 Town05 smoke 因此只能作为历史诊断，不是本节折扣一致性的实验验证。当前入口已改为单源注入、运行时 fail-fast 和 checkpoint 实际值记录；新 Town05 证据必须在修复提交后 fresh 生成。

## 1. 修改动机

R0 的 update 10 诊断显示，随机训练动作中两辆车的 brake mode 约为 68%，两次确定性 C0 均为两车全程制动、16/16 timeout。同期 agent 0 的速度正奖励约为 `+26.79/episode`，但 `steer_rate=-272.23`、`jerk=-123.14`、`step=-80.47`。因此，当前失败不能简单解释为“训练时间不足”：带噪前进积累的稠密惩罚显著大于前进收益，而停车能够同时规避碰撞和动作变化成本，形成了可重复的局部最优。

R1 已经消除三维 WTA 动作的冗余、切换不连续和零均值半油门偏置，但没有修改奖励。R2 的研究问题是：在动作、Critic、场景和 PPO 不变时，能否建立一个量级可审计、无法通过停车或往返运动刷分、并满足预注册轨迹排序的基础驾驶奖励？

## 2. 文献依据与设计选择

Ng、Harada 与 Russell [1] 给出了 potential-based reward shaping 的形式

\[
F(s_t,s_{t+1})=\gamma\Phi(s_{t+1})-\Phi(s_t),
\]

并讨论了其策略不变条件。Kendall 等 [2] 以安全接管前的行驶距离作为自动驾驶的核心任务信号；Jaeger 等的 CaRL [5] 在 CARLA 和 nuPlan 中以 route completion 为主要奖励，并报告复杂的多项稠密 reward 会给 PPO 优化带来困难。这些结果共同支持“路线完成度为主、辅助项尽量少且有界”的方向。

Zhu 等 [3] 将安全、效率和舒适性分开构造，其中舒适性使用物理 jerk；Lin 等 [4] 进一步通过 Pareto 分析表明，小 jerk 权重可以改善舒适性，但权重过大可能妨碍必要的避险控制。因此，R2 不再把 throttle 变化误称为 jerk，而是明确惩罚实际执行的纵向命令变化率与 steer 变化率。物理 jerk 不进入本阶段 reward；若后续使用，必须由车辆加速度差计算并单独验证信号质量。

论文提供的是结构依据，而不是可直接复制的系数。本项目的 `dt=0.1 s`、最长 1000 步、约 100 m 目标距离和终止语义均与文献不同，因此具体数值由本项目的轨迹级预算不等式确定。

## 3. Reward v3 数学定义

### 3.1 路线完成度势能

令回合初始目标距离为 \(d_0>0\)，当前距离为 \(d_t\)，定义裁剪后的路线完成度

\[
q_t=\operatorname{clip}\left(\frac{d_0-d_t}{d_0},0,1\right).
\]

唯一的正稠密任务信号为

\[
r_t^{\mathrm{progress}}
=\alpha(\gamma q_{t+1}-q_t),\qquad \alpha=10.
\]

当 PPO 使用相同折扣因子时，长度为 \(T\) 的折扣和严格望远镜化：

\[
\sum_{t=0}^{T-1}\gamma^t r_t^{\mathrm{progress}}
=\alpha(\gamma^Tq_T-q_0).
\]

因此，从同一完成度出发的前进—后退闭环不能制造净 progress 回报；停在起点时回报为 0；在终点附近拖延会因 \(\gamma^T\) 墦加而损失价值。这里借用了 PBRS 的代数形式和望远镜性质，但由于路线完成度本身就是任务目标、且有限回合的终止完成度不强制为零，R2 不声称它是对旧 reward 的“最优策略不变变换”。

### 3.2 终局预算

成功和碰撞互斥，且同一仿真 tick 同时发生时碰撞优先：

\[
r^{\mathrm{success}}=+10,\qquad
r^{\mathrm{collision}}=-20.
\]

因为 \(q_T\le1\)，任意时刻发生碰撞时，progress 与碰撞终局项的折扣和满足

\[
\gamma^{T-1}(10\gamma q_T-20)<0,
\]

而安全停车在无其他成本时为 0。因此即使接近终点后碰撞，也不能通过之前积累的 progress 超过安全停车。

### 3.3 有界辅助成本

R2 取消正 speed、alive、centering、yaw、approach、固定 step 和 time bonus。车辆只有真正减少目标距离才能获得正稠密奖励。辅助项全部非正且先归一化：

| 分量 | 定义摘要 | 单步最大幅值 |
|---|---|---:|
| overspeed | closing speed 在 15–30 km/h 间线性升为满风险 | 0.02 |
| longitudinal rate | \(\min(1,(|\Delta(T-B)|/(0.1\times2))^2)\) | 0.005 |
| steer rate | 与纵向命令相同的归一化二次成本 | 0.005 |
| LiDAR risk | 使用最近 ray，不对 11 条 ray 求和 | 0.01 |
| TTC risk | 3 s 阈值内的平移/归一化指数风险，阈值处连续为 0 | 0.02 |
| lane deviation | 0.5 m 死区，1.5 m 达满风险 | 0.01 |
| lane event | Broken / Solid / Curb 取单次事件最严重值 | 0.5 / 2 / 4 |

实际执行的纵向命令定义为

\[
u_t^{\mathrm{lon}}=T_t-B_t=g_d(\ell_t),
\]

因此 throttle 与 brake 的等幅变化得到完全相同的成本。传感器列表长度、重复车道 marking 或 LiDAR ray 数量不会静默放大奖励预算。

## 4. 参数校准方法

参数不是通过观察新 pilot 后反复试错确定，而是先在五类 scripted trajectory 上冻结约束：

1. `stopped`：完成度始终为 0、控制不变；
2. `smooth-forward`：100 步内平滑达到 80% 完成度；
3. `oscillatory`：与 smooth-forward 具有相同完成度，但纵向与转向逐步换向；
4. `collision`：达到 80% 完成度后发生碰撞；
5. `success`：100 步内平滑完成并成功。

在 \(\gamma=0.997\) 下，默认预算得到：

| 轨迹 | 折扣回报 |
|---|---:|
| success | 14.8320 |
| smooth-forward | 5.9239 |
| oscillatory | 5.0588 |
| stopped | 0.0000 |
| collision | -8.9304 |

这满足预注册排序

\[
G_{success}>G_{smooth}>G_{stopped}>G_{collision},
\]

以及同进度下

\[
G_{smooth}>G_{oscillatory}.
\]

核心 route、success、collision 和 smoothness 权重独立变化 ±25% 时，上述排序仍必须成立。对于 250 步完成一条约 100 m 路线的合理驾驶轨迹，progress 折扣预算为 4.7183；同一时间窗内任意单个稠密成本即使每步满额，其最大预算为 0.8803–3.5211，不能单独压过 progress。

## 5. 工程与协议边界

- CARLA-independent 数学集中在 `environment/base_reward_v3.py`，环境只负责读取物理量和传感器事件。
- reward v3 仅允许无对抗基础策略；所有对抗训练仍显式使用历史 reward v2，避免改变蓝车奖励语义。
- 正式训练契约为 `P0_BASE_MAPPO_TOWN02_REWARD_V3`，只允许 fresh seed 42；R0/R1 checkpoint 不得正式 resume/pretrained。
- C0 v3 同时验证 reward v3 分量、诊断、二维策略动作和三维 CARLA 执行动作；C0 v1/v2 只读历史证据仍可严格验证。
- metrics schema 嵌入完整 reward protocol 和参数，训练代码指纹包含 reward v3 源文件。
- R2 不修改 AgentConditionedCritic；value 拟合与 normalization 属于 R3。

## 6. 验收标准与局限

| 编号 | R2 验收标准 |
|---|---|
| B1 数学 | completion、势能望远镜、终局互斥和所有辅助成本边界均可由无 CARLA 测试重算 |
| B2 排序 | 五类轨迹排序、任意完成度碰撞低于停车、±25% 敏感性全部通过 |
| B3 防投机 | 起点停车、前进—后退循环、近终点拖延、横向速度和传感器数量均不能刷正回报 |
| B4 对称与可解释 | 油门/刹车变化成本对称；`longitudinal_rate` 不冒充物理 jerk；每个分量均有单位、归一化和预算说明 |
| B5 可追溯 | reward v3 训练/C0 契约、指标 schema、源码指纹、文档与全量无 CARLA 回归一致 |

局限包括：当前 completion 使用 Town02 直道路段上的目标欧氏距离；扩展到曲线道路时应改为 route arc-length。LiDAR/TTC 是可学习的风险近似，不构成形式化安全保证。离线排序只证明 reward 的数学偏好，不证明 Actor 一定学到该偏好。

R3 阶段在用户启动的 CARLA 0.9.16 服务上补做了固定 Town02 脚本诊断：stopped 两车折扣回报均为 0；smooth 两车成功回报为 13.9143/14.9965；受控追尾为 -15.8667/-18.1656；所有 active transition 奖励分量守恒。该结果验证真实传感器/动力学信号链，但仍不是训练后策略性能证据。完整报告与边界见 [R3 文档](./R3_Critic价值归一化_论文正文与真实CARLA验证.md)。R4 和 R5 仍分别负责早期行为门槛与最终入口 smoke。

## 0. 一句话结论

这 10 轮 PSRO **实际未学到任何东西**：蓝车从第 1 步起就 100% 撞车、回合在 ~3 秒内被碰撞
终止，红车永远到不了终点，于是收益矩阵处处 = 1.0、元策略 σ 始终停在均匀分布。**PSRO 外层
完全空转**，等价于"用同一个退化信号独立训了 10 个会自杀的蓝队"。问题不在 PSRO 代码本身，
而在**底层对抗任务设定（生成几何 + 碰撞即终止 + 奖励配比）使 payoff 信号饱和**。

## 2. 根因链（自底向上）

1. **生成几何过挤**：`scenario_01_basic` 红车 y=176 / 210（相隔 34m），蓝车被
   `make_adversarial_positions` 自动塞在中间（y≈189、197）。Town02 为**单车道**，4 辆车
   （每辆 ~4.7m）首尾仅余 3–8m 间隙。单车道上"挡住前车" ≈ "被追尾"。
2. → **蓝车一启动就撞**（初始策略 = 自然驾驶克隆，置入夹缝立即追尾/被追尾；
   `blue_collision` 首个 update = 1.0）。
3. → **碰撞立即终止整个回合**（env "任一严重碰撞即结束"），回合死在 ~30 步，红车摸不到终点。
4. → **`coop_success ≡ 0` → `adv_eff ≡ 1.0`，所有格子相同**。
5. → **收益矩阵零方差，PRD 无梯度 → σ 永远均匀 → PSRO 外层空转**；JPC/泛化指标全部饱和。
6. 旁证：`reward_threat≈0` 表明即便不撞，也几乎无正向"威胁"奖励把策略拉向真实挡道，
   优化目标实际退化成"别撞（但撞不可避免）"。

> 次要因素：此前把 `--init-log-std` 修成生效（std≈0.6 初始探索），在夹缝里可能**加剧**早期
> 乱撞。主因仍是几何 + 终止；夹缝里可试 `--init-log-std -1.0`（std≈0.37）。

## 3. 当前问题清单（按严重度）

1. **【致命】payoff 信号饱和 → PSRO 退化为空转**。外层循环 / 元策略 / JPC 全建立在"收益有
   区分度"之上，本次收益处处 = 1。**修好它之前，跑多少轮 PSRO 都无意义。**
2. **【根因】蓝车靠"瞬间自杀式撞车"取胜**，违背"可泛化、协同、**不自毁**"的设计目标；
   自适应自碰惩罚饱和无效。
3. **【机制】单车道夹缝生成 + 碰撞即终止**，使"无碰撞挡道"几乎物理不可行，红车也没机会跑完。
4. **【信号】正向威胁奖励量级太小（~0.02）**，缺少把策略推向"真实逼停"的梯度。
5. **【次要·指标】**10 轮里内联 JPC 只在 iter 2 算了一次；最终 3×10 非方阵 → R_- NaN
   （本就预期，看泛化段；但泛化段同样因饱和无信息）。

## 4. 下一步：先做基线判定（本次新增工具）

**核心待判定**：coop_success≡0 到底是
(A) **红车基础策略不足/几何过挤**（红车在 4 车自然车流下本就过不去），还是
(B) **对抗蓝车收敛到自杀式局部最优**（红车本能过，是被蓝车撞停的）。

为此新增 **`training/psro/baseline_eval.py`**：把蓝车换成**良性驾驶**（不再对抗），
在同一 4 车场景里评估每个 RED 的 `coop_success / coop_collision / blue_collision / ep_len`：

```bash
python -m training.psro.baseline_eval \
    --red-pool-dir logs/red_pool/ckpts \
    --scenario scenario_01_basic.json \
    --blue-mode natural \
    --n-eval 5 \
    --output-dir logs/psro_runs/baseline_$(date +%Y%m%d)
```

`--blue-mode`：
- `natural`（默认）：蓝车用 RED 的合作驾驶策略开向终点 = 4 车自然车流。**这是判定 A/B 的关键。**
- `stationary`：蓝车刹停（纯几何堵塞参照，单车道下必堵，用于对照）。
- `passive`：蓝车恒定小油门直行（无目标）。

**判读规则**（脚本会自动打印 verdict）：

| natural 模式下 | 结论 | 处置方向 |
|---|---|---|
| `coop_success` 高（≥0.6） | **(B)** 几何/红车 OK，问题在对抗蓝车自杀式局部最优 | 改奖励/终止/几何，让"无碰撞挡道"成为可行最优；抬 `--threat-coef`、提高 `--self-collision-coef-init` |
| `coop_success` 低 且 `coop_collision` 高 | **(A)** 红车自然车流下就大量碰撞（不会跟车/避让）或生成过挤 | 先修红车基础策略 / 拉开生成间距（已新增 `--adv-min-gap`，见 §6） |
| `coop_success` 低 且 `coop_collision` 低（红车不撞但到不了） | **(A’)** 终点判定 / 距离过远 / 被前车堵 | 检查 `goal_zone` 与车间距、`max_steps` |

> 备注：`stationary` 在单车道上必然堵住后方红车，不能用来判 A/B（会把几何与挡道混淆）；
> 判定务必看 **`natural`** 模式。

## 6. 修改记录：拉开生成间距（2026-06-22 晚）

**问题**：`scenario_01_basic` 红车 y=176/210（span 34m），蓝车被自动塞在中间（y≈189/197），
4 车挤在单车道 34m 内，中间车距仅 ~8m（去掉 4.7m 车长仅剩 ~3.3m），一启动就追尾。

**修改**：给 `make_adversarial_positions` 增加 **`min_gap`（最小纵向间距，米）** 参数（默认 0=不改
旧行为）。`min_gap>0` 且恰好 2 红车时启用「等间距铺开」：**最前红车锚定不动**，整列沿车道
**向后**等间距展开，保证相邻间距 ≥ `min_gap`（不足则把队尾红车后挪），仍满足「蓝车不超过最前
红车」不变式。

经 `prepare_eval_scenario` 透传，并在 **`psro_runner` / `jpc_eval` / `baseline_eval`** 增加
`--adv-min-gap`（**默认 14.0**，三者须一致；训练与评估用不同 gap 会让 payoff 失真）。

**数值验证**（纯函数，scenario_01）：

| `--adv-min-gap` | 4 车 y 坐标 | 相邻间距 | 队尾红车 y | 不变式/在路 |
|---|---|---|---|---|
| 0（旧） | 176 / 189 / 197 / 210 | 13 / **7.9** / 13 | 176 | OK（但中间过近） |
| 14（新默认） | **168 / 182 / 196 / 210** | 14 / 14 / 14 | 168 | 蓝车不超前✓、≥160 在路✓ |
| 16 | 162 / 178 / 194 / 210 | 16 / 16 / 16 | 162 | 临界（队尾接近后界 160） |

> 14m 间距 ≈ 9.3m 车头距，给「无碰撞跟车/挡道」留出物理空间；最前红车始终在 y=210
> （距终点 264 仍 54m）。建议 `--adv-min-gap` ≤ 16（Town02 默认终点场景，直道后界约 y=160）。
> 旧紧凑布局仍可用 `--adv-min-gap 0` 复现。这是**几何修复**，与"蓝车自杀"是否为局部最优正交——
> 仍需先跑 baseline 判定 A/B；若是 (A)-过挤，本修复直接缓解。

## 7. baseline 判定结果 + 根因定位（2026-06-23）

跑了 `baseline_eval --blue-mode natural --adv-min-gap 14`（蓝车=红车自己的合作策略，4 车自然车流），
结果 **`logs/psro_runs/baseline_gap14/baseline_natural.json`**。脚本聚合 verdict 给的是 (A)，但
**逐 RED 拆开才是真相**：

| RED | coop_success | coop_collision | blue_collision | ep_len | 解读 |
|---|---|---|---|---|---|
| **A0608** | **0%** | 100% | 0% | **30** | 策略**坏**：无对抗车，自己 30 步内就撞 |
| **A0610** | 20% | 80% | 80% | 331 | 策略**勉强**：多数撞，偶尔成功 |
| **A0617** | **100%** | 0% | 0% | **827** | 策略**好**：4 车自然车流一路到终点，零碰撞 |

### 三条独立根因（按重要性）

**① 间距修复已生效，几何不再是瓶颈。** A0617 在 gap=14 的 4 车单车道里 100% 到终点、零碰撞 →
合格策略能跑通。**几何项可划掉。**

**② RED 池质量参差，3 个里 2 个不合格。** A0608(0%)、A0610(20%) 在**没有对抗车**时就撞——它们
在 2 车干净世界训练、从没学过跟车，放进 4 车车队就追尾。放进池里 → 2/3 的 payoff 行恒为 0，污染元博弈。

**③【最致命】"自杀"是 PSRO 的统治性策略，根在环境终止规则。**
[`carla_multi_agent_env.py:1700-1711`](../environment/carla_multi_agent_env.py#L1700) 里：**任一 agent
严重碰撞 → 把所有 agent 的 done 置 True（全局终止）**。把它和 baseline 对上：
- A0617 在干净车流里要 **827 步**才到终点（红车开得极慢）；
- 对抗蓝车 **~35 步**就把自己撞了；
- 任一碰撞→全局终止 → 蓝车一自杀，回合在第 35 步结束，A0617 的 827 步旅程被腰斩 → coop_success=0。

→ **即便满分红车，只要蓝车自杀就被判 0**；"自杀"零成本稳定剥夺红车成功 → 这就是 payoff 处处=1.0、
10/20 轮都纹丝不动、σ_red 永远均匀的根本原因。**与训练轮次无关**（20×50 轮、8h 仍全 0 已证）。

### 待实现的关键修改（修改 1）

**对抗车自撞 → 不全局终止回合**：把"任一碰撞即结束"改成"**仅合作车(红)碰撞 / 全员到达 /
超时**才结束"；对抗车(蓝)自撞 → 只 despawn 那辆蓝车，红车继续。建议加 env 构造参数
`adversary_collision_ends_episode=True`（默认保旧行为），PSRO/baseline 路径传 `False`。
效果：蓝车自杀=自废武功（收益归零）→ 消除统治策略 → `coop_success` 重新有区分度 → **payoff 去饱和**。
这是当前唯一能根治 payoff 饱和的改动。

## 8. 修改记录：修改 1 —— 对抗车自撞不全局终止（2026-06-23 晚，已实现）

**目的**：消除 §7 根因③——蓝车自杀=零成本终止回合、稳定剥夺红车成功，导致 payoff 处处饱和。

### 改了什么（5 处）

| 文件 | 改动 |
|---|---|
| `environment/carla_multi_agent_env.py` | ① 构造参数 `adversary_collision_ends_episode=True`（默认保旧行为）。② `_check_dones` 全局终止判定：该参数为 `False` 时，**仅合作车(红)严重碰撞**触发全局终止（蓝车自撞不触发；其自身 `done/terminated` 仍逐 agent 置位）。③ `step()` 在 `info` 记录完本步 collisions/terminated **之后**，把撞毁的对抗车 **despawn**（复用 `_despawn_reached_vehicle`，不标记 reached_target），避免残骸停在单车道变"自杀路障"。 |
| `training/psro/train_blue_oracle.py` | rollout 加 **death-masking**：`blue_done/red_done` 逐 agent 追踪，已终止的车不再采样（不记零观测假 transition）；收尾条件改为「**红车全终止 或 蓝车全终止**」（旧 env 行为下与原 `all(dones)` 等价）。 |
| `training/psro/jpc_eval.py`（`evaluate_pair`） | 同 death-masking；收尾改为「**红车全终止**」（eval 必须让红车跑到底以量 coop_success）。 |
| `training/psro/baseline_eval.py` | 同上。 |
| `psro_runner / jpc_eval / baseline_eval` | env 创建传 `adversary_collision_ends_episode=args.…`，并加 CLI `--adversary-collision-ends-episode`（**默认 False=新行为**，加开关恢复旧行为做消融）。 |

### 关键正确性论证（梯度/奖励不受损）

- **撞毁那步的奖励照常**：`step()` 先 `_compute_rewards`（含碰撞罚）→ 再 `info`（记 collisions/terminated）→ **最后才 despawn**，故蓝车撞毁的 reward 与 `collision_sticky`/`terminated` 都被正确捕获。
- **GAE 终止正确**：撞毁步 `terminated=True` → `mask_value=1-terminated=0`，value bootstrap 被乘零，**无论 episode-bootstrap 给 None 还是 last_gs 都不影响**结果。蓝车自身死亡的价值/梯度与旧实现一致。
- **自适应自碰 PID-I 不受影响**：`win_blue_collision` 仍由 `collision_sticky` 准确统计（despawn 在 info 之后）。
- **激励方向被纠正**：蓝车不再能靠自杀免费终止回合；**不撞地持续挡道**才能累积更多 threat 步、且无撞毁罚 → return 更高。
- **死后无悬空轨迹**：death-mask 后蓝车一旦 done 即停止采样，其轨迹在撞毁步终止，不会产生零观测假样本。

### 仍存的设计局限（非本次范围）

蓝车每步训练奖励是 **threat 代理量**，并不直接含「红车是否被拦下(coop_success)」——后者只进 payoff/eval。
若 threat 与真实拦截相关性不足，会有 train/eval 口径错配。可选增强：给蓝车加**终局奖励**（红车超时/未到→+R，红车到点→−R）把目标写进梯度。留待后续。

### 9.2 暴露的新问题：对抗车仍"靠撞取胜"

能赢的红车（RED1/2/3）`coop_collision ≈ blue_collision ≈ 0.8~1.0` —— **红蓝一起撞**：蓝车贴脸硬挡 →
红车（2 车世界训出、不会跟车刹车）追尾 → 红车碰撞结束回合。蓝车自己也撞毁，**违背"不自毁"目标**。

根因：旧 `threat = exp(−TTC/τ)` 在 **TTC→0（即将相撞）时最大** → 直接奖励"贴到撞距离"。训练时
`self_collision_coef` 顶到上限 10 仍压不住（`threat_coef=2.0` 太强）。另：σ_red→0.88 集中在打不动的
RED0，下一个蓝 oracle 对它学成消极策略（threat 0.20、不撞、啥也没干成）。

### 9.3 优化 A：把"奖励贴脸即撞"改成"奖励安全距离逼停"

**威胁奖励重塑**（`train_multi_adversarial_kl_risk.py: compute_blue_threat_scores`）：

```
威胁分 = band_kernel(纵向距离) × impede(红车被压慢的程度)
```
- `band_kernel`：[threat_near, threat_radius] 内的钟形核，峰在安全甜点 d_peak≈threat_near+0.3·跨度；
  **纵向 < threat_near（撞距离）直接 0 分** → 怼上去不再有正回报（撞了还吃自碰罚）。
- `impede = clamp((red_desired_speed − 红车前向速度)/red_desired_speed, 0, 1)`：红车被压得越慢越高，
  自由巡航≈0 → 奖励"**持续把红车压慢**"而非"逼近瞬间"，对齐"拦住红车"。

**核数值验证**（纯函数）：撞距离1.5m→0；安全甜点6.6m(红车慢)→0.875；带边12m→0.50；带内但红车满速→0；
红车半速→0.50；太远16m→0。✅ 符合预期。

**默认值调整**（`psro_runner`）：`--threat-coef` 2.0→**1.0**；`--target-blue-collision-rate` 0.05→**0.03**；
新增 `--self-collision-coef-max`（默认 **20**，was 10）、`--threat-near`（默认 **3.0m**）。
经 `_build_inner_args` / `evaluate_pair` 透传到训练与评估（eval 威胁指标用同形状，口径一致）。

**改动文件**：`compute_blue_threat_scores`（重塑+新参数）、`train_blue_oracle`（传 threat_near、自碰罚上限参数化）、
`jpc_eval`（evaluate_pair 加 threat_near + CLI）、`psro_runner`（默认值+CLI+inner 透传）。5 文件 `py_compile`+import 通过。

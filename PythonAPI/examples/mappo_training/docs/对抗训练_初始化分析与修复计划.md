## 1. 场景初始化时序（事实陈述）

```
[Env 构造时] _find_straight_road
    └─ 按 cooperative/adversarial 分配 waypoint，存 start_waypoints / target_waypoints
       self.goal_zone = None（初始）

[训练脚本启动]
    ├─ curriculum = CurriculumLearning(scenario_dir=...)
    │     dist_NNm 文件 → 3 stage（30m | 30+50m | 全部 + 其他）
    └─ 读 coop_start_config (默认 scenario_03_far.json)
          coop_start_positions = {agent0: y=160, agent1: y=220}

[每个 episode]
    scenario_config = load_scenario_by_name(scenario_name)
        ↓
    coop_start_positions != None ?
        agents = _scenario_agents(scenario_config)
        agents.update(coop_start_positions)        ← 覆盖红车 = y=160/220
        scenario_config["agents"] = agents
        ↓
    auto_adv_positions == True ?
        make_adversarial_positions()                ← 蓝车均匀夹中
        默认布局：red[160] - blue[180] - blue[200] - red[220]
        ↓
    env.set_scenario(scenario_config)
        → apply_scenario_config:
            ① if "goal_zone" in config:
                  set_goal_zone(...)
               else:
                  self.goal_zone 静默保持上次值！
            ② set_custom_start_positions(agents)
        ↓
    env.reset() → _spawn_vehicles() → 在 custom_start_transforms 位置生成车辆
```

## 2. 问题清单

### 🔴 P0-1 — dist_NNm 课程学习实质失效

| 场景文件 | 文件中的 agent 位置 | 训练时实际位置 |
|---|---|---|
| scenario_dist_30m.json | agent0=y234, agent1=y248 | **y=160/220**（被覆盖） |
| scenario_dist_50m.json | agent0=y214, agent1=y228 | **y=160/220**（被覆盖） |
| scenario_dist_70m.json | agent0=y194, agent1=y208 | **y=160/220**（被覆盖） |
| scenario_dist_90m.json | agent0=y174, agent1=y188 | **y=160/220**（被覆盖） |

四个 dist 文件对训练**等价**。课程 stage1（只看 30m）→ stage3（看全部）的"从易到难"梯度消失。

### 🔴 P0-2 — 无 goal_zone 场景的 goal 取决于采样顺序

含 goal_zone 的 6 个：`01_basic, 06_mixed, dist_30m/50m/70m/90m`（均设 goal y=264）。

**无** goal_zone 的 6 个：`02_close, 03_far, 04_left, 05_right, 07_v_close, 08_angle_offset`。

`apply_scenario_config` 缺 goal_zone 时**静默继承上次值**：

- 第一个 episode 采到 02_close → `self.goal_zone = None` → fallback 到 `target_waypoints[-1]`（直道末端，y 不确定）。
- 后续 episode 采到 02_close → 继承上一个采到的场景的 goal_zone（多半是 y=264）。

**后果**：同一份场景文件在不同采样顺序下，goal 不同 → 训练日志不可复现。

### 🟡 P1-3 — Blue 比 Red follower 更接近 goal

红 y=160/220，蓝 y=180/200，goal y=264：

| 角色 | 距 goal |
|---|---|
| Red follower (agent0) | 104 m |
| Blue 0 | 84 m |
| Blue 1 | 64 m |
| Red leader (agent1) | 44 m |

Blue 一旦冲到 goal → `naturally_terminal=True` → 后半 episode 完全失活。
KL anchor 又把 blue 拉向 base actor 的"向目标开"反应 → blue 会主动跑路。

### 🟡 P1-5 — `adv_success = not coop_success` 太宽

timeout / 某 red 自己撞死都算 adv 成功，即使 blue 啥都没干。
课程 weighted 采样基于此 → "对抗失败的场景上采样"逻辑被污染。

### 🟢 已正确实现（不修）

- 算法骨架（GAE / PPO / CTDE / KL anchor / 自适应惩罚）
- 训练数据流（buffer / bootstrap / per-agent advantage）
- `set_scenario → reset` 时序
- KL anchor 方向（forward KL，拉 adv 回 base）
- target_kl 早停 + self_collision_coef 时序
- 续训完整性

## 3. 车辆初始化问题的修复计划（核心）

下面专门针对 **P0-1 / P0-2 / P1-3** 给出方案。原则：**最小改动 + 显式语义 + 可复现**。

### 3.1 设计原则

1. **场景文件自描述完备**：每个 JSON 同时声明 `goal_zone` 和 `agents`，env 不再依赖"上次状态"。
2. **`coop_start_config` 改为可选**：默认 `none`，让场景自己说了算；想要"固定红车起点"是 opt-in。
3. **环境失败语义显式**：缺 goal_zone 不再静默继承，改为**显式重置回 waypoint 默认**并发警告。
4. **课程基于"距离"做真差异化**：dist_NNm 系列保留各自的红车位置，让 30m 真的是 30m。

### 3.2 三个修复

#### M1 — 场景文件 goal_zone 完备化（一次性数据迁移）

把当前缺 goal_zone 的 6 个文件全部补上 goal_zone 字段（统一 y=264），同时把扁平 `agent0/agent1` 嵌套到 `agents:{}` 下：

| 文件 | 当前格式 | 改后 |
|---|---|---|
| scenario_02_close.json | flat | `goal_zone: y=264` + nested |
| scenario_03_far.json | flat | `goal_zone: y=264` + nested |
| scenario_04_left.json | flat | `goal_zone: y=264` + nested |
| scenario_05_right.json | flat | `goal_zone: y=264` + nested |
| scenario_07_v_close.json | flat | `goal_zone: y=264` + nested |
| scenario_08_angle_offset.json | flat | `goal_zone: y=264` + nested |

`_scenario_agents` 已经兼容两种格式（兼容旧扁平），但写成 nested 更明确。
统一 y=264 与现有 `01_basic / dist_NNm` 一致，消除歧义。

迁移后 dist_30m 还需要单独调整 agent 位置以恢复课程梯度（见 M2）。

#### M2 — 课程梯度恢复（二选一）

**方案 a（推荐，最少改动）**：脚本默认不开 `coop_start_config`。

```python
# 当前默认
p.add_argument("--coop-start-config", type=str, default="scenario_03_far.json")
# 改为
p.add_argument("--coop-start-config", type=str, default="none",
               help="可选，仅当需要红车固定起点时显式传入。默认 none 让场景文件说了算。")
```

效果：
- dist_30m 红车起点保留为 y=234/248 → 距 goal 16/30m
- dist_50m 红车起点保留为 y=214/228 → 距 goal 36/50m
- dist_90m 红车起点保留为 y=174/188 → 距 goal 76/90m

课程 stage1 → stage3 真有"易→难"梯度。

**方案 b**（如果非要红车固定起点）：保留 coop_start_config，但把 dist_NNm 系列改为通过 **goal_zone y 差异化**，红车位置统一为 y=160/220：

| 文件 | 现 goal | 改后 goal | 含义 |
|---|---|---|---|
| dist_30m | y=264 | **y=190** | 红 follower y=160 → 距 30m |
| dist_50m | y=264 | **y=210** | 距 50m |
| dist_70m | y=264 | **y=230** | 距 70m |
| dist_90m | y=264 | y=250（≈90m） | 距 90m |

⚠️ 但**方案 b 有边界问题**：red leader y=220 在 dist_30m 下会 past goal（y=190）→ 直接 `reached_target=True`，episode 启动即结束。所以需要同时调红 leader 位置或接受 leader 起步即胜的语义。
**推荐方案 a**。

#### M3 — 环境侧 fail-loud（防御性修复）

[carla_multi_agent_env.py:545-547](../environment/carla_multi_agent_env.py#L545-L547) 改为：

```python
def apply_scenario_config(self, config: Dict):
    if "goal_zone" in config:
        self.set_goal_zone(config["goal_zone"])
    else:
        # 显式重置回 waypoint 默认，避免静默继承上一场景的 goal
        if self.goal_zone is not None:
            print(f"⚠️ 场景未声明 goal_zone，回退到 waypoint 默认目标（target_waypoints[-1]）。"
                  f"建议为所有场景文件补充 goal_zone 字段以保证可复现。")
        self.goal_zone = None
    # ... agents 处理同前
```

完成 M1 后这个 fallback 不会再被触发，但作为防御性设施保留，防止未来新增场景时再次踩坑。

### 3.3 P1-3（蓝车早到 goal）的处理

车辆初始化范畴内能做的：

#### M4 — `make_adversarial_positions` 加内缩比例

把 `--adv-margin-ratio` 默认从 0.0 改为 **0.15**：

- 当前 (margin=0)：blue 在 [160, 220] 均匀夹中 → y=180, 200
- margin=0.15：blue 在 [169, 211] 内夹中 → y≈183, 197

让 blue 离 leader 更远，**减缓 blue 过早冲到 goal** 的速度。但治标不治本，根本上需要在奖励 / 终止条件层面动手（属于 P1 训练设计，不在本次车辆初始化修复范围）。

#### M5（可选）— 蓝车放在 RED 队列**末尾后方**

如果"BLUE 阻挡 RED"是设计目标，蓝车应在 RED 队列**后方**才合理（蓝车追上红车队尾，给 follower 施压而不是被 leader 拉着跑）。
但 `make_adversarial_positions` 当前设计是"夹中"语义（红-蓝-蓝-红）。
改为"末尾"语义需要新增 `--adv-placement-mode {between, behind}` CLI 参数。

→ 留作后续 P1 工作，本次车辆初始化修复不动。

### 3.4 执行顺序

```
Step 1: 备份现有 6 个 flat 场景 JSON 到 docs/或临时目录
Step 2: 重写 6 个 JSON 文件 → nested 格式 + goal_zone y=264
Step 3: 修改 apply_scenario_config 加 fail-loud（M3）
Step 4: 修改 build_parser 把 --coop-start-config 默认改为 none（M2 方案 a）
Step 5: 修改 build_parser 把 --adv-margin-ratio 默认改为 0.15（M4，可选）
Step 6: sanity 运行 3 update 验证：
        - 控制台无 ⚠️ goal_zone fallback 警告
        - 控制台 "终点区域已设置: center=..." 每 episode 都打印
        - 不同 dist_NNm 场景下 avg_ep_len 应有差异
```

### 3.5 验证清单

- [ ] dist_30m 场景下 episode 平均长度 < dist_90m（短距离更快到点）

- [ ] curriculum stage1（warmup）跑 10 update 后 coop_success 显著高于 stage3

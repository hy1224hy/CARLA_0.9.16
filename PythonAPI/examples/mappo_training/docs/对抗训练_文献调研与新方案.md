# 对抗智能体训练 — 文献调研与新方案设计

## 1. 问题陈述

当前对抗训练脚本 [train_multi_adversarial_mappo_v2.py](../training/train_multi_adversarial_mappo_v2.py) 的设计意图：

> 让对抗车辆在**保持正常驾驶能力**的前提下，对合作车辆构成**真实威胁**——
> 不是自毁式撞击，而是像一个"激进但合理"的人类司机做加塞、阻挡、抢道。

现行实现以"先训基础策略 → 再叠加危险行为奖励"的两阶段思路展开，
但实际训练中遇到的核心矛盾：

- **正常驾驶奖励**（progress / success / time_bonus）和**对抗奖励**（cut_in / blocking）
  量级失衡（10–40 倍），对抗车实际学到的是"正常开车去 goal，顺路骚扰"。
- 想通过调权重平衡，往往陷入两端摆动：权重小 → 没对抗行为；权重大 → 自毁式攻击。
- 单边训练（仅 BLUE 更新，RED 冻结）导致 BLUE 过拟合到 RED 当前策略。

学界对这个问题（"plausible adversary" / "realistic adversarial driving"）有较成熟方案，本文档汇总后给出本项目的工程化改造方案。

## 2. 文献调研

### 2.1 AdvSim — Adversarial Scenarios for Self-Driving (Wang et al., ICCV 2021)

- **核心**：对真实场景中其他参与者轨迹做对抗扰动，**显式约束扰动后轨迹的运动学可行性**（最大加速度、转向率、车道一致性）。
- **关键技巧**：可行性损失项 $L_\text{feas}$ 进入总目标，违反则梯度反向。
- **借鉴**：把"是否合理"写成可微显式约束，而不是靠 reward 平衡硬调。

### 2.2 KING — Generating Safety-Critical Driving Scenarios (Hanselmann et al., ECCV 2022)

- **核心**：基于梯度的对抗场景生成，对每个对抗 actor 强加**车道一致性 + 运动学约束**。
- **关键技巧**：硬门槛 + soft penalty 双层防护，越界直接截断 episode。
- **借鉴**：把 jerk / lateral_accel / steer_rate 这些"驾驶可读性"指标设为硬门槛。

### 2.3 STRIVE — Generating Useful Accident-Prone Driving Scenarios (Rempe et al., CVPR 2022)

- **核心**：**预训练一个"正常交通行为先验"（VAE 编码）**，在它的潜空间里搜索对抗扰动，
  强制对抗行为落在"真人会做"的分布内。
- **关键技巧**：对抗采样限制在 prior 的 ε-ball 内。
- **借鉴**：合作策略本身就是"正常驾驶 prior"，可以直接拿来做 anchor —— **KL(adversary ‖ base) 正则项**就是这个思想的简化版。

### 2.4 CAT — Closed-loop Adversarial Training (Zhang et al., NeurIPS 2023)

- **核心**：在线生成对抗交通参与者训练 ego，对抗行为强制"可解释 + 物理合理"，整体跑 co-evolution loop。
- **关键技巧**：交替更新对抗者与防守者，避免单边过拟合。
- **借鉴**：要让 RED 也变鲁棒，必须接一个交替训练调度器（本项目当前缺失）。

### 2.5 RARL — Robust Adversarial Reinforcement Learning (Pinto et al., ICML 2017)

- **核心**：双 agent 零和博弈，但对手只能扰动**受限的控制噪声**，protagonist 在最坏情况下学鲁棒策略。
- **关键技巧**：显式限制对抗自由度（不是任意改全部 action，而是有界扰动）。
- **借鉴**：限制对抗动作的"可达范围"是防止自毁的最简单办法。

### 2.6 Constrained Policy Optimization 系列

- **CPO** (Achiam et al., ICML 2017)
- **PID-Lagrangian** (Stooke et al., ICML 2020)

- **核心**：约束 RL —— 最大化主目标，subject to 安全约束。Lagrange 乘子自动调节。
- **关键技巧**：

  $$\max E\!\left[\sum_t \gamma^t r_\text{attack}\right] \quad \text{s.t.}\ E[\text{collision\_rate}_\text{blue}] \le \varepsilon$$

- **借鉴**：把"BLUE 不能撞自己"写成硬约束，比手调 collision_penalty 数学上更合理。

### 2.7 Causal Influence Reward (Jaques et al., ICML 2019)

- **核心**：多智能体中，对 agent 行为的奖励应该归因于"如果它不存在，结果是否不同"。
- **关键技巧**：counterfactual baseline。
- **借鉴**：奖励应该是"BLUE 出现导致 RED 风险上升"的部分，而不是 BLUE 单纯的几何位置。

### 2.8 IL + RL 微调（Robustifying Imitation, Lu et al., Waymo 2023）

- **核心**：先 BC 模仿正常驾驶，再用 RL 微调时通过 KL 约束保持"像人"。
- **关键技巧**：BC loss 权重随训练线性衰减。
- **借鉴**：BC warm-up + KL 锚定是 Waymo 用在生产系统的标准配方，可直接照搬。

### 2.9 综述（推荐阅读）

- Ding et al., *"A Survey on Safety-Critical Driving Scenario Generation"*, T-ITS 2023
- Deng et al., *"Adversarial Attacks and Defenses in Deep Learning for Autonomous Driving"*, 2024

## 3. 综合设计：KL-anchored + 风险增量奖励

把上面 7 条主流方法的"最小公倍数"提炼出来，得到三件套：

### 3.1 KL-anchored Policy（来自 STRIVE / Waymo IL+RL / RARL）

在每次 PPO 更新中，actor loss 加一项 KL 锚定到**预训练正常驾驶策略**：

```
total_loss = ppo_loss − ent_coef · entropy + β_KL · KL(π_adv ‖ π_base_frozen)
```

其中 `π_base_frozen` 是预训练 checkpoint 的 actor，在训练全程冻结。

- **β_KL 含义**：允许对抗策略偏离正常驾驶的"距离"。
  - β_KL 大（如 0.5） → 行为更像正常司机，对抗效果弱
  - β_KL 小（如 0.01） → 偏离自由度大，可能向激进/自毁演化
  - 推荐起步值：**0.1**，根据 `coop_collision_rate` 是否过高再调

- **数学形式**（pre-tanh 对角 Gaussian 间的 KL）：

  $$\mathrm{KL}(p \| q) = \sum_i \left[ \log\frac{\sigma_{q,i}}{\sigma_{p,i}} + \frac{\sigma_{p,i}^2 + (\mu_{p,i}-\mu_{q,i})^2}{2\sigma_{q,i}^2} - \frac{1}{2} \right]$$

- **梯度路径**：β_KL · KL 项对 adv actor 的 μ / log_std 都有梯度，自然把策略拉回 anchor。

### 3.2 风险增量奖励（来自 AdvSim / Causal Influence）

替换原 `cut_in / blocking` 几何奖励（位置奖励）为**因果归因的风险奖励**：

对每对 (BLUE, RED) 在每步计算 RED 受 BLUE 威胁的程度，
具体用 RED 视角的 TTC 衰减表达：

```python
# blue 在 red 前方威胁窗口内，且 red 追上 blue
if blue_ahead_of_red and lateral_in_window:
    closing_speed = red_forward_speed − blue_forward_speed
    if closing_speed > 0.1:
        ttc_red_to_blue = longitudinal_dist / closing_speed
        threat = exp(−ttc / τ)           # τ ≈ 1.5s，越临近越大
        blue_threat_score += threat
```

每个 BLUE 当步奖励 = sum over reds of threat exerted。

- **为什么是"RED 视角的 TTC"而不是"BLUE 视角"**：
  因果归因——我们要奖励的是"BLUE 让 RED 觉得险"，不是"BLUE 自己觉得险"。
- **为什么是 exp(−ttc) 而不是 1/ttc**：
  exp 形式在 ttc→0 时不会爆炸，TD3/SAC 数值更稳。
- **为什么用 closing_speed > 0 才发**：
  blue 比 red 快 / 同速 = blue 在跑路，不构成威胁，避免奖励"溜走"。

### 3.3 自碰撞约束（来自 CPO / PID-Lagrangian, 简化版）

不上完整 CPO（实现代价高），用**自适应 collision penalty**做简化：

```python
# 每个 update 收完一轮后：
blue_collision_rate = mean(blue_collided_in_episode)
if blue_collision_rate > epsilon:
    self_collision_coef *= 1.2     # 撞太多 → 加大自惩
else:
    self_collision_coef *= 0.95    # 撞得少 → 适度放松
self_collision_coef = clip(self_collision_coef, 0.1, 10.0)
```

这是 PID-Lagrangian 的极简版（只有 I 项），实现成本约 10 行代码。

### 3.4 总奖励函数

```
r_blue(t) = base_driving_safe(t)              # 仅速度/居中/jerk/lane等"安全驾驶"项，剔除 progress/success
          + α · threat_reward(t)              # 风险增量（3.2）
          − self_collision_coef · collision(t) # 自碰撞惩罚（3.3 自适应）
          + zero_sum_coef · (−avg_coop_r)     # 可选保留（已有）
```

其中 `base_driving_safe` 不含 progress/success/time_bonus —— 这些项是"推 BLUE 去 goal"的，与对抗目标冲突。

## 4. 与现有 v2 脚本的差异

| 模块 | v2（现行） | 新方案 |
|---|---|---|
| 对抗奖励 | cut_in/blocking 位置奖励 | RED 视角 TTC 风险增量 |
| base_driving | 含 progress×0.3, success×0.3, time_bonus×0.3 | 剔除目标导向项，仅保留"安全驾驶" |
| KL 正则 | 无 | 锚定预训练 actor，β_KL 可调 |
| 自碰撞 | 固定 collision_penalty | 自适应（PID-Lagrangian 简版） |
| 零和项 | zero_sum_coef × (−avg_coop) | 同左（可选保留） |
| 学习目标 | "最大化对抗奖励 + 零和" | "最大化对 RED 的威胁，subject to 像正常驾驶 + 不自毁" |

## 5. 实现路径

新文件 [train_multi_adversarial_kl_risk.py](../training/train_multi_adversarial_kl_risk.py)：

- 复用 v2 的 `RolloutBuffer / CurriculumLearning / compute_gae* / sample_scenarios_stratified` 等
- 新增模块：
  - `compute_blue_threat_scores()`：每步算每个 BLUE 对 RED 的威胁
  - `gaussian_kl_diag()`：对角高斯 KL
  - 训练循环中：
    - 创建 `base_actors_frozen`（deepcopy 自预训练 actor）
    - 奖励组装：base_safe + α·threat − coef·collision + zero_sum
    - actor loss 加 KL 项
    - 每 update 末更新 `self_collision_coef`

新 CLI 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--beta-kl` | 0.1 | KL 锚定权重 |
| `--threat-coef` | 2.0 | 风险增量奖励权重 |
| `--threat-radius` | 15.0 | 威胁判定纵向距离上限（米） |
| `--threat-lateral` | 2.5 | 威胁判定横向窗口（米） |
| `--threat-tau` | 1.5 | TTC exp 衰减常数（秒） |
| `--target-blue-collision-rate` | 0.05 | 自适应碰撞惩罚的目标值 ε |
| `--self-collision-coef-init` | 1.0 | 自适应惩罚初始值 |
| `--use-base-driving-clean` | True | 用"剔除目标导向项"的 base 奖励 |
| `--zero-sum-coef` | 0.0 | 默认关掉零和项（KL 锚定+风险奖励已足够） |

## 6. 验证 / 验收指标

跑 30 update sanity，TensorBoard 上看：

- `blue/threat_reward_per_step` 单调上升（BLUE 学到威胁 RED）
- `blue/collision_rate_window < 0.15`（不自毁）
- `coop/rate_success_window` 缓慢下降（攻击有效）
- `ppo/kl_to_base_anchor` 稳定（不应炸）— **0.05~0.3** 区间合理
- `blue/self_collision_coef` 缓慢调整，最终稳定在 0.5~3.0

如果 `blue/threat_reward` 不上升 → 调小 β_KL（锚定太紧）或调大 threat_coef。
如果 `blue/collision_rate` 失控 → 调大 `target-blue-collision-rate` 的目标值 ε 或初始 `self-collision-coef`。

## 7. 后续可选扩展

- **完整 CPO**：替换简版 PID 为正式 Lagrangian PPO（参考 [omnisafe](https://github.com/PKU-Alignment/omnisafe) 实现）
- **Co-evolution 调度**：交替训练 RED（用 BLUE best.pt 当 frozen 对抗）和 BLUE
- **多步威胁累积**：threat 用 n-step return 而不是单步，加强信号
- **风险增量 + 反事实**：估计"if BLUE not present, RED 还会不会有这个风险"，做 causal influence 真正归因

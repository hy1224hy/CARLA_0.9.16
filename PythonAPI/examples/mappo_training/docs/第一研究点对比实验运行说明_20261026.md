# 第一研究点：直接运行的对比实验代码

2026-10-26。工作分支 `codex/mappo-experiment-baseline`。本版本复用现有MAPPO/IPPO、A/B学习器与完整边界恢复，只补实验所缺链路。没有训练通信，没有新增信用估计网络。原训练默认入口及旧奖励配置继续可用，新实验显式选择新协议。

## 已有链路与本轮补齐

| 环节 | 实现 |
|---|---|
| 原驾驶资格 | 复用 `evaluation.evaluate_base_driving_vnext` 的静止/滚动、逐车/方向/角色资格，补输出物理加速度/jerk与实际控制测量 |
| 对抗前检查 | C0无蓝、C1普通冻结蓝交通，输出四车任务的驾驶指标和分层表 |
| 小规模场景 | 训练24例：基础池滚动、四方向、并排/±8m错位、完整编号对；8例并排可单独准备 |
| 独立评估划分 | gate/selection/test各16例，完整编号对，固定留出蓝红距离；不是192例网格 |
| 攻击奖励 | `c1_progress_team_v1`：共享C1参考进度效用、小权重蓝方进度、安全与风险成本 |
| 信用与生命周期 | 退场后真实团队回报折算到最后一个有效动作，不补造失活动作 |
| 方法 | MAPPO、IPPO、B0、B1、B2及已有门控控制组，配置由同一入口生成 |
| 公平预算 | A+B合计实际训练ticks，完整边界软上限，记录验证、重置、总成本 |
| 选模 | 仅selection；先安全筛选，再按安全合格效率效用；test不选模 |
| 协同解释 | 四车保持不变的00/10/01/11冻结策略组合，输出两蓝贡献与交互项 |
| 结果 | 每个独立run/outer seed一行CSV、组均值/标准差、实际成本与弱红标签 |

新增专项测试集中在一个文件，没有另写大套校验程序。测试覆盖实际奖励组合、持续反馈、退场回报、负贡献、场景几何，以及真实PPO到冻结评估的合成环境闭环。

## 准备正式比较配置，不启动仿真

```powershell
# 五组算法/组件比较 × 三个外层seed；目录应是新的
python -m utils.run_first_point_experiments prepare --output experiments/first_point_comparisons --red-checkpoint logs/BD_vNext_V6_scratch_s42_u600_20261020_v1/periodic/ckpt_update_000370.pt --suite comparisons --seeds 42 43 44 --train-ticks 120000 --device cuda
```

`suite=core`只生成B0/B1/B2；`comparisons`增加标准单团队MAPPO与严格局部Value的IPPO；`controls`是原有随机/等强度诊断。训练ticks是可调候选预算，不表示一定收敛；正式运行前统一确定，不能运行后给某组单独加预算。

只做并排小闭环时，用新的实验目录并加 `--scene-stage parallel`，训练池即8例。完整并排/错位主实验使用默认 `full` 的24例。不要改运行中已有实验清单。

## 一条链运行

```powershell
# 自动做基础资格、C0/C1、准备正常参考、训练全部组、选模、测试及贡献评估
python -m utils.run_first_point_experiments run --experiment experiments/first_point_comparisons --with-credit
```

基础资格使用原32例验证配置和两个注册seed；几何报告默认寻找现存 `diagnostics/base_driving_vnext_20261020/preflight_validation_live.json`。在另一台机器须传入其已有基础场景预检报告：

```powershell
python -m utils.run_first_point_experiments run --experiment experiments/first_point_comparisons --geometry-report <基础验证池预检报告.json> --with-credit
```

已有 `utils.preflight_base_driving_scenarios_v1` 负责这份报告，本轮没有再造校验工具。历史checkpoint若不满足当前基础协议，不应强行当作通过新资格；先使用匹配的checkpoint/已有参考评估接口。

只有基础资格和注册C0/C1条件通过，正常模式才进入训练。若明确研究弱红方的工程/诊断对照，可显式选择：

```powershell
python -m utils.run_first_point_experiments run --experiment experiments/first_point_v1 --allow-weak-red --with-credit
```

这条命令会执行真实仿真和训练。弱红模式不伪造资格，参考与比较表会标为diagnostic；可以比较该弱基线上的相对变化，但不能说是合格正常红方上的攻击泛化证据。

## 分阶段与恢复

```powershell
# 完整基础资格；同时输出舒适性等补充测量
python -m utils.run_first_point_experiments base-eval --experiment experiments/first_point_v1

# 只做小场景C0/C1，不训练
python -m utils.run_first_point_experiments red-eval --experiment experiments/first_point_v1

# 准备train/gate/selection普通交通参考；失败普通驾驶不自动当合格参考
python -m utils.run_first_point_experiments references --experiment experiments/first_point_v1 --allow-weak-red

# 先检查B0第一个完整A+B边界
python -m utils.run_first_point_experiments train --experiment experiments/first_point_v1 --groups B0 --stop-round 1

# 同一配置完整恢复，直到共同训练tick预算
python -m utils.run_first_point_experiments train --experiment experiments/first_point_v1 --groups B0 --resume

# 独立selection、冻结导出、test和四组合；可筛选组/seed
python -m utils.run_first_point_experiments evaluate --experiment experiments/first_point_v1 --groups B0 --allow-weak-red --with-credit

# 不连接CARLA，重新汇总已有结果
python -m utils.run_first_point_experiments summarize --experiment experiments/first_point_v1
```

整个链恢复用 `run --resume`。已完成且身份相同的引用/评估复用，失败评估保留并创建retry目录。训练只从完整A+B边界恢复，丢弃的部分轮仍进入实际成本。修改模型、奖励、清单或预算后应建立新实验，不冒充同身份续训。

普通C1参考按case绑定红方/任务身份和曲线SHA；训练断点绑定train/gate参考。test参考在冻结选模之后才准备，训练更新不读取test案例。参考重复次数改变需新版本，不能覆盖已有训练依据。

## 奖励与门控的实际版本

每个固定模板先记录普通C1的道路切向归一化进度曲线。主项为红方相对该曲线的有符号进度落后，按统一时域归一化。出生保护期不发攻击信用；红更快会扣分，持续落后不会被2秒滑窗忘记。成功完成是吸收任务状态，提前完成的已知参考尾项结算在终止奖励，不补物理帧。

共享团队奖励：`10*attack + team_progress - risk - comfort - team_event_cost`。事件成本采用每回合每类别的首次团队事件，避免持续标志和双车传感器重复；接触/越界/道路违规50，任务违约20。原+5事件、距离威胁和+15超时只留作诊断，不再进入新profile的训练reward。

蓝车自身到达后不再有大额成功奖。动作mask仍真实失活；后续团队收益按gamma折算回它最后一个真实动作，因此先前有效行为仍能获得团队结果的信用。日志的`returns`是实际活动时刻奖励，`team_discounted_return`与`team_tail_credit`明确记录训练回报结算。

B2按parallel/staggered真实初态组，使用独立gate的安全合格效率均值差，候选最小差0.02；原q仍作诊断。教师b≤1/8且不高于学生、每族至少8例，冻结教师与all-valid KL分母继续沿用。新profile成本系数固定，不使用4回合粗粒度乘法lambda调度。

这套系数和阈值是共同先导候选。所有组相同，不为制造B2门控或“获胜”单独调奖励。普通MAPPO/IPPO、双独立B0、普通互学B1、选择互学B2的网络与优化器由原注册表真实切换，不只是改标签。

## 输出在哪里

- `base_screen/qualification.json`：原逐车分层资格；`driving_measurements.json`：额外物理平顺性测量。
- `red_screen/summary.json`：C0/C1完成、安全、逐车巡航/低速/横向/控制/净距/TTC/时距/加速度/jerk；`strata`按条件、任务组、方向分层。无纵向曝光的TTC保持空值。
- `references/`：普通C1曲线及来源、正常/弱基线标签。
- `runs/<组_seed>/`：真实PPO日志、gate、成本、完整断点；每个Actor仍独立保存。
- `evaluations/<组_seed_轮次>/selection/`：仅选模用，导出一个团队的 `frozen_blue_team.pt`。
- 同目录`test/`：独立C0/C1/C2；`credit/`：00/10/01/11、两车Shapley型贡献、交互项与四组均安全子集。
- `comparison.csv`、`comparison.json`：独立run结果、组均值/标准差、样本数、实际ticks与弱红状态。一个run若有多轮评估，只汇总预先规定的最新完成轮次，不按测试表现挑轮次，不把A/B算两次重复。

## 通信的后续边界

本版通信关闭且保留原20维观测/2维动作。Actor定义、TeamLearner更新和Runtime采样分别独立，后续在这些位置加入消息编码与队内交换，并为消息条件、log_prob重算和checkpoint建立新版本。不能只把配置enabled改为true或缓存旧消息，就宣称通信已训练。

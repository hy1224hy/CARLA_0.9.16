核心目标：在 CARLA Town02 直道场景下，用 MAPPO（CTDE） 训练一支合作驾驶团队，再训练一支多对抗智能体团队去攻击它，从而量化合作团队的鲁棒性短板，并验证"对抗 / 对抗数量 / 课程 "等设计对合作团队的鲁棒性的影响。

---

## 2. 问题与假设

| 编号      | 研究问题                                           | 假设                                                    |
| ------- | ---------------------------------------------- | ----------------------------------------------------- |
| **RQ1** | robust v2 的场景采样 / 奖励版本 / 课程改进，能否提升合作团队成功率与稳定性？ | weighted 采样 + reward v2 + 课程软过渡 优于 random / reward v1 |
| **RQ2** | 冻结合作团队上训练的多对抗团队，能在多大程度上降低其成功率                  |                                                       |
| **RQ3** | 对抗智能体数量 M 与课程学习对攻击有效性的影响                       |                                                       |
| **RQ4** | 合作团队的鲁棒性短板在哪些场景上最明显                            | 训练分布外（边界 / 角度偏移）场景掉得最多                                |

---

## 3. 架构

```
CARLA 服务器 (Town02 直道, 同步模式 fixed_delta=0.1)
        │  carla python client
        ▼
CarlaMultiAgentEnv  ── 19维obs(8基础+11 lidar) / 3维连续动作 / 多维度reward
        │
   ┌────┴───────────────────────────────┐
   ▼                                      ▼
合作团队 MAPPO (robust v2)          对抗团队 MAPPO (multi-adv v2)
 · 全局Critic + per-agent Actor       · 冻结合作 ckpt，训练 M 个对抗 Actor
 · 场景采样 + 课程 + GAE               · 全局Critic + per-agent advantage
        │                                 │  reward = 对抗 + coef×(-合作reward)
        ▼                                 ▼
   coop_best.pt  ───────────────────►  adv_best.pt
        │                                 │
        └─ ─► 鲁棒性评估 (有/无对抗对照) ◄───┘
```

**要点**：CTDE，无策略共享（每 agent 独立 Actor），GAE + PPO clip + 熵正则 + KL 早停

### 4.2 合作训练 v2 相对 v1 的改进

1. **GAE 跨 episode 泄漏修复**：按 episode 边界独立计算 GAE，截断 episode 用 Critic bootstrap 而非 0。
2. **数据量 / 复用调优**：`rollout_episodes 4→16`，`ppo_epochs 10→5`，降低优势估计方差。
3. **场景分层 + 加权采样**：weighted 模式保证每场景至少 1 次、困难场景上采样。
4. **课程软过渡**：阶段切换前后线性混合新旧场景，避免硬切换遗忘（第三轮修复了 `stage_start` 对齐 bug）。
5. **PPO 优化 + 训练稳定性**：KL 早停（target_kl=0.02）、`init_log_std=-0.5`、`clip_eps 0.2→0.15`、逐 episode 优势标准化、`best.pt` 跟踪、TB 时间戳隔离、`--resume` 续训。

### 4.3 对抗训练 v2 相对 v1 的修复

| 问题（v1）                        | v2 修复                              |
| ----------------------------- | ---------------------------------- |
| 零和系数被写死 ×0.01                 | 提为 `--zero-sum-coef`               |
| Critic 只看对抗 obs → 价值有偏        | 改用全员 `get_global_state()`          |
| 所有对抗 agent 共享 joint advantage | per-agent advantage（各自 reward）     |
| 不采样场景 → 训练/测试分布不一致            | 复用 robust v2 场景采样 + 课程             |
| 评估脚本不兼容多对抗 ckpt               | 新建 `evaluate_multi_adversarial.py` |

### 4.4 奖励函数与环境关键 bug 修复

按 [bug修复记录.md](bug修复记录.md) 时间线，目前主要新修复了以下问题：

- **collision 统计恒为 0**：env 每 step 清零事件字段，改为 rollout 内 sticky 累积。
- **"撞了反而赚"**：调整奖励系数，使撞车 episode 收益严格为负。
- **lidar 探测bug**：CARLA `LabelledPoint.label` 是语义枚举不是 actor ID，11 条 ray 全打在自己车身→obs 全 0、奖励恒 -3.3。改用 bbox 外接圆半径过滤自身。
- **"原地不动"刷奖励（两轮）**：① speed_reward 减 baseline、新增 motion-gated alive_bonus；② 给 centering/yaw 加运动门控 `min(1, speed/2)`，停车每步净收益从 +0.55 变为 -0.1。
- **人行横道压线漏判**：主动用 `map.get_crosswalks()` 多边形做点-包含判定，踏上斑马线立即 done。
- **到点姿态 / done 状态机抖动**：reached_target 时直接清零刚体速度 + done 对 reached_target sticky。

## 5. 实验设计（待批量跑）

实验分三组，统一基准超参 `--updates 100 --rollout-episodes 16 --ppo-epochs 5`，核心结论跑 3 seed ：

- **A 组（RQ1）**：合作团队训练消融
  - A0 主基线（weighted + reward v2 random/stratified/we+ 软过渡）→ 产出 `coop_best.pt`
  - A1 采样模式 (ighted)、A2 奖励版本 (v1/v2)、A3 课程 (软过渡/硬切换/无 lr 衰减)
- **B 组（RQ2/RQ3）**：对抗团队训练消融（以 A0 best.pt 为冻结合作团队）
  - B0 主基线 (M=2, zs=1.0, 课程)、B1 零和系数 sweep (0.1/0.5/1.0)、B2 数量 M (1/2/3)、B3 关课程
- **C 组（RQ4）**：鲁棒性评估

## 8. 已知局限 / 风险

- 当前场景**训练集 = 测试集**，RQ1 的 hold-out 需另划分场景（实验计划 §9 已留接口 `--test-scenario-dir`）。

- 多对抗 M≥3 时起点分配可能冲突，可能需要在 scenario JSON 显式指定起点。

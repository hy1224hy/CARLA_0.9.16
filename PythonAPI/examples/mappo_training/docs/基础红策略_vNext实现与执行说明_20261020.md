## 修改内容及理由

| 内容 | 实现 | 对应问题 |
|---|---|---|
| 场景分布 | 新训练池48例、24完整编号互换对；四方向、并排/相邻车道±8m错位、静止/同速滚动2.5m/s；验证池32例使用±4m，模板与镜像整体分离 | 避免方向/位置/编号绑定及长期重复并排起步 |
| 逐车目标 | 每车32m、显式逐车目标；编号互换时初态、目标和角色一起交换 | 避免只移动起点却改变路线长度，也避免共享终点覆盖逐车目标 |
| 配对采样 | 每update16回合，四方向各4回合，完整编号对；解锁全池后3updates轮完48例 | 文件更多不自动获得更多权重，固定弱车必须得到对应物理角色的训练机会 |
| 跨轮课程 | stage0含16例并排静止/滚动，stage1累积全部48例；至少20updates/320回合、各分层20回合，最多80updates一窗，两个不重叠达标窗解锁 | 消除每层8回合一次事件即12.5%的离散瓶颈；安全比例仍10%，不自动放宽标准 |
| 奖励对照 | V6原公式合同；另一个`startup_v1`合同只改无阻挡pace宽限与成本 | 分离场景/课程改动和效率奖励改动，保留可归因的对照 |
| 资格与选模 | 每辆车、每方向/静止滚动/角色均检查；先安全与正常驾驶，再从合格候选中选模 | 共同到达或高回报不能掩盖一车超速、一车迟起；没有合格候选就明确不给基础策略资格 |
| 完整恢复 | 严格延续双Actor、Critic、Adam、ValueNorm、RNG、课程窗口、采样相位、学习率/熵时钟；合同/profile/源码漂移拒绝恢复 | 不把重新初始化或改奖励称作连续训练，不把未提交尾部计为有效进展 |
| 测量口径 | 诊断净车距使用实际bbox占用长度，道路切向投影计算闭合速度/TTC；转向/制动用实际控制回读，缺失单独计数 | 中心距不冒充净车距，发送控制不冒充已执行控制，终止帧缺失不填零 |

课程判定中的“角色”包括Actor编号，防止强车均值覆盖弱车。课程解锁是训练调度证据，不是冻结驾驶资格。理想达标数据下stage0最早u40解锁；stage1完整角色暴露需要更长窗口。失败窗口给出复核项，不自行扩预算或改变门槛。

## 奖励的具体边界

`configs/base_driving/base_driving_v6_v1.json`保留`instant_pace_v6`原公式。`configs/base_driving/base_driving_startup_v1_v1.json`使用相同父奖励，只将无阻挡pace宽限从2秒改为0.8秒，最大效率成本从0.5/秒改为1.5/秒。远目标参考速度仍2.5m/s，近目标仍0.5m/s；真实前车阻挡、复杂交互、终止事件仍豁免，不累计历史罚债，不惩罚到达时间差。

V6的高速肩部、超速、参考车道偏离、中心二次成本、转向变化项、碰撞/越界和目标项均保留。0.8秒及1.5/秒是待真实车辆响应标定的候选参数，不能只凭代数正确就宣称足够驱动正常驾驶。

20维观察/2维策略动作、双独立Actor、PPO/GAE、活跃mask、到达即移除和600步学习率/熵调度保持。没有实施共享Actor、教师/行为克隆、新观察、同道跟车或四车对抗；相邻车道纵向错位不是跟车任务。后续若仍有固定弱车，需单独检验这些候选，避免同时改完后无法定位原因。

## 驾驶资格与验证分工

新资格合同为`configs/evaluation/base_driving_vnext_v1.json`。工程默认阈值：无阻挡静止起步首次达到0.5m/s不晚于2秒；排除起步段及距自身目标5m内的巡航段，7.2–15km/h占比至少80%、超15占比不高于5%；超30、碰撞/越界/道路违规、参考车道偏离及实际转向稳定性另设硬条件。上述速度带是研究任务偏好，不是当地法规限速。

每阶段先用同一checkpoint执行新训练池的16个并排配置×2seed＝32例能力保持回归，再执行32个未训练初态组合×2个固定seed（63001/63002）＝64例验证；按逐车、方向、静止/滚动及角色分层。最终选模必须同时通过并排回归与错位验证，缺少前者只标`PENDING_PARALLEL_REGRESSION`，不授予基础候选资格。回归属于训练分布能力保持，验证也仍来自既有四个走廊；二者都不是最终保留测试或跨地图/种子总体泛化证明。正式保留测试应另行冻结，不参与本轮反复调参。

旧V6 checkpoint只允许显式作为历史参照，不能因为符合部分数值阈值而自动获得新协议资格。阶段冻结使用保存副本，评估退出后才恢复训练；端口2000只允许一个时钟拥有者。

## 本机运行指令

下面是**尚未执行的候选先导预算**u25/u50，不沿用旧run的u600授权。600仍为学习率/熵调度长度；实际执行上限由新计划`stop_updates`最后一项决定。先通过真实几何和短程运行核验，再明确启动；需要更长预算时，在新计划准备阶段显式列出里程碑，不能改已绑定计划来扩预算。

```powershell
Set-Location D:/study/yan2/CARLA_0.9.16/PythonAPI/examples/mappo_training
$carlaPython = 'D:/study/yan2/CARLA_0.9.16/venv/Scripts/python.exe'

# 用户启动CARLA后，串行检查地图；这两条不spawn/tick，但会连接服务器。
& $carlaPython -m utils.preflight_base_driving_scenarios_v1 --scenario-dir data/training_scenarios_town05_base_vnext_v1 --output diagnostics/base_driving_vnext_20261020/preflight_train_live.json --live
& $carlaPython -m utils.preflight_base_driving_scenarios_v1 --scenario-dir data/training_scenarios_town05_base_vnext_v1_validation --output diagnostics/base_driving_vnext_20261020/preflight_validation_live.json --live

# prepare只建立新文件，不连接CARLA，不启动训练；路径必须是全新目录。
& $carlaPython -m utils.base_driving_session prepare --run-dir logs/BD_vNext_V6_s42_pilot_v1 --control-dir diagnostics/base_driving_vnext_20261020/v6_pilot_v1 --contract configs/base_driving/base_driving_v6_v1.json --stop-updates 25 50 --train-geometry diagnostics/base_driving_vnext_20261020/preflight_train_live.json --validation-geometry diagnostics/base_driving_vnext_20261020/preflight_validation_live.json --seed 42

# 纯文件核查，PREPARED不等于训练成功。
& $carlaPython -m utils.base_driving_session inspect --plan diagnostics/base_driving_vnext_20261020/v6_pilot_v1/plan.json

# 明确启动后才按有限预算串行运行，异常即停止，不自动重启。
& $carlaPython -m utils.base_driving_session run --plan diagnostics/base_driving_vnext_20261020/v6_pilot_v1/plan.json

# CARLA崩溃后由用户重启，核查旧worker已退出，再明确恢复同一计划。
& $carlaPython -m utils.base_driving_session run --plan diagnostics/base_driving_vnext_20261020/v6_pilot_v1/plan.json --resume-controller
```

`prepare`也允许引用已经存在的离线PENDING报告进行方案审查，但`run`拒绝PENDING：必须在同一路径补上与该冻结池及checker源码匹配的真实几何报告。没有报告文件时先执行纯文件预检创建PENDING，不能手写PASS。

运行`startup_v1`对照时只替换合同为`configs/base_driving/base_driving_startup_v1_v1.json`，并使用**另一个全新run/control目录**，其他预算、seed和冻结套件相同。不能把同一个run切换profile续训，也不能把旧u327作为新协议权重装入。

每阶段输出`u000025_summary.json`等、不可变checkpoint副本、`screen_u000025/parallel`与`validation`的manifest/轨迹/qualification、及`selection.json`。训练日志由`run/session/launch.json`指向，exit必须匹配launch UUID及实际worker PID；每20分钟写`monitor_latest.json`及历史，只计manifest安全边界。训练时跟踪镜头，冻结评估由评估器跟踪车辆。阶段正常结束后训练镜头`EXITED`是正常状态，不能因无训练车辆误报。

恢复时保留中断会话和未提交尾部，训练器从最后安全update重做未提交段；若已安全保存里程碑但崩溃前没写exit，可在明确恢复时先补冻结，并标注缺失exit和`explicit_safe_boundary_recovery`，不补造成功退出。部分完成的评估整套归档后重跑，不重训已经提交的阶段。不允许后台仍有旧worker时覆盖会话。

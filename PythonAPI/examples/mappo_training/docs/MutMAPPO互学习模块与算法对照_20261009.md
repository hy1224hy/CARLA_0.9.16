## 1. 互学习模块实际做什么

物理环境2红2蓝；红0/1冻结。A/B是两套蓝团队学习器，交替使用同一个仿真，不是增加车辆。每套有蓝2/3独立Actor；MAPPO采用集中Critic，各自optimizer、ValueNorm及随机流。

1. A用自身策略采样，自己的真实reward计算GAE与PPO目标。
2. A蓝角色i与冻结B同角色i都读取**A样本的同一个观测**，比较动作高斯策略分布。
3. KL只更新A Actor，教师无梯度；B的数据不当作A的on-policy PPO数据。B对称。
4. 独立gate案例串行验证冻结快照，保存q/b/n、case keys、版本与teacher hash。门控在下次refresh前固定；Critic只拟合本方回报。

`L_student = L_MAPPO + beta * mean_all_valid(g * KL(student || frozen_peer))`。

逐动作维度求和，再对该Actor有效样本平均；完成／失效蓝的无效动作不入buffer，g=0的有效行保留在分母。anchor是独立辅助项，默认0。KL位于原PPO Actor minibatch loss hook，不另复制更新器。不同实体车不强制动作一致；此机制是训练期策略互蒸馏，执行通信另做模块。

默认方向student_to_teacher；teacher_to_student和symmetric可明确配置，教师仍截断梯度。分母版本固定all_valid，拒绝enabled_only。比较的是策略tanh变换前Gaussian分布；物理油门／刹车deadzone非双射，不能将这个KL直接称最终车辆控制分布的精确KL。

## 2. 实现位置与控制参数

| 位置 | 职责 |
|---|---|
| `training/mutual_distillation.py` | 纯策略KL、方向/分母校验、evidence/random/strength权重构造 |
| `training/mut_mappo_learning.py` | 独立学习器、同角色冻结peer、PPO aux hook、场景门控、RNG与恢复 |
| `models/mut_mappo_critics.py` | IPPO严格局部Value，只取当前蓝的20维槽 |
| `training/train_mut_mappo.py` | 单/双团队串行采样、任务与预算、完整边界保存、gate时序 |
| `training/mut_mappo_experiments.py` | 算法／组件注册表，不能只改算法标签 |
| `evaluation/mut_mappo_selection.py` | 仅用selection选团队/轮次并导出冻结Actor，test/gate禁止选模 |

主要配置：`algorithm=mappo|ippo`，`team_count=1|2`，`method=off|plain|selective`；`learning.beta/anchor_beta`；`learning.distillation.direction/reduction/gate_variant`；`mutual`的暖启动、refresh、最小案例数、安全阈值、质量差；`run`的轮次或tick时钟、停止规则／预算；红权重、案例清单与选模规则。均写入配置及断点身份，恢复不允许偷偷改。

IPPO仅允许off；当前Mut主方法是dual MAPPO。IPPO每蓝独立Critic、Adam、ValueNorm、GAE和梯度裁剪，避免共享ValueNorm或全局clip造成角色更新耦合。公共状态存80维便于同一日志和buffer，但局部Critic内部只读自身20维，不接对方状态或ID one-hot。Actor仍完全相同的20/2、两层128单元、独立参数。

已预训练初始化保持源Actor隐藏宽度；改变网络尺寸须另设计初始化协议，不能强行加载不匹配权重。当前不支持的算法／通信会明确报错，避免仅换名字便写成已实现。

## 3. 对照各自回答什么

| 组 | 实际算法／学习器 | 控制的问题 |
|---|---|---|
| MAPPO | 单团队、集中Value、无互学习 | 标准MAPPO在共同任务上的性能 |
| IPPO | 单团队、每蓝独立局部Value、无互学习 | 集中训练信息的作用 |
| B0 | 两套独立MAPPO，无互学习 | 双学习器和更多选模机会本身的收益 |
| B1 | 双MAPPO，暖启后全部有效样本互蒸馏 | 互学习本身的增量 |
| B2 | 双MAPPO，质量／安全场景门控 | 候选选择机制的增量 |
| G_RANDOM | 双MAPPO，打乱本轮证据权重但保持每Actor启用行数 | 选择位置是否重要的诊断 |
| G_STRENGTH | 双MAPPO，每行权重填本轮证据覆盖率 | 辅助项只是变弱的诊断 |

基础算法比较与组件消融都需要。仅B2胜B0不能区分互学习、双学习器选模或门控强度；仅胜IPPO不能证明选择机制有效。主要比较用MAPPO/IPPO/B0/B1/B2，控制组先小预算定位。

G_RANDOM和G_STRENGTH目前**匹配自身run当前rollout的权重质量**；不保证另一独立B2 run具有相同覆盖或实现KL。更强机制结论需冻结外部B2门控覆盖日程，在独立重复/留出案例上做匹配控制；不能把本轮代码自动生成控制称为严格cross-run等KL消融。所有控制保存配置和随机状态，权重一次rollout生成、跨PPO epoch固定。

- Mut-DQN参考以此前用户六页全文解读为准：Q softmax/TD结构与本次Gaussian Actor/PPO不同。不能仅因引用本人的论文就把连续控制迁移说成已证实的新算法。

若论文主张超越既有选择性蒸馏，仍需明确最近邻差异并补DPD式适配对照；目前DPD忠实复现、MADDPG/MATD3/MASAC及通信未实现。后续不同算法家族应另处理replay、target、噪声、调参及完整恢复，遵循共同外部评价；不为堆名称改变20/2连续动作能力。

## 5. 实验生成与选模

模块目录执行，先激活venv或使用 `D:/study/yan2/CARLA_0.9.16/venv/Scripts/python.exe`：

```powershell
# 纯离线接口预检；不创建CARLA Client
python -m training.train_mut_mappo --algorithm ippo --team-count 1 --validate-only
python -m training.train_mut_mappo --algorithm mappo --team-count 1 --validate-only

# 生成五组先导配置和串行queue，不启动训练
python -m utils.plan_mut_mappo_experiments --phase pilot --suite comparisons --output logs/mut_mappo/queues/comparisons_v1
# 全部七组（控制组应先作小规模探索，不自动全部长跑）
python -m utils.plan_mut_mappo_experiments --phase pilot --suite all --output logs/mut_mappo/queues/all_controls_v1
```

`suite=core`仍只B0/B1/B2；comparisons是五组；controls是两诊断组；all是七组。五组正式各3外层seed为15个run，比原9个主run多6个，不能未经吞吐定标便把所有未来通信/风格实验叠加。队列只是计划，不启动租赁机器或CARLA。

比较配置按A/B合计实际train world.tick停止，并按训练成本设置LR与教师refresh。rounds只作估时；single不会因同样轮数而仅获得dual一半数据。仍在**完整单团队／完整A+B边界**停止，故预算是软上限，记录overshoot、废弃ticks、validation、参数量和优化采样量；不能声称精确同ticks。共同成本检查点及实际差额要进入主表。默认smoke仍按少量rounds停止。

只用selection清单安全过滤后排名：AttackGain_safe、q、任务违约数、较早轮次、稳定团队ID。要求每个竞争团队的全部共同计划配对完整；缺例输出INCOMPLETE_EVIDENCE，不合格输出NONE_QUALIFIED，两者均不导出。不同算法/seed不混在一个选模池，选模时机和候选数一致。

```powershell
# 用户已启动CARLA后：对不可变完整boundary做selection，随后显式选模
python -m evaluation.evaluate_mut_mappo --config <该run配置> --checkpoint <boundaries/round_*.pt> --team both --split selection --output-dir <新selection目录> --select-best
# 或从同一个run多个完整selection目录选轮次，禁止test挑赢家
python -m evaluation.mut_mappo_selection --evaluations <selection_1> <selection_2> --output-dir <新选模目录>
# 冻结导出包只能评估/部署，不能恢复优化器
python -m evaluation.evaluate_mut_mappo --config <该run配置> --checkpoint <选模目录/frozen_blue_team.pt> --team both --split test --output-dir <新test目录>
```

选模输出selection.json与带SHA的inference-only冻结Actor；source checkpoint/hash、case/red身份、排序依据完整。多轮评估务必使用不可变boundary，正在覆盖的latest.pt不能作为可追溯选模候选。

## 2. 两个研究点的梳理

### 研究点一：面向多车驾驶策略的安全约束对抗交互生成

**问题：** 冻结正常驾驶红车后，能否训练蓝车主动触发有价值的交互困难，并避免通过自身碰撞、违法行驶、利用终止漏洞制造虚假攻击效果？

**方法候选：** 在PPO/MAPPO中组合有事件依据的红车响应奖励、带有效交互条件和累计预算的稠密威胁引导，以及蓝车自身安全成本。保留现有KL锚定作为训练稳定工具，不把“用了KL/MAPPO”单独当作贡献。事件归属使用碰撞对象、时间窗和相对几何；满足这些条件只能称规则归属证据，不能称严格的单回合因果证明。

**主实验规模：** 2红车+2蓝车；先以2红+1蓝验证生命周期、指标和可学习性，再扩展到双蓝车。只有双蓝结果完成，才在本月材料中主张“多对抗车团队方法”；若只有单蓝结果，诚实使用“面向多车驾驶系统的单对抗车辆方法”。

**拟验证的贡献：** 相对于仅追求红车失败的普通对抗学习，在蓝车碰撞/违规更少或相近的条件下，保留有用的攻击强度，并产生可解释的制动、阻挡或合法车道交互案例。约束方法攻击更弱但更安全也有研究价值，需要报告折中，而不是只挑攻击最强的模型。

**月底交付：** 一套冻结基础红车、一套统一C0/C1/C2评估、一套对抗训练入口、主方法/普通对抗各3个训练seed、2项探索性消融、跨参数测试结果、3–5段典型轨迹视频。

### 研究点二：面向未知对手的策略种群对抗训练与双边演进

**问题：** 只针对一个固定红车训练的攻击策略是否过拟合？能否借助历史策略池与元策略采样，让蓝车面对不同红车仍有效，并让红车在迭代中保持正常驾驶能力、抵抗历史攻击？

**方法候选：** 基于PSRO维护红/蓝池，复用研究点一的训练器作为蓝方近似最佳响应；另提供红方鲁棒训练入口。每轮训练响应、评估新增交叉配对、更新元策略并检查行为多样性与正常驾驶退化。

**与研究点一区别：** 点一研究固定被测策略下如何生成合格攻击；点二研究跨对手分布的训练、策略选择和历史能力保留，必须包含新对手/旧攻击的交叉评估。

**本月框架最小完成范围：** 兼容20维观测/2维动作的策略注册表、按回合选取冻结对手、收益矩阵缓存、均匀与一种收益驱动元策略求解、蓝响应训练、红响应训练接口与小预算实跑、整轮恢复。至少完成2红×2蓝矩阵和一次蓝响应迭代；争取新增一次红响应形成小规模双边演示。仅蓝池扩展时标记单边原型。

**后续实证方向：** 固定对手、均匀历史池、收益驱动种群采样三组比较；看留出对手上的性能、最差对手表现和旧攻击回归，而非仅看池内平均收益。不能把有限池内表现称真实exploitability或纳什收敛；不对没有配对训练关系的任意矩阵使用对角线JPC解释。

### 创新性边界

学习型危险场景生成及PSRO本身已有研究，候选贡献应落在约束和交互归属机制、以及质量/行为差异驱动的驾驶策略种群构建，需通过消融建立支持，不能预先写成已证实创新。本月不另开显式通信、路口拓扑、图网络或大模型方向。

- [Learning to Collide，IROS 2020](https://arxiv.org/abs/2003.01197)：已有学习式安全关键场景生成方法，不能把“RL生成困难场景”单独作为新颖性声明。
- [PSRO，NeurIPS 2017](https://arxiv.org/abs/1711.00832)：已有对策略混合训练近似响应、由经验博弈求元策略的框架。

以上是定位所用文献，不是完成全面查新。10月8日前补充近年最相关方法对照表，限定本项目实际能验证的区别。

## 5. 研究点一的最小实验矩阵

### 5.1 三条件统一评估

- C0：2红、无蓝，测自身失败。
- C1：2红+与C2同数量蓝车，蓝车使用冻结的普通驾驶策略；出生位置、车型、初速度、任务预算与C2相同。规则控制可作补充基线，但不能在比较过程中随意切换C1定义。
- C2：同场景同初始配置，蓝车使用学习型对抗策略。红车始终同一冻结权重。

固定红车actor不要求critic输入维度与旧2车critic相同：红车仅执行原actor；蓝方critic按当前总车辆数构建。训练和评估都必须传入正确剩余时间、动作映射和失活状态。

主指标保留现有符号：`Δsuccess = Success(C2)-Success(C1)`，越负攻击越强；另报`TrafficEffect=Success(C1)-Success(C0)`。需要正向图时可显示`AttackGain=-Δsuccess`，必须标注变号。不要把`1-Success(C2)`直接当学习增益。安全约束是单独报告的蓝车碰撞、违法、直接撞击证据；这些指标不能凭“对方先触发sensor”武断解释责任。

### 5.2 训练方法比较

| ID | 组别 | 训练seed/预算建议 | 用途 |
|---|---|---|---|
| P0 | 2红1蓝完整方法 | 1seed，30–50updates | 验证能学、角色奖励正确，不作为双蓝主结果 |
| B | 2红2蓝普通对抗PPO/MAPPO | 3seed，同主方法预算 | 同环境/网络，任务失败奖励为主，无新增归属门控/自适应安全模块；不是移除所有基础驾驶成本 |
| M | 2红2蓝完整方法 | 3seed，名义150updates/seed | 主结果 |
| A1 | M去掉自适应安全成本，改固定成本 | 1seed，等预算 | 自适应约束消融，探索性 |
| A2 | M去掉有效交互门控/预算，保留相同威胁计算 | 1seed，等预算 | 密集引导是否制造虚假高分；探索性 |

训练seed建议42/123/2024。先跑B/M各1seed验证趋势，算法版本冻结后再补其余seed。M与B总预算一致，默认150updates仅为估时单位；真正比较同时固定/报告仿真交互步、episode数、每agent有效transition和优化次数。按预先校准的world-tick预算在完整update边界停止、记录尾部超额，不能因为某组失败回合短就获得隐蔽更多优化预算。双蓝/单蓝不能把agent transition数直接当相同环境交互量。

只完成1seed的消融写“探索性”，不能写多seed稳定改进。若资源充裕，先补关键消融seed，优先于增加第三辆蓝车或大量系数扫描。以置信区间和安全折中如实结论，不承诺主方法一定攻击更强。

### 5.3 场景与数据划分

红车原12个基础场景不自动等于可用对抗场景，需要加入合理蓝车起点和可产生交互的任务设计。先定义跟驰/逼近、相邻车道速度冲突、合法变道/阻挡三个族，方向均衡。合法变道族仅在路段拓扑和标线允许且双方普通策略能执行时纳入；若无法完成，明确缩为前两个族，不以违法穿插替代。

建议从3族×4方向=12个对抗模板构建：训练时在合法起点、速度、相对间距的小范围内采样；验证24例（每模板2个固定配置）；同分布测试60例（每模板5个未用于训练/选模的配置）；留出参数压力测试36例（每模板3个组合，明确哪些间距/速度组合未进入训练）。物理出生可行性需检查，不把seed不同等同于场景不同。配置在主训练前落盘，最终测试不用于改奖励。

每策略评估60+36=96例；8个蓝策略约768例C2，加两组各96例C0/C1约960例，补充复跑和案例预计约1000–1300例。公共C0/C1结果仅在红车、协议、蓝车数量和初始化完全相同时复用；2+1不得复用2+2的C1。

### 5.4 必要指标和结论

主表：C0/C1/C2红车团队成功、红车碰撞/越界/超时、蓝车碰撞/违规、配对Δsuccess。补充：有效交互事件率、畅通低速时长、到达时间分布、最低TTC/近失事件（阈值固定）、不同失败类型、每模拟小时发现有效困难场景数。到达时间须同时报告失败/超时比例，不能只展示成功子集提速。

按场景配置配对，分训练seed报告均值及离散程度；3训练seed与96评估配置是不同层次，不能把288回合当288次独立训练重复。必要时用按场景配置和seed分层的配对bootstrap表示不确定性，小样本不夸大显著性。

## 6. 点二代码框架与演示验收

复用已有training/psro模块，最小接口围绕 `PolicySpec / Population / OracleResult / PairEvaluation / MetaStrategy / IterationState`，具体命名实施时确定，不新建重复训练栈。

| 模块 | 本月要完成的行为 |
|---|---|
| 策略注册/加载 | 每策略记录角色、20/2协议、奖励版本、来源、SHA和质量指标，拒绝不兼容加载 |
| 对手采样 | 每回合从指定分布采样冻结对手，记录实际policy ID；不是每step换对手 |
| 收益评估 | 缓存每对策略×场景配置的结局与安全向量，保留样本数和未评估标记 |
| 元策略 | 先均匀分布跑通，再校核PRD的概率单纯形与最低探索概率约束；均匀采样不称等价于fictitious play |
| 蓝响应 | 调用点一训练器，对红车分布训练新蓝策略，按验证集准入 |
| 红响应 | 对蓝车混合训练红车，保留C0/C1正常驾驶回归与历史对手评估 |
| 外层恢复 | 保存池版本、矩阵、元策略、随机数状态、oracle断点及待评估任务，重启不重复入池或重复计数 |

PSRO求解收益与论文报告的Δsuccess应区分：双边主博弈可用共同定义的红车任务效用及其负值，安全通过策略准入或明确的一般和成本处理；不能把每个红策略的C1校正量直接当红方学习目标，避免红方通过降低正常表现获得有利分数。报告仍计算C2-C1。一般和安全成本不能不加说明强行称严格零和。

演示：2个质量可用的红策略（不同训练seed优先；若仅不同checkpoint须注明相关性）×2个蓝策略，12个固定验证配置/配对=48回合起；生成矩阵、元策略分布并执行一次新蓝oracle。争取再训练一个红响应并补矩阵。若没做红响应，框架状态标为单边已跑通、双边待验证；矩阵图不能单独证明循环克制。

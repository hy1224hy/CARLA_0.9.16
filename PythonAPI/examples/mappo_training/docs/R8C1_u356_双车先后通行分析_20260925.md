# u356 双车先后通行分析

结论：存在明显的先后到达和速度不对称；历史u208确定性南短静止场景确实呈现“agent0到达后agent1才起步”。但现有u356训练日志没有逐步速度，不能认定当前所有场景都学会了以队友到达为触发条件的等待策略。

## 最新训练证据

统计u337–356全部320回合中的238个团队成功回合：225次agent0先到，13次agent1先到。只在成功回合中，用active_decision_steps×0.1秒推算到达时刻（每步对活跃agent累加，达到目标后不再采样）；失败回合不能这样解释。时间均为仿真时间，不是墙钟时间。成功条件统计会遗漏超时和安全失败。

|场景|成功/总数|agent0先到/成功数|agent0到达中位秒|agent1到达中位秒|
|---|---:|---:|---:|---:|
|01北短rolling|24/25|22/24|3.40|5.95|
|04南短静止|28/28|28/28|3.00|6.10|
|05北长rolling|9/28|0/9|16.90|10.20|
|06南长rolling|22/28|22/22|6.25|15.60|
|10南长静止|20/26|20/20|8.20|22.10|

大多数场景是agent0先到；北长05成功回合反而全部agent1先到，说明角色分化也依赖场景。最后一个完整回合（u356场景11）agent0第65步到达，agent1第349步到达，相差28.4秒，但该记录不能告诉我们agent1此前是在停等、爬行还是途中减速。

也不是越训越串行的单调趋势：同场景04在u187–208成功回合的两车到达中位数为2.75/10.5秒，到u337–356为3.0/6.1秒；场景06为5.5/24.2秒→6.25/15.6秒。后车效率相较u208已改善，仍存在显著差距。

## 历史完整轨迹：现象成立，但不是所有模式通用

u208、场景04、确定性策略的两个seed结果一致：agent0第26步（2.6秒）到达；agent1在此时路线完成度约0，首次达到0.5m/s为第51步（5.1秒），第94步到达。这是先到后起步的直接时序证据；起步还滞后队友到达2.5秒，不能称到达瞬间触发。

相同u208场景04随机策略的两个seed，agent0都第29步到达，agent1分别在第17/28步已达到0.5m/s。因此，不能将确定性例子的等待方式直接套用于训练时的随机策略。

反例：u208确定性场景01、06，两车第1步已运动（含初速度），agent0到达时agent1已完成约37.5%/22.3%路线，之前速度持续≥0.5m/s。这些是同时运动、速度不对称，不是从起点一直等到队友到达。

## 可能机制与尚未证实之处

1. 环境`_check_dones()`在到达时调用`_despawn_reached_vehicle()`，销毁车辆与传感器。先到车辆消失后，两车碰撞机会和另一车的局部感知输入可能变化。这为“错开通行降低风险”的策略提供了条件，但没有证明Actor依赖消失事件起步；队友也可能早已驶出10米感知范围。
2. 两个Actor独立、权重不共享，允许形成快慢角色。现有证据确认不对称行为，不能仅由网络独立性推导它必然等待。
3. 当前gamma=0.999，等待50步对应折扣约0.951，等待100步约0.905；仅靠折扣对几秒等待的抑制有限。v6 pace惩罚需free_flow且non_interactive标签并通过豁免条件，不能默认所有长任务都受到相同效率约束。风险规避和效率奖励的权衡是候选解释，尚无训练消融因果证据。
4. 既有u208轨迹还出现死区内零油门、随后有油门仍未运动；起步物理及控制回读对齐疑点仍在。不能把所有停滞都解释为主动协作或奖励投机。

## 建议验证计划（待审核，未实施）

先对u356做冻结策略短评测，选择04南短静止、05北长、06南长、10南长静止；确定性/随机两模式、3个配对seed，共24基线回合。逐步记录两车首次持续运动时刻、目标到达/消失时刻、队友到达前路线进度、双方同时运动占比、低速/油门/刹车、完整车辆控制状态及雷达输入。

预先约定“从起点等待”的诊断口径：后车在队友到达前大部分时间低于0.2m/s且路线进度很小，同时报告连续值，不靠单一阈值掩盖爬行。达到0.5m/s须持续若干步，避免一次速度尖峰算起步。本轮历史分析只用了首次跨阈值，不能冒称已有持续运动验收。

若基线复现，再在独立诊断环境中做配对干预：固定后车出生条件，改变前车的行驶/到达时间，核对后车起步时间是否随之移动；进一步区分前车驶离感知范围与到达后消失。干预会改变场景输入，只用于机制定位，不计入正式成绩。保留原冻结环境，不先改奖励或训练配置。当前不自动连接CARLA或续训。

实验结论应同时报告团队成功率、联合完成时间、到达间隔、并行运动比例和等待开销。错开通行可以是合法策略，但在非交互平行任务中过度等待不应被包装成高效协作；做对抗训练前需判断攻击是否只是利用基础策略的等待弱点。

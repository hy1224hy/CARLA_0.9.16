## 1. 当前目标与事实

目标是得到每辆车都能正常驾驶、处理基本交通交互的合格基础策略。奖励修正是手段，场景覆盖与独立评估同样必要。BasicAgent快速路线保留为备选，本轮主线继续使用学习型红策略。

实际u456 checkpoint核验：update456；SHA256为8b9cb173cd70aacc201f0cb68183fdfeeb593cc8f29863c096a5f59076954545；training_config为reward_version=v6、pace_profile=route_pace_v1、gamma=0.999、r8a_balanced、r8a_mastery_v1、20m距离射线/TTC检测范围。观测/动作协议为20/2，独立Actor。

源文件：training/train_no_rllib_mappo_robust_v2.py、environment/base_reward_v4.py、base_reward_v5.py、base_reward_v6.py、route_pace_reward.py及carla_multi_agent_env.py。根AGENTS的早期每米+20/居中+0.5不是本轮实际奖励。

历史u456末20次更新的320个训练回合：成功90.31%、碰撞5.31%、越界3.13%、道路违规1.25%、超时0；两车均速20.14/8.14km/h，峰值49.12/40.50km/h。来自持续更新策略的训练窗口，不是冻结u456独立评估。缺少同u356继续相同预算的旧奖励对照，不能把变化全部归因奖励；快慢差的原因仍需轨迹定位。

## 2. 场景池是否合理

当前实际基础池是data/training_scenarios_town05_r8a_v1，共12例：南北短滚动2、南北短静止2、四方向长畅通4、四方向长静止并排4。分阶段累计扩展，S2每更新16回合采用精确平衡分配，余数轮换。晋级按mastery而非固定轮数自动推进。保持出生车道目标；不直接训练跟驰、追近、近间距恢复或强制并线。

结论：作为起步、直行、车道保持和到达的课程合理；作为正常交互及多风格底座覆盖不足。课程中很低的起步门槛不是正常驾驶的最终验收。

仓库另有v1的16例与v2的32例，不能把它们的存在等同于u456已训练过。新四车候选采用南北parallel_rolling模板并增加两蓝，滚动速度/角色位置/前方交通都有变化：道路几何重叠不代表交互能力已经合格。

建议先保留12例为稳定核心，增加少量镜像且正常的稳态跟驰、初始追近/减速、合法并线让行探针；是否纳入微调由冻结评估缺口决定。复用既有模板，先核几何与20/2环境协议，不直接启用历史v2的19D/rewardv3/自动课程。起点纵向位置、速度、间距与左右/前后角色可在合法范围内变化，并留出不同物理参数组合；仅换随机种子不是完整泛化留出。

并线不是当前直路阻挡最小任务的全部前提，可先用跟驰/速度冲突补基本响应，再逐步增加并线。不要立即把32例全加入长训，也不要直接改冻结R8-A目录后称严格resume。

## 3. 奖励是否合理

| 项目 | 当前实际实现 | 审查判断 |
|---|---|---|
| 进度与到达 | 20×(gamma×completion_next−completion_prev)，到达+20 | 保留；以任务进度为主，避免站着刷正奖励 |
| 安全与道路合法 | 碰撞/越界/持续道路违规−50；超时按未完成程度扣分 | 保留共同安全底线；数值大小不自动构成安全保证 |
| 车道与平滑 | 车道偏离成本、合法变道处理、纵向/转向命令变化成本 | 保留；命令变化不等于实测物理jerk |
| 效率pace | 参考9km/h，累计每车畅通时间与路线欠账比较；最多−0.05/0.1s步 | 欠账会延续到当前速度已恢复之后，且饱和；不直接要求队友同步 |
| 超速 | 15km/h开始，30km/h后固定最多−0.005/步 | 过早封顶，不能继续区分30与50km/h；当前任务速度阈值不是道路法定限速声明 |
| 可见状态 | 20D=目标/自车8项+11距离ray+剩余时间 | 没有累计畅通时钟和初始路长，MLP不能完整恢复pace奖励状态；也不直接提供前车相对速度/TTC |

大方向合理，优先修正效率与速度目标的不一致，而非叠加更多正奖励。pace和超速最大单步成本比10倍只是局部量级，不能当完整回报比；奖励之外的初态、角色、感知与独立Actor差异也可能影响双车不平衡。

最小候选修正：

1. 保留进度、到达、安全、合法变道和终局定义。
2. 用畅通时沿目标/路线前进方向的即时速度缺口替换累计pace欠账，保留起步、受阻/合理让行、终点减速豁免。不得以横向运动或危险跟车抵消低速罚款。实现时明确方向估计及门控的可用输入；移除累计时钟不等于奖励已完全可观测。
3. 超过合理速度上界后的成本在可行物理速度范围继续增长，避免30km/h就饱和；舒适速度范围内不新增可通过延长回合刷取的正速度奖励。9–15km/h仍为本任务候选范围，权重需短先导定标。
4. 不加入两车速度差/到达时间差罚款，以免快车等待慢车来改善表面同步。逐车看起步、畅通速度、任务完成和安全。
5. 显式新奖励版本、新合同和RunID；改变奖励目标需调整/重新估计Critic与ValueNorm，不冒称严格旧断点续训。先保留20/2及PPO网络，复用既有reward-fork工具。

效率项主动改变任务偏好，不能声称拥有势函数塑形的策略不变保证。[Ng等原论文](https://people.eecs.berkeley.edu/~russell/papers/icml99-shaping.pdf)给出的是特定势函数形式及相应假设下的结论。

## 4. 研究点2对基础策略的额外要求

先筛一份合格平衡基础Actor冻结供点一使用，再从共同初始化培养谨慎、平衡、积极正常红风格。风格由行为证明，不以私有reward名称、Actor编号或训练快慢差命名。当前不必先开发风格条件网络；多份独立Actor与明确参数身份足够首轮原型。

| 层次 | 共同要求/候选风格差异 | 同一探针评估证据 |
|---|---|---|
| 共同能力 | 逐车能完成、合法、不无故久停、合理处理前车、阻挡解除后恢复通行 | 逐车/团队完成率、真实碰撞/越界/逆行、起步/恢复延迟、无理由停滞与超时 |
| 速度偏好 | 合法上限内不同目标速度，不能靠超速区分 | 排除起步/受阻/终点后的稳态速度分布与完成耗时 |
| 跟驰偏好 | 不同期望时距/净间距，均满足安全要求 | 有前车机会下的车间净距、有效时距、TTC与制动响应 |
| 舒适性 | 不同加减速/转向平滑偏好 | 实测加速度、jerk以及控制变化率，分别记录 |
| 让行偏好 | 不同合法接受间隙/让行倾向 | 有冲突机会时的让行比例、间隙与恢复通行时间 |
| 可复现性 | 同场景、相同出生条件、共同能力门槛 | 行为分布跨案例/seed的稳定差异；没有机会的指标记缺失 |

谨慎允许合理减速让行，但不能永久停车；积极保持安全/合法共同标准，不能通过降低碰撞/越界惩罚制造风格。任务时限要允许最慢合格风格完成。不应为了让风格分离强行改变所有底层驾驶项。

时距风格不要求Actor必须读取“时距”这个字段，但相对运动可观测性会限制学习。当前距离ray快照没有直接给前车速度；如果跟驰/让行辨识是核心且现接口不足，再加可获得的相对运动特征或历史输入，升级观测协议并显式初始化，不称原20D原样恢复。集中critic的全局状态不能替代执行Actor的信息。红style ID先作注册元数据，不直接泄露给蓝Actor。

正常风格与抗蓝防御能力分开：先在正常交通探针证明风格，再评估固定蓝算法的跨风格攻击。不同风格私有reward原始return不可直接比较PSRO收益；用共同外部任务/安全指标。种群大小对照要有同风格多seed池与等规模多风格池；点一的冻结红保持固定，避免把目标变化混入Mut增益。

已存在的历史PSRO默认19/3、rewardv2，不是当前20/2四车Mut兼容风格PSRO。当前风格参数加载/注册、行为筛选和新PSRO迁移尚未实现；三类各1个合格策略可做原型，重复性结论需更多独立seed。

风格维度参考：[CARLA 0.9.16代理说明](https://github.com/carla-simulator/carla/blob/0.9.16/Docs/adv_agents.md)已有速度、制动距离及安全时间等规则风格参数；这不证明调整RL奖励就能自动得到同样的行为风格。

## 5. 最短下一步与状态

建议先对冻结u456做当前12基础案例的一次确定性行为筛选，再决定候选奖励fork。evaluate_reward_fork支持指定checkpoint列表与seed；1个checkpoint×12例×1seed=12回合可作工程筛选，不能据此估计总体可靠性。两权重×两seed默认为48回合，必要时才扩。若仅做4个代表案例需补场景筛选接口，目前不能虚构该参数。

记录起步、每车畅通速度、受阻/豁免、阻挡解除后恢复、超速及真实事故类型；不要只比较总回报。无长评估重复；需要CARLA时由用户启动，2000唯一时钟所有者。然后在新run做约20–30updates的小预算奖励微调，固定源Actor和场景以方便定位；这是候选工程预算，不是收敛保证。奖励筛选先不同时改网络/全场景池；交互探针识别后再按阶段补训练分布。正式因果结论仍需同预算旧奖励对照及独立评估。

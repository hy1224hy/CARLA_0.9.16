# 两研究点修订：互学习、通信与驾驶风格种群

日期2026-10-07。用户希望点一侧重算法改进，参考其此前深度强化互学习并加入通信消融；点二围绕不同驾驶风格建立策略池。本文件为设计草案，取代此前计划中“通信本月不做”和点一以约束奖励为唯一核心的定位，未修改训练源码或启动实验。

## 1. 当前前提与研究定位

用户已提供其本人发表的[Mut-DQN](https://ieeexplore.ieee.org/document/11274845)全文，PIMRC 2025，DOI 10.1109/PIMRC62392.2025.11274845。现已阅读六页并核对方法和实验图表。原文为多个学习器求解同一单智能体任务、softmax(Q)的KL辅助TD学习；不是物理多车之间直接对齐动作。新增[原文解读与迁移建议](./MutDQN原文解读与第一研究点迁移建议_20261007.md)：先以普通互学习MAPPO作迁移基线，再只增加一个选择机制。以下为候选设计，未实现或验证。

本项目当前是连续动作MAPPO，critic估计V而非离散动作Q表。建议保留现有PPO主体，用同角色actor分布蒸馏承接互学习思路；不能把原DQN损失直接加到V上，也不为引用该论文而将车辆控制离散化。由DQN迁移到MAPPO本身只是适配，不能单独作为算法原创性证据。

- **点一：面向多车协同对抗的角色一致、质量门控互学习方法。** 安全和事件奖励为各组共同任务基础；核心改进在信息传递对象、蒸馏样本选择和优化损失。通信是第二个可控因素，研究它与互学习是否互补，不把普通通信模块本身称原创。
- **点二：面向驾驶风格差异的策略种群构建与对抗泛化。** 先构建合法、可用且行为可区分的红车风格池，使用点一训练器作蓝方响应，比较固定对手、同风格多seed池和多风格池，再逐步引入PSRO。月底交付风格池小原型与外层闭环，完整双边演进/未知风格优势仍是后续验证目标。

逻辑：点一解决单个对抗团队如何学习，点二解决对哪些对手学习、如何保持跨风格能力。点一主实验先只用一个冻结平衡风格红团队，避免把多风格训练收益混进互学习收益。

## 2. 点一：互学习对象不能与物理车辆混淆

不建议直接最小化蓝车1在观测o1与蓝车2在观测o2的动作KL。车辆位置、目标和交互角色不同，正确行为可能一个制动一个加速；强行一致会压制分工，不能解释成知识共享。

推荐首版：训练两个独立的蓝团队学习器A/B，每个包含两辆蓝车的actor、自己的critic/优化器；训练时轮流使用同一个CARLA服务采集本团队on-policy rollout。环境仍只有2红2蓝，不是同时生成4辆蓝车。A/B可不同随机初始化或场景顺序，但共享任务定义。

跨团队传递同一车辆角色的行为知识：在A数据中的某个联合局部观测O上，A的第i个actor和B的第i个actor都评估同一个角色、同一个局部信息条件。B需在该样本上重新前向，不使用B在别处采集的动作。输入协议和角色对应必须一致；场景方向采用统一自车坐标表达是后续可选改造，不为首版同时扩大基础actor接口变更。

用最小化损失记号：

`L_A = L_PPO,A + beta * E[g_B->A(O) * KL(pi_A,i(.|O) || stopgrad(pi_B,i(.|O)))]`

全文核对后，此处改为本方在前、同伴在后的KL方向，与原文公式(7)保持一致；前版教师在前是另一适配选择，不应冒称原论文方向。两方向并不等价，首版不增加方向消融，所有比较保持一致。

B同理。通信存在时，pi_k,i(.|O)表示学习器k使用各车局部观测及自身通信网络得到的条件分布；训练可将O存成联合记录，但部署仍只读取本车观测和收到的消息。教师消息由教师网络重算，不能把不同编码器的隐向量当作同一语义硬复制。

### 门控与首版可实施性

先有PPO暖启动，再启用小权重互学习。g由三个条件构成：角色/输入匹配、教师在验证窗口满足蓝车安全条件、教师在相同场景族的独立小验证窗口中安全合格任务效用优于学生且超过预设容忍差。可以按场景族选择学习方向，使A擅长的场景教B、B擅长的场景教A；性能接近则不蒸馏。教师对学生状态的前向输出没有真实执行结果，不能给这些输出伪造逐动作安全标签；场景族层面的安全门控不保证每个迁移动作安全。

验证窗口只用训练/选模数据，不得读取最终测试。门控估计有噪声，是方法的待验证假设，不等于教师每个动作都更优。两边独立训练的V(s)尺度和误差不同，不能简单比较V_A与V_B来判断谁的动作好；若将来使用动作级Q优势门控，需要额外可信Q估计和不确定性处理，不作为首版附带复杂模块。

每轮教师使用冻结快照并停止教师梯度；限制互学习强度，记录策略KL，避免辅助项绕过PPO裁剪产生巨大更新。互学习仅更新actor及必要编码器，critic继续使用本方真实回报；不强行对齐两个不同任务分布下的critic数值。双方rollout只能用于各自PPO，不能把另一方轨迹当自己on-policy样本；共享数据只能明确用作辅助蒸馏。

策略为相同tanh变换与动作协议时，可在一致的变换前高斯分布上计算KL，避免用不合适的连续动作交叉熵或把均值MSE当完整策略分布KL。反向概率、动作mask、通信状态必须一致。

推理时选择验证集上的一个蓝团队，不把两个团队临时集成得到的额外计算优势混入结果。必须说明互学习可能导致策略同质化；不要求所有风格互相蒸馏，本模块主要用在蓝响应内部。

## 3. 通信：执行期局部信息交换

每辆蓝车用本地观测生成8维连续消息，单轮交换，actor输入自身观测和队友消息，输出原2维动作。红车仍冻结20维actor，不新增红蓝通信。actor不能读取对手真实策略ID、未来轨迹或集中critic输入。

首版若排除自身且每个接收者只有一个队友候选，对唯一发送者做softmax注意力权重恒为1，不能以此宣称学会了目标选择。原TarMAC公式包含自身消息，因此两车本身并不必然造成attention退化；保留self/null候选可以学习自我/队友权衡。先使用简单拼接或可学习标量门控，失活/距离不可达时用显式可用性mask，多邻居寻址留作后续。

通信消息只能由执行期可获得的本地观测产生。集中critic看到全局状态属于CTDE，不等于显式通信。加入通信后执行方式应写成“局部观测加队内消息的分布式执行”，不继续声称每车完全独立执行。

PPO采集冻结整套消息编码器/actor，保存原log_prob、局部观测和通信可用性；训练重新计算当前消息及动作分布，并用一致的mask/噪声实现ratio检查。不能使用旧缓存消息训练新接收器却声称编码器已端到端学习。新actor输入和通信状态必须使用新模型/协议版本；旧20维actor只能显式映射初始化兼容部分，不是原样严格续训。

## 4. 点一实验矩阵：拆出互学习与通信

| 组别 | 互学习 | 通信 | 回答的问题 |
|---|---|---|---|
| G0 | 无 | 无 | 共同奖励/安全约束下的MAPPO基线 |
| G1 | 质量门控互学习 | 无 | 互学习本身是否有效 |
| G2 | 无 | 有 | 消息交换本身是否有效 |
| G3 | 质量门控互学习 | 有 | 两者组合效果/交互效应 |
| G4 | 普通无门控互学习 | 有 | 改进门控是否优于直接采用互学习 |

G0–G3各3个外层训练seed；G4本月先1个seed探索性比较，有时间再补到3。每个外层seed包含A/B两个学习器，不能把这两个相关学习器算成两个独立重复。无互学习组同样维护两个独立学习器并使用同样验证选择规则，或者另设等总交互预算单学习器基线；主表必须标明。总CARLA步数按A+B合计，不能让互学习组多一倍数据。通信/无通信尽量匹配actor参数量，并报告真实参数量和训练计算开销。

G3固定模型再做消息置零、跨回合打乱、随机丢包测试，无需重新长训；这些只证明模型是否使用/依赖通信，不能代替从头训练的G1/G0，也不能把消息干预造成的分布偏移全部称信息价值。发送消息由本车信息生成，噪声和mask种子记录。

所有组共享基础/对抗奖励、安全条件、红策略和场景划分，替换上一版计划中“安全成本/威胁门控”为核心的消融优先级。继续C0/C1/C2及蓝车安全指标；报告样本效率、有效交互、失败类型、同场景到达/低速数据及策略KL。是否互补看完整2×2对比，不能只比较G3和G0。不能用两车动作一致性当协同指标。

## 5. 点二：红车驾驶风格池

暂按“不同风格的正常红车策略池”理解用户意图；蓝池由对抗训练产生，其差异更多描述为阻挡/逼近/分工等攻击行为，不混称正常驾驶风格。

首版选三个风格：谨慎让行、平衡通行、积极通行。共同保持道路合法性和最高速度规则，积极不等于违法/撞车，谨慎不等于无理由永久停车。

控制变量可以用z=(期望速度、期望时距、舒适性偏好、让行倾向)。例：合法畅通速度参考可设9/12/15km/h；谨慎时距较大、平衡居中、积极较小，具体范围需按车长、感知距离和任务可行性校准。通过奖励参数和训练交互分布构建不同风格，但不得为某风格放松碰撞/越界定义。此前全员9–15km/h效率区间是基础筛选候选，不应再用统一9km/h低速阈值惩罚确有前车而合理让行的谨慎策略。

本月优先独立actor、共同20维输入/2维动作及安全协议，style标签先作配置/注册元数据，不自动输入给蓝车。连续风格条件策略pi(a|o,z)可在后续做，避免现在叠加一个新条件网络。基础红车冻结后第一点不受风格池开发改变影响。

### 风格须由行为证明

所有风格用同一组自由行驶、跟驰、速度冲突和合法让行探针场景，测自由行驶速度分布、跟车时距、制动响应、加速度/jerk、让行比例和任务成功/安全。条件不可观测时指标记缺失，例如没有跟驰机会不计算有意义时距。按相同场景比较并按场景标准化行为向量，不把出生速度差、场景构成差或失败率高当风格差。

先要求每个策略正常完成任务，再判断风格可分；可画雷达图/距离矩阵，但分类准确率或简单聚类不是单独的机制证明。三个风格各2seed共6策略为后续目标，本月保底每类1个合格策略；未完成多seed则明确有限样本。

### 与PSRO的衔接

红池先按风格分层，风格内再容纳不同seed/训练快照；蓝响应在每回合开始采样一套红团队。对2红团队先使用同风格组合，谨慎+积极等混合团队作为留出测试，避免风格×角色×seed组合爆炸。

普通PSRO未必保留风格覆盖：若某种红风格被赋很低权重，训练可能很少再遇到它。可研究 `q(style)=(1-epsilon)*q_meta(style)+epsilon/K` 的风格探索下限，再在风格内按元策略或均匀采样。这是附加的分层覆盖机制，不等于求得无约束博弈的精确均衡，亦不宣称原创公式；需通过消融证明在此任务中的价值。

核心对照：单一红策略、相同数量同风格多seed池、多风格均匀池、多风格PSRO池；条件允许再比较有/无风格覆盖下限。前三组先分离池大小与风格差异收益，第四组检验元策略调度。训练蓝方算法固定为点一选定版本，避免算法与种群同时变动。

未知风格测试包括未参与训练的风格参数组合、各风格新seed、红团队混合风格组合，分别报告；换地图是额外泛化维度，不能混称风格泛化。训练/验证/测试及质量阈值需先冻结，不能看蓝车攻击结果后移除不好看的红风格。收益矩阵按同一外部任务/安全指标评估，不使用不同风格私有奖励的原始return直接比较。

## 7. 相关方法与候选创新边界

- [Mut-DQN, PIMRC 2025](https://ieeexplore.ieee.org/document/11274845)：用户本人已发表工作；PDF六页现已读，详见原文解读。原代码的梯度截断等细节尚未核对。
- [Deep Mutual Learning, CVPR 2018](https://openaccess.thecvf.com/content_cvpr_2018/html/Zhang_Deep_Mutual_Learning_CVPR_2018_paper.html)：属于互学习基础思路，不能直接将分类任务的互学习当作本项目已实现的强化互学习。
- [Dual Policy Distillation, IJCAI 2020](https://www.ijcai.org/proceedings/2020/435)：已有强化学习中的双策略蒸馏框架，新增KL损失本身不足以构成原创声明。
- [Policy Distillation and Value Matching in MARL](https://arxiv.org/abs/1903.06592)：已有同质多智能体知识迁移研究，需要说明角色对应与选择性迁移相对已有方案的实质差别。
- [TarMAC, ICML 2019](https://proceedings.mlr.press/v97/das19a.html)：通信已有成熟方法，本项目通信首先是对照模块。
- [Interaction-aware Decision-making using SVO](https://arxiv.org/abs/2207.05853)：已有风格相关驾驶策略学习，给策略设置风格标签不构成新颖性证明。

候选算法贡献在多车对抗任务下角色、场景能力与安全条件联合约束的信息迁移，以及风格覆盖与策略响应的结合。DPD已有选择性蒸馏，故“加KL”或“优者教劣者”均不能独立宣称新颖；还需要对照Mut-DQN全文及DPD等方法确认实质区别。G4只是普通互学习消融，不替代相关方法比较；若声称优于现有互学习，应增加匹配预算的DPD式适配基线，并标注适配差异。是否有效由预算公平的对照决定，当前仅为研究假设。

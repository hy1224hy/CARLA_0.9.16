# 四车初态覆盖、奖励设计与代表性文献核对（2026-10-29）

本记录接续10月28日的离线审查。只增加本目录的CPU探针与分析记录；原先导配置、算法、基础资格和历史证据均不修改。没有创建CARLA Client，没有真实tick/reset/训练。

## 建议的下一步

先把“可交互的场景”和“蓝方允许付出的运动代价”写清楚，再生成新版候选清单并做C0/C1。前次80例C0/C1、24k B0是v1候选预算；现阶段不应自动照旧表进入学习。v1保留，所有新版改动另立身份。

研究目标继续按既有范围理解：蓝方在登记的驾驶/任务资格内，相对普通C1降低红方通行效率。事故发现、近失生成和安全合格效率干扰是不同目标，不能直接照搬事故奖励。u1000仍未取得基础驾驶资格；真实预检即使通过，也只支持弱红工程诊断，不能自动升级正式算法比较。

## 当前场景实际覆盖

核对对象是 `experiments/adversarial_u1000_pilot_20261028_v1/cases.json`，不是仓库中所有历史/候选场景。

- 训练24例、gate/selection/test各16例，共72例。
- 蓝2相对红0、蓝3相对红1，均在相同车道前方，初速均2.5m/s。
- forward_m依次为train=10、gate=11、selection=12、test=13m，全部为正；沿模板道路方向计算，72/72例两蓝均在整个红队前方。
- `parallel/staggered`描述两红的纵向关系。错位初态改变了邻车相互关系，但没有引入后方追近、侧后占位或初态换道入侵。
- 红车目标中心距约32m，蓝车复用对应红目标；蓝初始剩余中心距离约为22/21/20/19m。蓝方更早进入目标区并退场的可能性必须实测，3秒出生保护后可能只剩较短交互窗口。

这些前方布局可以研究前车阻挡、受限超车和诱导减速；不能据此称覆盖了完整对抗交互。两条车道都被慢蓝车占住时，即使正常红方也可能必须减速。这种结果可以是有效交通干扰，但不单独证明红策略缺陷、两蓝超加性协同或Mut方法优势。

候选扩展建议：

| 布局 | 作用 | 优先级与边界 |
|---|---|---|
| 两蓝前方，含现有布局 | 保留简单阻挡控制组与工程基线 | 首轮保留，分清普通交通影响 |
| 一蓝前方、一蓝侧后 | 前蓝影响节奏，侧后蓝可能影响相邻车道空隙，增加互补机会 | 优先增加，但必须证明侧后蓝能在速度、道路和剩余时间约束内参与 |
| 侧方接近/合法切入 | 动态冲突点、让行和时机控制 | 后续候选；先确认相邻Driving车道、虚线许可、可避让空间与目标可达 |
| 两蓝都在后方 | 测试追近或超越能力 | 暂不优先；不能靠放后面就认为有对抗机会 |

不要机械地把+10改成-10。乐观同道追近时间为 `t_close = gap/(v_blue-v_red)`，只有相对速度为正才定义；还要扣除加速、出生保护和合法变道时间。它只是直线运动筛查，不是四车可行性证明。当前红策略存在超过任务优选速度带的情况，约32m短路段中的后方蓝未必能在同一速度合同内接近；不能为制造可攻击性而放松速度资格。

建议新版先只选两类布局：现有双前方与一前一侧后。可从“两布局×两方向×完整编号对”的8个模板开始，C0/C1各一次共16回合，只做工程预筛；再扩到四方向的16模板。这个数目是设计候选，尚未生成/批准；不把初态、间距、速度、红错位全部做笛卡尔积。gate/selection/test仍需独立四车几何和足够每族样本，不能由这16回合代替。

当前Mut的family还作为gate统计分组；若未来按攻击布局分族，需要显式登记新协议/统计层级和每族样本量，不仅改标签。先导仍只考虑B0，避免同时解释奖励、场景和互学习机制变化。

## 奖励值得保留与优先修订的部分

现有C1相对进度项为有符号差，比直接减去红方全部驾驶reward更贴近“额外通行效率损失”。共享团队目标、退场后真实团队尾项、首次团队事件去重和独立安全评估均应保留。不能把这一任务特定代理称为某篇文献的标准攻击奖励。

本轮直接调用生产规则的隔离CPU探针得到：

| 假设输入 | 持续4秒后的驻停任务违约 |
|---|---|
| 无前方阻挡、距目标20m、速度0 | true |
| 无前方阻挡、距目标20m、速度0.21m/s | false |
| 无前方阻挡、距目标5m、速度0 | false（6m近目标豁免） |

这只验证驻停判定条件，不代表整回合完整资格通过，也不是在CARLA中观察到学习策略采取了这些行为。它说明目前规则容许的自由度：持续蠕行可绕过0.2m/s驻停阈值，且近目标豁免不要求已到达目标区。结合双前方布局，可能学到长期占道制造延迟。

另一个源码事实：`blue_driving_reward`计算自由行驶低速deficit，但新 `c1_progress_team_v1`会覆盖旧drive，只保留蓝进度势差、risk、comfort和事件成本。因此不能把配置里的 `free_flow_target_mps=2.5`误解为新profile已经在约束长期低速。

量级例子：两红平均落后C1完成度0.1，持续2秒，N=500、攻击权重10，其攻击项累计仅为 `10*0.1*20/500 = 0.04`。这远小于一次50的事件罚项，也可能小于普通蓝推进/平顺成本。这个合成数值不是实测训练信号；它说明应记录并检查分量，而不是只看总reward上升或直接扩大攻击权重。

推荐的共同奖励结构候选：

`G_t = w_A * C1相对红进度落后 + w_P * 蓝进度势差 - dt*(风险密度 + 控制变化密度 + 无阻挡低速密度) - 首次违规事件成本`

优先顺序如下：

1. **先明确合理运动合同。** 若允许长期合法慢行，那是阻挡任务，研究结论相应限定。若希望研究有限自损的动态干扰，就登记蓝方无阻挡长期低速/停滞预算；瞬时正常制动、真实前车阻挡应合理豁免，未到达不能仅凭距目标近就永久豁免。新规则对全部算法共用，不为某个模型放宽旧验收阈值。
2. **让该成本确实进入新profile。** 可复用已有低速deficit的思想，明确系数、时间单位与豁免，不只保留一个不生效的配置字段。先用现有普通C1和合成边界轨迹核对。
3. **审计时域和生命周期。** 蓝车目标应保证覆盖交互区，成功退场与未完成分开；必要时把目标放到交互区下游，但先做地图合法性检查，并新建任务版本。保留真实尾项结算，不给退场车辆补动作。
4. **再共同标定量级。** 固定测量时域与归一化，连续成本按dt计、离散事件按次计。先检查攻击项、蓝推进、风险、comfort和安全罚项的分布及优势信号，再确定同一组系数；本轮不直接改变10/50/20。
5. **效果仍用冻结外部指标。** C1/C2双方蓝均合格的配对效率贡献、AttackGain_safe、任务完成、安全事件分别报告。普通C1相对其参考的攻击项应接近零；红更快应为负；不安全的raw收益单列。不能只用训练reward选胜者。

不建议首轮再加“贴得越近越奖励”或“TTC越小越奖励”；那会把接近危险本身变成目标。也不建议堆叠多个高度重复的延迟、降速、超时大额奖金。相对C1的进度面积做主项，到达延迟、成功转坏与近失分开评估即可。

既有蓝Actor也来自未合格基础模型。冻结它并加KL锚定不能自动形成“自然驾驶先验”；应先验证普通蓝参考的驾驶质量。规则普通蓝可以作为单独冻结的备选基线，但必须登记新身份，不能在同一比较中悄悄替换。

## 别人的设计及可借鉴边界

以下核对原始论文，而非根据题目推测实现。四项工作控制对象、场景和目标不同，数值不能直接横比。

| 工作 | 实际目标/奖励或优化目标 | 对本项目的启示 |
|---|---|---|
| Learning to Collide（2020） | 生成场景参数，reward包含负AV–障碍距离、碰撞bonus和不合理出生位置罚项；非本项目的双蓝在线MAPPO | 事故发现目标会直接奖碰撞；不能移植为安全合格效率奖励。[论文§III-B](https://arxiv.org/pdf/2003.01197) |
| STRIVE（CVPR 2022） | 学习交通先验的潜空间优化；对抗目标外加先验、初始场景偏离及非ego碰撞/道路成本；另尝试寻找安全的ego解 | 挑战性还要有合理性和可解性检查，不能仅最大化失败。[论文§3.2、§4.1](https://nv-tlabs.github.io/STRIVE/docs/strive.pdf) |
| CAT（CoRL 2023） | 根据交通轨迹先验、当前ego反应及碰撞概率重采样对手轨迹；并非另一个双蓝PPO碰撞reward | 普通交通先验和当前目标策略反应都要纳入；该工作同时训练ego，与本项目冻结红方设置不同。[论文§3](https://proceedings.mlr.press/v229/zhang23g/zhang23g.pdf) |
| FREA（CoRL 2024） | CARLA闭环背景车RL：向AV路线上的潜在冲突点推进/到达，撞其他背景车受罚；再由AV可行域指导优势和PPO更新 | 任务目标、背景车行为和AV仍可安全应对的约束分开处理。[论文§3.2、附录B.2](https://arxiv.org/html/2406.02983v2#S3.SS2) |

FREA尤其相关：它不仅调一个碰撞罚权重，还离线学习AV可行价值，用当前与下一AV状态是否在可行域内切换优化信号。直接复现需要额外网络、离线数据与对照；当前不建议引入。可先借鉴其“有交互机会、有合理运动、留有应对空间”的设计原则，不能把简单TTC检查称为FREA可行域保证。[FREA方法与附录](https://arxiv.org/html/2406.02983v2)

这些论文大多研究事故或近失生成；本项目研究蓝方资格内的额外效率损失。沿用C1相对效率主项是本任务下的设计判断，不是上述论文证明了这套系数最优。

## 分阶段操作出口

1. **已完成的离线审查：** 当前72例初态覆盖、生产驻停规则边界、奖励量级例子及上述原始文献核对。证据为本目录 `offline_probes.py/json`，物理ticks=0。
2. **下一项准备工作：** 新版清单中保留双前方控制组、加入可达的一前一侧后；统一蓝方合理运动、目标/退场和测量时域。先做OpenDRIVE合法性与合成轨迹审计，不覆盖v1。
3. **用户明确启动后的第一项真实操作：** 新版少量C0/C1，先看普通蓝是否正常、红是否自然失败、能否形成保护期后的有效交互、实际初态/传感器时序及奖励分量是否可信。失败先解释，不进入学习。
4. **其后条件性操作：** 只有明确选择弱红工程诊断，才做单seed B0小预算闭环；所有B组后续共用同一奖励和场景版本，不把A/B当实验seed。正式比较仍需合格正常红方。

本轮没有启动真实CARLA、没有修改训练奖励或资格阈值、没有添加弱红豁免，也没有创建监控。

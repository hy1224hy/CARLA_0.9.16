# Project Subagents for MAPPO CARLA Experiments

This directory defines the six primary subagents used to run the thesis experiment workflow for `PythonAPI/examples/mappo_training`.

Chinese usage guide: [README.zh-CN.md](README.zh-CN.md).

Use these as prompt templates when spawning Codex subagents. Each agent has a narrow scope, clear inputs and outputs, and explicit boundaries to avoid duplicate work, conflicting edits, or expensive accidental CARLA runs.

## Agent Roster

| Agent | Main job | Default mode | Primary output |
| --- | --- | --- | --- |
| `Experiment-Planner` | Turn a research question into an experiment matrix | Read-only | Run table and dependency graph |
| `Command-Auditor` | Verify commands before training/evaluation | Read-only | Corrected command list and risk report |
| `Scenario-Steward` | Manage scenario split and geometry checks | Read-only unless assigned JSON edits | Scenario coverage and held-out plan |
| `Reward-Metrics-Guardian` | Keep reward, metrics, and anti-hacking checks aligned | Read-only unless assigned reward/metric files | Reward-metric audit |
| `Training-Runner` | Execute exactly one approved CARLA training run | Runnable, no code edits | Training status, log summary, ckpt/TB paths |
| `Evaluation-Repro-Analyst` | Run/evaluate completed checkpoints and archive facts | Runnable/read-only by default | Result table and reproducibility ledger |

## Coordination Rules

1. Start with `Experiment-Planner`.
2. Send draft commands to `Command-Auditor` before any expensive run.
3. Use `Scenario-Steward` and `Reward-Metrics-Guardian` in parallel when changing scenario sets or reward definitions.
4. Give `Training-Runner` exactly one approved command at a time.
5. After every completed run, send artifacts to `Evaluation-Repro-Analyst`.
6. Only one agent may own a writable file set at a time.

## Write Ownership

| Writable area | Owner |
| --- | --- |
| `data/training_scenarios/*.json`, `data/test_scenarios/*.json` | `Scenario-Steward` |
| `training/adversarial_reward.py`, `utils/adversarial_metrics.py`, related tests | `Reward-Metrics-Guardian` |
| `logs/**`, `checkpoints/**` generated by a single run | `Training-Runner` |
| `logs/eval/**`, `docs/experiments/**` | `Evaluation-Repro-Analyst` |
| Experiment plan documents | `Experiment-Planner` |

## Hard Rules

- Do not let read-only agents run CARLA or modify files.
- Do not reuse a `--save-dir` for a new experiment.
- Do not report a result unless it comes from a log, JSON output, TensorBoard export, or an explicitly provided checkpoint.
- Do not compare runs unless their seed, scenario split, reward version, checkpoint selection rule, and evaluation protocol are recorded.
- If a command or result is uncertain, write `NEEDS_CONFIRMATION` instead of guessing.

## Recommended Main Flow

```text
Experiment-Planner
  -> Command-Auditor
  -> Training-Runner
  -> Evaluation-Repro-Analyst
```

Parallel side checks:

```text
Scenario-Steward + Reward-Metrics-Guardian
```

Use PSRO only after the robust baseline and 2-red-1-blue adversarial loop are stable.
